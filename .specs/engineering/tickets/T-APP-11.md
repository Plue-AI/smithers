## Goal
An open File or Diff card on a branch shows each outside write (SSH editor, terminal tool, coding agent) within 1 s and names its writer. It says so when the file is deleted ("Deleted by Maya via SSH · Restore") or renamed ("Renamed to `deliver.ts` · Follow"), and an outside-change diff offers **Restore this file**, all on the existing File surface (`CodeSurface.tsx`). CodeMirror arrives with stage 3 co-editing (T-APP-14a).

## Ownership (Will, 2026-10-02)

Design (smithers-06) builds the File and Diff states: reload, deleted and renamed, Restore this file, Compare, with the CSS, in T-UI-16 (on `CodeSurface.tsx` and on `DiffSurface.tsx`, where T-APP-15 folds `DiffView`). This ticket builds no View, CSS or editor presentation. It owns the File and Diff card files, which map the topic to View props, the commands in Changes, and the language server's move onto the daemon (minimal-code synthesis v1 §2).

## Scope
In:
- Land dark against the specified contracts for every unavailable dependency above. No fake success, host fallback or duplicate renderer. `file-reload.spec.ts` tests each unavailable provider independently. Dependencies without landing evidence remain unavailable.
- File card on `branch:<id>:files`, rendered by the existing read-only File surface (`CodeSurface.tsx`). In stage 2 the card is read-only for everyone (§9.2).
- Reload: a `file_written{path, actor, post_digest}` event for the card's path (§9.3.4) loads the content at that digest (§7.6) and hands the View the new `text` and `digest` once, within 1 s of the write. The View applies it with no remount, so scroll position and the viewer's line survive (T-UI-16). Events for other paths do nothing.
- Header: the file's last writer (T-APP-09 actor), including "changed outside Smithers" (§9.3.1).
- In-card controls (mvp.md Appendix B.4), each a catalog row with a stable id and `agent: run` (§6.1.2):
  - **Restore this file** (`file.restore`, §9.3.5) on an outside-change diff: puts one file back to its burst's per-file `before` bytes from its versions commit, attributed to the person who pressed it, through T-COL-04's service. If the file changed again since that burst, it writes nothing and opens Compare instead.
  - **Compare** (`file.compare`): a read-only side-by-side of a snapshot version and the current file. In S2, Restore opens it; in S3 the "Changed outside Smithers" flag opens it against the live document (T-APP-14).
  - **Restore** (`file.restore-deleted`, §9.2.6) on "Deleted by <actor>": rewrites the delete burst’s per-file `before` bytes from its versions commit, then calls `write_file(path, "absent", content, actor)`. A `409 stale` (someone re-created the file) shows the current file and writes nothing.
  - **Follow** (`file.follow-rename`) on "Renamed to <path> by <actor>": moves the same card to the new path.
- Diff card on `branch:<id>:files` (`@pierre/diffs`): an item branch's hunks against the previous item's candidate (§12.5.1); a scratch branch's against its fork revision (§8.5.3). It reloads on change events and shows per-file last writers (§7.2). Per-hunk authors are excluded; the projection supplies per-file last writers only.
- A sleeping branch's File and Diff read the captured snapshot and never wake it (§8.4.4).
- Code intelligence survives stage 2: the File card's language server runs on the branch machine as a daemon `exec` session owned by the member who asked (§9.1.2), replacing the `workspace/sessions` kind `lsp` path in `state/CloudLspClient.ts`. A sleeping branch starts none, and the gestures bind nothing there (§8.4.4).
- Commands: `/file <path>` (`files.read`), `/files` (`files.list`), `/diff` (`change.diff`), branch-scoped.

## Risks and notes
- The stage-2 surface is the existing `CodeSurface.tsx`. Stage 3 restores CodeMirror and binds `y-codemirror.next`'s sync extension (T-APP-14a, §7.6). Reloads here are new `text` props; in S3 they arrive as Yjs updates, and text reloads stay only for read-only files over 1 MiB (§9.2.1).

Missing isolation or daemon authority refuses execution; no host/browser fallback and no sudo. `file-intelligence.spec.ts` uses a repository plugin canary and observes its uid and write only inside the machine.
- Root step: the existing T-TRM-07 broker starts and ends the LSP exec session; this ticket adds no privileged installer. Inputs consumed by that step: broker binary, privileged interpreter/base executables, fixed startup environment, identity validation and cgroup root come from main-pinned install/image code; authenticated member uid/login, branch/session ids and boot authority come from host state, not repository fields. Account/group records, cgroup entries, executable/import ancestors and retained filesystem metadata are image state that branch processes can influence. Session argv, cwd, environment, repository-selected language-server executable/plugins, stdin and file paths are member/branch data. Root parses only validated identity and bounded session-control fields, drops supplementary groups/GID/UID to the member’s prescribed identity, then resolves or applies argv/env/cwd and repository inputs. Root never loads or executes branch-built code. Close/kill consumes only a validated session id under the fixed cgroup root and kernel process state.
- `TestLspRootInputsValidatedBeforeUse` in `packages/backend/internal/machined/confinement_integration_test.go` extends C-COL-04 through the production code-intelligence route → `open_session(exec)` and close/kill, with real users/cgroups in a machine. Supply root/foreign-member identities, malformed session ids, cgroup traversal, hostile PATH/LD_PRELOAD/PYTHONPATH, replaced executable/import ancestors and retained-machine symlinks. Refuse invalid control inputs before privileged use; independently observe member uid/gid/groups before repository executable/plugin loading, unchanged root/other-member sentinels, and bounded cleanup. Include a valid-session control. Branch-influenced inputs to root remain an activation blocker until this test passes; smithers-3f reviews the inputs and receipt.
