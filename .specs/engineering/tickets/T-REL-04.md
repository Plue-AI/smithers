## Goal
Every named kill point across runs, merges, GitHub writes, bursts and rebases is exercised by one suite, and each leaves no re-run completed step, no duplicate external effect and no lost acknowledged write.

## Scope
In:
- One kill-point vocabulary for the host, reusing the five points of `packages/backend/internal/services/durable_crash_restart_test.go:30-50` (`pre-commit`, `post-commit`, `pre-launch`, `post-launch`, `stale-owner`) and its child-process harness (`SMITHERS_CRASH_POINT`, the `CRASH-POINT` marker).
- Kill points this ticket adds, beyond those its sibling checks own:
  - start (§4.1, §11.4.1): after `queued → starting` pins the flow digest and before the `todo` run's first step;
  - stop and resume (§4.1): after the durable pause signal and before the run parks in its `paused` wait, and after Resume settles the wait and before the next step;
  - merge (§10.6.2), a stack-engine system operation outside the `todo` run (§10.4.1): before the `checks.Land` row, after it and before GitHub's merge call, after the call and before `merged`;
  - rebase (§9.4.1, §10.5): after capture and before the rebase, mid-rebase, after the rebase and before the "Rebased onto" activity entry, with people present and without;
  - PostgreSQL SIGKILL inside a TODO transition's transaction.
- The suite runner: runs every fault test, with C-DUR-01 to C-DUR-04's tests, as one nightly job on CI (host and daemon kills) and on the reference host (VM kills); writes a receipt per kill (point, subject, steps re-run, effects seen on the fake GitHub, writes acknowledged and found) into the matching check's evidence directory.
- A guard against vacuous passes: a test fails unless the child logged the kill point's marker before it died.
- Lands dark until T-FLW-09, T-STK-05 and T-FLW-11: refuse run-recovery cases without the reconciliation, pause and launch contracts; never substitute direct journal writes. Lands dark until T-STK-04 and T-GH-09: refuse merge cases without the production merge decision, fence and pending-operation recovery. Lands dark until T-COL-03, T-COL-03a, T-COL-04 and T-STK-08 (S2): refuse daemon and rebase cases without the production transport, capture, watcher and presence-aware rebase contracts. Lands dark until T-INS-02: refuse supervised restart and machine cases without the launcher and microVM provider. Build against these specified contracts before they land; unavailable cases produce non-passing receipts, not skips or fallback execution (C-DUR-01 to C-DUR-04).
- Lands dark until T-SEC-01's C-SEC-02 root-boundary validations pass and an approved main-built test daemon is available: refuse privileged daemon cases. A branch-built daemon is never installed or run as root. Missing reference-host selection in the approved check runner refuses VM cases (C-DUR-02, C-DUR-04).

## Tests
- All cases below are named additions to C-DUR-01 to C-DUR-04. Run a real backend under the launcher against real PostgreSQL, the production command dispatcher/routes and machine transport, with fake GitHub only at the external HTTP boundary. Seed fixtures before dispatch; never call a service, worker or daemon hook directly to perform the operation being accepted. Hard-code expected states, request counts, fixture digests and bytes in test fixtures; never read spec files or derive expected results from implementation code at runtime.
- `TestTodoStartPauseResumeCrashThroughRoutes` (`todo_pause_fault_test.go`): start through the production TODO admission/launch path; stop, resume and retry through `POST /api/todos/{n}/{stop|resume|retry}`. The start case observes the pinned launch before the first step. `TestTodoMergeCrashThroughRoute` (`todo_merge_fault_test.go`) calls `POST /api/todos/{n}/merge {reviewed_head_sha}` as an eligible session. `TestTodoPostgresCrashThroughRoute` (`postgres_kill_fault_test.go`) kills PostgreSQL during a route-triggered transition and observes REST/live projection after supervised recovery. `TestRebaseCrashThroughDispatcher` (`rebase_fault_test.go`) dispatches `branch.rebase-now` with people present and drives automatic production rebase without people; file writes use real member sessions. These are planned names at the specified boundaries, not claims that the future routes exist today.
- `TestRebaseFaultRootInputsValidatedBeforeUse` (C-DUR-04, `rebase_fault_test.go`) drives the production machine startup and rebase transport with malformed envelopes, hostile argv/env, traversal/symlink paths, substituted artifacts and forged kill selectors. Independently observe non-root execution of repository payloads, no outside writes or root canary, and refusal before privileged use; include trusted positive controls. Privileged runs remain disabled until this test and the inherited C-SEC-02 validations pass.
- fault: start killed → after restart the TODO is `starting` or `working` as its last `product_job_events` row says, and the run keeps the digest pinned at Starting.
- fault: stop or resume killed → after restart a stopped TODO is `paused` with the same run parked, never cancelled; Resume continues that run from its last finished step; Retry after a failure starts a new attempt and keeps the earlier attempt's row and evidence.
- fault: merge killed at each point → exactly one merge on the fake GitHub, one `merged` transition, one `checks.Land` row bound to the reviewed head; a kill before the GitHub call leaves `in_review` with Merge enabled again.
- fault: rebase killed at each point → the working copy equals either the pre-rebase capture or the rebased head, never a mix; no acknowledged write lost; "Rebased onto" appears at most once; a changed base or prefix requires a new candidate and voids earlier approvals even when the captured tree is unchanged (§10.5.3a).
- fault: PostgreSQL killed mid-transition → after restart the TODO state equals its last `product_job_events` row; no projection event without its row.
- fault: the runner reports a missing marker as a failure, not a pass.

## Risks and notes
- inotify and cgroups need a Linux guest, so daemon kill tests run on a Linux CI runner or in a microVM (§21 integration row). Observation: a macOS-only CI job skips them silently; the runner counts skips as failures.
- A shell step re-runs only when it declares itself idempotent (§19.2). A test must show a non-idempotent shell step becomes `interrupted` with Retry, not re-run.
- Stage split: start, stop, merge and PostgreSQL points land with T-FLW-09 at stage 2; rebase points follow T-STK-08 at stage 2; the reference-host VM run completes at stage R.
- smithers-3f accepts Go/infra kill-hook placement, machine/root boundaries and reference-host setup. smithers-38 accepts the TypeScript harness and target integration; neither owner may waive a missing marker, a skipped required case or credential isolation. smithers-8a decides phase coverage and any exception to the fault matrix; Will decides changes to the product durability guarantee. Existing recorded owner answers stand; unresolved seam questions are reviewed post hoc under the parallel-build directive.
- Security: repository flows, scripts, checks and writers execute only as unprivileged users inside machines (M-29, §17.3); no sudo. Approved engineering automation uses the declared CI/reference host without publication credentials or readable issue-claim configuration (§21.4a). smithers-3f reviews both boundaries. Host, PostgreSQL and VM kill controllers run as an unprivileged harness user; this ticket adds no root kill controller or root repository execution.
- Root input inventory for inherited guest provisioning and daemon startup/rebase: interpreter, guest helper, daemon binary, libraries, toolchain/image bytes and digests, fixed PATH/import settings and service configuration come from the installed approved main bundle, never branch output. Host-generated machine/session identity, UID/GID, credential and transport envelope, request IDs, cgroup subtree/IDs, descriptors, signals and kill-point selector come from trusted main-built host/test code or the kernel; enumerate their concrete values/sources in each receipt. Member argv/env/cwd, file bytes, relative paths, retained filesystem/symlink state, branch heads/capture trees, rebase targets and document/write streams are branch/member data. Root parses only bounded authority fields; repository payloads run after group/GID/UID drop. Validate fixed cgroup confinement, artifact provenance, transport identity and no-follow path confinement before privileged use. Branch/member inputs block privileged cases until `TestRebaseFaultRootInputsValidatedBeforeUse` and C-SEC-02's `TestGuestHelperInstallPinsInterpreterAndEnv`, `TestRootSetupNeverFollowsMemberSymlinks` and `TestRootPreflightParsesOnlyEnvelope` prove validation. Branch-built executable inputs stay forbidden even after passing tests. A newly discovered root input needs its source and validation recorded before enabling the case.
