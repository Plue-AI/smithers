## Goal
`/branch Tn` shows one card for the whole branch: its machine state, the item it works and its place, everyone on it (people and agents, each with where they are), grouped activity including steers and outside changes, changed files and terminals, and it reads a sleeping branch without waking it.

## Ownership (Will, 2026-10-02)

Design (smithers-06) builds the `BranchView`, with the CSS, in T-UI-15. This ticket builds no View, CSS or editor presentation. It owns the Branch card file, which maps the topics to `BranchView` props, the commands in Changes, and the browser's presence heartbeat (minimal-code synthesis v1 §2).

## Risks and notes
- The current mock `.specs/design/mock/src/cards/Branch.tsx:119–143` derives Add to stack from the fork source; its SSH line at :214 uses `hostOf(world)`. Production placement follows §8.5.3 and the SSH host follows §8.10.5.
- Risk: presence rows flicker as heartbeats from several tabs of one person interleave. Falsified if a person with two tabs ever shows two rows or a row that disappears and returns within 30 s (§7.3.2: one avatar per person).
- Decision owners: smithers-b8 accepts app dispatch, heartbeat lifecycle and legacy cutover choices; smithers-06 accepts BranchView props and interaction changes; smithers-38 approves shared RPC/TypeScript contract changes; smithers-3f approves backend route, admission and execution-security seams. Escalate changes to product behavior to Will; this ticket accepts no new ADR, public command or authorization policy.
- Security preconditions (smithers-3f reviews): commands authorize the authenticated actor and bound branch on the server before effects; presence actor/location data grants no authority. Repository flows, terminal commands, SSH sessions and conflict validation execute only in the branch machine, as non-root member or agent, with no sudo and no host fallback (M-29, spec §1.3). Existing providers retain C-SEC-02 and their guest-root validation requirements. This ticket adds no root step and consumes no root inputs: topic payloads, user text, paths, branch ids and copied SSH text are untrusted data, never root argv or executable host code. Missing isolation or authority providers fail closed in the integration cases above.
