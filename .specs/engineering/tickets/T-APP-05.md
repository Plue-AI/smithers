## Goal
`/flow todo` shows the TODO flow's steps and tells its versions apart (Active, Proposed with its TODO, "Merged · active after sync", "Merged · not active" with the load error), so a lead sees which version new TODOs use and asks for a change from the card.

## Scope
In:
- `flow` card, embedded and maximized from one component:
  - version chips for `active`, `proposed` (with its TODO), `merged-syncing` ("Merged · active after sync") and `merged-failed` ("Merged · not active"); `previous` has no chip;
  - the selected version's steps, with steps added relative to Active marked;
  - for `merged-failed`, "Load failed" with `load_error` (§11.3.2); Active stays the default;
  - actions: **Edit** on Active runs `/flow.edit <name>` with no request, so the form law asks for it (§11.5); Source (`/flow.source <name>`, the read-only File card); Plan (`/flow.plan <name>`, the retained `FlowPlanCard`); Run (`/flow.run <name>`, `agent: run`);
  - each step's agent as a chip that opens its Agent card (`/agent <name>`, T-FLW-08).
- Source, Plan, Run and agent chips are one click away, never on the first screen (mvp.md §6.14). The app agent's Edit posts a one-click Confirm card (T-APP-04).
- The selected version is the member's own view state (T-APP-16), changed through `onView`.
- System flows (§11.1.1, M-30) render read-only with no Edit, Source or Run.
- `/flow <name>` (new catalog door, Appendix A; reuse `flow.list`).
- Land dark against the specified contracts for every unlanded dependency above: no version card without T-FLW-03 and T-UI-10; no persisted selection without T-APP-16; no Edit or Source-created TODO without T-CAT-01, T-STK-01, T-APP-02 and T-APP-04; no Source without T-APP-15; no agent navigation without T-FLW-08; no repository Plan or Run without T-INS-02, T-FLW-01, T-FLW-04, T-FLW-11 and T-SEC-01. Keep unavailable actions absent and direct commands fail closed without effects. Cut over persisted legacy kinds only with T-APP-22. Enable each integration after its named production-boundary tests pass; missing providers never trigger host execution. Checks: C-UI-13, C-J5-01, C-SEC-02.

Out: loading, activation and pinning (T-FLW-03, T-FLW-04); flow-edit qualification (T-FLW-05); seed patches, seed storage and diff validators; a second flow-edit HTTP handler; direct writes to `main` or activation at merge time; triggers, a graph editor, model-choice controls; the monitor and Run View cutover (T-FLW-07); the Agent card (T-FLW-08); editing source (T-APP-14, S3); S2/S3 scratch-branch editing (C-J11-02); multi-repository selection; root helpers, image/toolchain changes and host execution of repository code.
