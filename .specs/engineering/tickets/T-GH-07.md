## Goal
The install follows GitHub's `main` with no declaration. The Home card's `main` row reads "synced 40 s ago", turns gold past 120 s with Retry, and names the cause when GitHub refuses. When `main` is rewritten, the owner sees it as Needs you, and nothing moves until the owner presses **Reset to GitHub main**.

## Scope
In: always-pull following; health `fresh`, `stale`, `refused`, `limited` (precedence `refused` > `limited` > `stale` > `fresh`); `GET` and `POST /api/github/sync`; `github.retry` (Member, `agent: run`); force-push detection, the owner-only bound reset `{id, old, new}` and its crash recovery; one ancestor check.
Out: streams and budget (T-GH-02); Home and Settings rendering (T-APP-01, T-APP-03); rebases after a move (T-STK-08); GitHub App setup; any write to GitHub's `main`. No new poller, token minter, flow loader, attention table, machine launcher or credential-policy table; no delegated reset confirmation, multi-repository following, push mirror or user-configurable triggers.

Landing dark: build against every listed dependency's spec contract. Until an unlanded dependency is available and its integration checks pass, keep its consumer disabled: no polling or Retry without T-GH-02, no effects without T-ACC-02/T-ACC-03/T-CAT-01 authority, no pull/reset without T-STK-01/T-STK-04/T-GH-03 serialization and merge fences, and no move/reset without durable T-STK-08 (S1) rebase and T-FLW-03 main-moved delivery. Flow-load dispatch refuses without T-INS-02/T-FLW-01/T-SEC-01 machine isolation and root validation; retain the intent for recovery. Publish no health/attention actions without T-COL-02 and the T-UI-06 seam. Unavailable authority or execution providers fail closed. C-J10-06, C-J10-07 and C-SEC-02 qualify activation; unlanded dependencies do not block Ready.

## Security preconditions
Repository code, imports, typechecking and dependency installation execute only as an unprivileged user inside a machine (M-29, spec §1.3). The host uses packaged code to move bare refs and store metadata; transfer disables repository hooks, filters and configuration-selected helpers. Reuse T-FLW-03's loader, T-INS-02's bundled isolation and T-SEC-01's guest validation. smithers-3f reviews this boundary. No host/process fallback or branch-built root executable is permitted (C-SEC-02).

The inherited privileged steps consume the following inputs. Main means code pinned into the installed bundle; branch includes repository-selected data and retained member state. These inventories supplement T-SEC-01 R1–R3; this ticket adds no root helper.
- Guest bootstrap/install: helper bytes/digest, bootstrap/install script, fixed destination and interpreter/search paths from main; msb path, host PATH/HOME/environment, machine ID, deadlines, pinned base-image selection and OCI registry responses from install state/main. Guest shell/Python/base utilities and their startup/import paths, helper temporary/parent entries and retained snapshot filesystem contents are main/base inputs with possible branch/member substitutions. `TestGuestHelperInstallPinsInterpreterAndEnv` validates provenance, environment, ancestors and replacement resistance before root execution (C-SEC-02).
- Guest setup: login/UID/GID/directories, HOME_LINKS/GO_SETTINGS and helper from main/install account allocations; passwd/group, useradd/shell and filesystem/kernel metadata from the base image. env.json keys/values, tool-cache selections, cache/home entries and all leaf/ancestor symlinks include branch-derived toolchain/dependency data and retained member state. `TestRootSetupNeverFollowsMemberSymlinks` validates bounded values, trusted identity and no-follow ownership/mode/home writes before root use (C-SEC-02).

- Root layer preparation and managed coding artifacts: scripts, helper/interpreter, artifact bytes/catalog digest, download URL/checksum manifest, package allowlist, signing-key fingerprint, UID and fixed install/cache/marker destinations from main/bundle; OS/package-registry responses from the pinned base and approved upstreams.
