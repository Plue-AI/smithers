## Goal

Two members with the same code file open see each other's characters within 1 s, each in the author's colour, with a name flag on each editor's line. Every keystroke is on disk, fsync'd, within 1 s and survives a restart. Agent, terminal and SSH writes merge into the document as attributed edits, and an outside save that overlaps unsaved typing never wins silently.

## Risks and notes

- Character offsets: Yjs in the browser indexes UTF-16, and the wiki FFI chooses an `OffsetKind`. A mismatch corrupts text with emoji. Confirmed if the interop test diverges on astral characters.
- An outside save made from an older copy can remove document text that was already flushed: against the base, that removal doesn't overlap unsaved typing, so it applies. That is the replaced-edit case, whose flag is [D] (§9.3.7). The removed text stays recoverable as the burst's `before` version (M-27).
- The merge base survives a daemon restart in the state record (§9.2.5). Confirmed broken if C-DUR-04's K7d shows an outside rewrite while down misclassified as overlap, or authors of unchanged text lost.
- `renameat2(RENAME_EXCHANGE)` must work on the guest’s working-copy filesystem. T-COL-11 records the reference-host probes. If it returns `EINVAL`, smithers-8a decides the remedy after smithers-3f reviews it; activation stays off until the recorded probes pass. This does not block dark integration work.
- T-COL-11 owns ADR 0003’s topology decision; smithers-8a accepts it after smithers-3f reviews the transport/disk-authority seam and smithers-38 reviews TS contract impact. T-COL-08b alone builds the optional `packages/backend/internal/live/codedoc.go`; this ticket integrates and verifies its rebuild and unchanged `saved` relay. The daemon stays the disk authority. Dark work can start before the decision; activation cannot. C-PERF-03 above 800 ms p95 goes to smithers-8a for investigation; acceptance remains < 1 s. ## Security preconditions and root inputs

Repository commands, dependency installs, watcher reconciliation, document saves and capture/rewrite commands execute only inside machines as unprivileged users (M-29, §9.5). The host authenticates, routes and measures; it does not execute repository code. smithers-3f reviews the following inventory before activation. This ticket adds no root operation; integration exercises these inherited ones. Branch/member data is a blocker until its named C-COL-04 test proves validation before privileged use; branch-built root code remains forbidden.

- Startup/install/restart consumes broker/daemon/helper bytes and digests, init configuration, interpreter and executable/import paths, fixed environment, destination paths, base image and retained filesystem metadata. Sources: main-pinned installed bundle/base and install-controlled boot state; retained path entries and environment can contain branch/member data. `TestLiveDocumentTrustedStartup` proves provenance, protected ancestors and substitution rejection on fresh and retained machines. Root never loads a branch build; test a main-pinned installed artifact after landing.
- Session start consumes socketpair peer, operation, authenticated actor/run/session identity, UID/GID/login mapping, fixed cgroup parent and child ID, passwd/group state, PTY/stdio descriptors and size, argv/env/cwd. Sources: main broker policy and install-controlled authenticated host/DB/kernel state; command payload and guest filesystem entries are branch/member data. `TestLiveDocumentBrokerInputs` proves bounded envelope/identity/cgroup validation before root use and applies argv/env/cwd only after group/GID/UID drop.
- Rewrite freeze/thaw and restart cleanup consume fixed session-cgroup root, validated session IDs, cgroup directory metadata and kernel `events`/`procs`/freeze/kill state, signals, deadlines and exit status. Sources: main policy and install-controlled kernel/session registry; branch/member processes influence population and state. `TestLiveDocumentBrokerInputs` proves no selectable path leaves the fixed subtree. Document bytes, paths, state records, merge bases, digests and `onto` revisions are branch data consumed by the unprivileged daemon, never root.
- Existing environment/home/token operations consume fixed destinations and allowed keys, authenticated member UID/GID and login, install secret values, home/run-directory metadata and credential-file entries. Sources: main policy and install-controlled DB/secret state; retained home entries and requested values can be branch/member data. Keep these outside document dispatch; `TestLiveDocumentBrokerInputs` proves document requests cannot invoke them or select another identity, and `TestLiveDocumentConfinement` proves member/token isolation. Changes to their implementation belong to their owning tickets.
