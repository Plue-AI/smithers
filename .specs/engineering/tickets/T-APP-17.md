## Goal
Every app-agent answer is built from a stored, inspectable context list that a preflight step chose on the host, never from the whole conversation, and the same selector serves the TODO planner's wiki citations.

## Scope
In:
- A preflight step at the start of every app-agent turn, inside T-APP-16's existing host turn runner (§15.1.4). It runs on the host, outside every machine, and survives its author closing the tab.
- Land dark against the specified contracts. Until T-APP-16 supplies authenticated prompt dispatch, SharedEntries and durable step/answer writes, preflight is disabled and its prompt path refuses without a model call. Missing T-INS-06 model access or T-FLW-08 model routing also refuses. Missing T-STK-12 item snapshots yields no file candidate for that item; T-INS-06 mirrored main remains the S1 source. Keep Context and Inspect wiring disabled until T-UI-07, T-FLW-07 and T-APP-15 provide their renderers and card-opening handlers. Enable each integration only after its C-UI-07 tests pass; never fall back to the browser transcript or host repository execution.
- Inputs (§15.1.2): the prompt, the author, the branch, the titles and summaries of recent shared entries, and the branch's state. Candidates: files, wiki pages, TODOs and runs.
- Reuse first, in this order:
  1. Selection: reshape the existing `recall` flow (`packages/smithers/agent/memory/src/Flows.ts:39`, `Recall.ts`, `Source.ts`), which mvp.md Appendix A maps to the Context line. Adapt file, wiki, TODO and run candidates as host-read data, preserving memory namespaces and policy. Its current results are memory rows and its `maxTokens` is a byte ceiling; neither is already the preflight contract. Add the required fast-model selection and enforce the preflight token budget without changing recall's public byte-budget semantics.
  2. Stored items: CardPrimitives' `ContextItemSchema` (`packages/rpc/src/CardPrimitives.ts:304`) extended with `reason`. No second context-item shape.
  3. Answer input: extend `composeAgentInstructions` (`packages/rpc/src/AgentContext.ts:559`) and its existing production caller, `packages/smithers/agent/model-host/src/ModelTurnHost.ts:68` (`providerRequest`), to render only the selected repository content. Today the helper renders runtime state, not selected items. Do not also inject unselected wiki documents, recent cards or the browser transcript.
  Rejected: a second selector or runner. A new Go selector requires a failing C-UI-07 integration receipt showing why reshaping recall is insufficient, recorded in #3504, and smithers-8a's decision with smithers-38 and smithers-3f reviewing the seam.
- The stored list sits on the answer entry within a token budget (default 24k tokens, an owner setting). Only the selected items, the prompt and the last 3 shared entries' text enter the answer step. Every read applies `SharedEntries` (T-APP-16): the author's own private entries are excluded too.
- Model: one call on `agent:fast` (§11.5a), recorded like any step. Without a fast-model key it falls back to the coding model and records which it used.
- File candidates are data from the host repository store, never a machine: S1 uses mirrored `main` (T-INS-06) or the item snapshot (T-STK-12); S2 uses the branch's last captured head (§8.4.4). Record the revision per file; a missing snapshot gives no candidate and never wakes a machine. Recent entries without summaries keep their titles; preflight does not wait for T-APP-07.
- The Context line: the existing `Context · N` disclosure expands to one item per `context[]` entry. Extend `packages/rpc/src/ContextLineCard.ts` and `apps/app/src/mainview/ContextLine.tsx` with the card-opening action, dispatched through the existing `cardActions` → `flowAction` path. File items use T-APP-15's File card. Inspect shows preflight as step 1 with candidates and choices (T-FLW-07). C-UI-07 proves disclosure and card opening.
- §13.4 reuses the same selection restricted to wiki pages (T-FLW-10).

Out:
- Jev command selection (`POST /api/commands/select`), kept as built.
- Changes to memory recall policy; the planner's citations (T-FLW-10); the coding agent's own context; the host runner (T-APP-16).
- Repository flow or plugin execution, shell or LSP tools, live machine reads, machine wake, private context.
- New conversation tables, a second turn runner or context-item schema, new memory ranking policy, budget/tool/permission editors, S2 captured-head transport and S3 planner integration. Preserve old persisted entries without `context[]`; do not backfill preflight or replay it.

## Risks and notes
- Risk: preflight adds a model round trip that breaks the 1.5 s first-token target. C-PERF-01 measures it at release; this S1 ticket supplies the timing hook. The install owner chooses the fast model. smithers-8a reviews candidate-limit changes against C-UI-07; only Will can relax the product target. No budget editor ships here.
- Risk: `recall` ranks memory rows, not TODOs and runs. Falsified by the integration test above passing on `recall`; only a failure there justifies a new Go selector.
- Security: preflight reads snapshots as data with shipped host code; it imports no repository module, executes no repository recall override or plugin, and never wakes a machine (§1.3, M-29). Only packaged bindings run on the host. SharedEntries filters every candidate and Inspect read with the author's delegated rights. smithers-3f reviews snapshot confinement, namespace/audience filtering and host execution placement; C-UI-07 proves the canaries and confinement.
- Root steps: none. Preflight, snapshot reads, the packaged model host and card dispatch run as the install user, never root. There are no root-consumed main or branch inputs in this ticket; it adds no launcher, guest bootstrap or privileged helper.
- No new tables: `context[]` uses T-APP-16's existing answer storage, so no `ownership.csv` reservation is needed. C-PRC-02 verifies the migration boundary.
- Owner review: smithers-06 (Context/Inspect views), smithers-b8 (app actions and prompt API), smithers-3f (Go and security) and smithers-38 (memory/model-host/RPC libraries) are the pre-review owners. Their recorded checklist answers stand under Will's parallel-build directive; remaining review is post hoc. smithers-38 signs off public TypeScript API changes, smithers-b8 the user-facing API, and smithers-3f the Go persistence seam; smithers-8a decides reuse exceptions.
