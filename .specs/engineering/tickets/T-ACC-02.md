## Goal
A maintainer adds a person by GitHub username; that person signs in only while listed and holding `push` or higher. Losing GitHub write access suspends them within one hour. Removal or suspension ends every session, credential, socket, terminal and SSH session within 5 s. In S2 their GitHub SSH keys work without manual setup.

## Scope
In: `GET/POST /api/members`, `PATCH/DELETE /api/members/{login}`; role seeding (admin or maintain = Maintainer, write = Member); one immutable owner (`owner_immutable`, HTTP 403); `needs_github_access` and `unknown_github_user` refusals with no stored row; hourly and on-401/403 recheck; transactional revocation; `todo.takeover`; GitHub key import (S2).
Out: hosted `/api/orgs*` (stays 404 on self-host), invitations, teams, owner transfer, a `members` table, the Members card (T-APP-06), unix users on machines (T-MCH-11). Out also: restoring the closed-alpha roster, hosted permission fallbacks, a new poll scheduler or sync table, SSH gateway/listener and forwarding (T-TRM-03), daemon session/cgroup implementation (T-TRM-07), terminal credential issuance (T-TRM-02), app-agent turn cancellation implementation (T-APP-16), secret delivery and image/toolchain changes.

Land dark against each unlanded dependency contract: T-ACC-01 gates roster identity/sign-in; T-ACC-03 gates serving member commands through Authorize; T-GH-01 gates GitHub-backed admission/rechecks; T-INS-02 and T-SEC-01 gate guest execution and revocation activation; T-STK-01 gates takeover. Missing authority, permission or termination providers refuse before effects. Keep downstream delegated credentials (T-ACC-04), shared polling (T-GH-02), Members card (T-APP-06), live transports and app-agent turns (T-COL-02, T-APP-16), and S2 unix users/daemon/SSH (T-MCH-11, T-TRM-07, T-TRM-03) dark until joint checks pass; do not add reverse dependency edges to these consumers. ## Security preconditions and root inputs
Repository code executes only as an unprivileged user inside a machine (M-29); no host repository execution, root member session or sudo. smithers-3f reviews the root boundary. This ticket reuses trusted guest cleanup; it adds no root setup or key-install step. Activation requires T-SEC-01's C-SEC-02 receipts. No branch-built helper, interpreter, binary or import is installed or executed by root.

- Root startup/retained wake consumes the main-pinned bundle helper/digest, install command/destination, bundled msb/base interpreter/executables, fixed PATH/PYTHONPATH, machine id and install configuration; retained image/snapshot, filesystem ancestors and environment/cache entries can contain branch/member data. T-SEC-01's R1–R3 input inventory applies in full. `TestGuestHelperInstallPinsInterpreterAndEnv` and `TestRootSetupNeverFollowsMemberSymlinks` prove provenance, bounded environment and no-follow validation before privileged use on fresh and retained machines (C-SEC-02).
- Root revocation cleanup consumes main-pinned helper code and fixed cgroup subtree; host-generated machine/exec/session ids and DB member/sponsor bindings come from install state, never branch-selected ids. Request envelope/file bytes, argv/env/cwd/paths, retained directory/symlink metadata and process population can come from branch/member data; passwd/group records, cgroup files, descriptors, signal/wait/exit results come from the trusted image/kernel, influenced by those processes. `TestRootPreflightParsesOnlyEnvelope` proves bounded identity/request parsing, protected request paths and cgroup confinement before root use; payload execution follows group/GID/UID drop (C-SEC-02). C-ACC-03 proves production cleanup terminates guest children within 5 s. Any branch-sourced data consumed before these validations is a landing blocker.
- Roster mutations, migrations, permission/key HTTP responses and SSH public-key parsing run in the unprivileged host service. GitHub keys never become privileged guest input; member provisioning and the S2 broker's root input validation belong to T-MCH-11 and T-TRM-07, and remain dark until their checks pass.
