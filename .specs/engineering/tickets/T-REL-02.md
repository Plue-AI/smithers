## Security preconditions and root inputs

Repository flows, template checks, coding agents, tool-login calls, outside-save commands, terminals and SSH execute only as unprivileged users inside machines (M-29, §1.3). The host runs installed or reviewed recording tools only; it never imports or executes canary repository code. No member or agent has sudo. Record no tool tokens or provider keys in videos, traces or logs. smithers-3f accepts the execution and redaction boundary before qualification. C-SEC-02 and C-MCH-10 supply isolation and credential evidence.

The recorder, Homebrew-installed launcher and per-user LaunchAgent introduce no root step. Machine preparation and sessions use existing privileged paths. Record these inputs and sources for each qualification run; unknown provenance refuses the run. Main means trusted main-pinned code or the approved installed bundle, not the TODO branch. Branch/member data remains blocked before privileged use until the named production test passes; branch-built code, interpreters, imports and toolchains remain forbidden even after a test passes.

- Guest helper installation/startup (R1): helper/install-script bytes and digest, fixed destination, msb path, machine ID, deadlines and host environment are main/bundle or install-controlled state. Image/layer selection and OCI metadata/blob responses use main-pinned manifests; shell, Python, hash/core utilities and import/search paths come from that approved base. Retained snapshot files, helper/temp ancestors, caches and environment can be branch/member-controlled. Require `TestGuestHelperInstallPinsInterpreterAndEnv` through C-SEC-02 on fresh and retained machines before privileged cleanup or helper start.
- Guest setup/home defaults (R2): setup login/UID/GID/directories, fixed home links and Go settings, account records and account utilities come from main/bundle and authenticated install allocations. env.json keys/values, PATH/PYTHONPATH/tool-cache settings consume branch-derived toolchain selection; home/cache names, bytes, modes, owners, ancestors and symlinks consume branch/member-retained state. Filesystem results come from the guest kernel. Require `TestRootSetupNeverFollowsMemberSymlinks` for bounded settings, no-follow writes and replacement races before chown/chmod or home/cache use.
- Exec/fs/terminal/cleanup/relay (R3 and the S2 broker): request IDs, fixed identity envelope, cgroup subtree, relay endpoint/port, registered run, per-boot authority, account bindings, request-directory ownership, deadlines and signals come from main/bundle and authenticated install state. argv/env/cwd/stdin, file paths/content/modes/read limits, terminal size, request-file bytes, retained symlink graphs and process population consume branch/member data; cgroup/fork/wait/signal/fs/network results are kernel/peer observations. Broker secret/env bytes come from authenticated host secret storage; home credential bytes are member-controlled. Require `TestRootPreflightParsesOnlyEnvelope` before privileged parsing/use and C-COL-04 for the broker, fixed identities, credential-home child UID drop, socketpair caller and path confinement. Apply command payload only after supplementary-group/GID/UID drop.
- Layer builds (R4): image/toolchain/download manifests and digests, base interpreters, package destinations and machine.json package list come from main/bundle; index/recipe/toolchain selection, package/lockfile bytes, archives, tar/chown destinations, marker parents and retained caches can come from branch data. Registry/network responses are untrusted bytes checked against the pinned manifest. Require `TestRootLayerInputsValidatedBeforeUse` through C-SEC-02 before any branch-derived data reaches root; dependency install scripts and checks run unprivileged in the machine.
- Managed artifact installation (R5): helper/CLI/skill/flow-host bytes, catalog digest, interpreter and fixed install destinations come only from main/bundle. Candidate paths, workspace/run/machine binding and retained parents may carry branch/member data. Require `TestRootManagedArtifactInstallUsesApprovedBundleOnly` and the C-SEC-02 guest-coding binding/helper tests before installation or dispatch; never install branch build output as root.
