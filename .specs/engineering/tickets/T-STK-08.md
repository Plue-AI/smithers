## Goal
S1: anyone on a branch rebases it now; the stack service performs it and records "Smithers, for Ben". A conflict gets one agent attempt, then Needs you with the paths and Resolve; nothing retries silently. S2: with people on the branch the rebase waits as "Rebase pending" and never runs during a write made through Smithers.

## Scope
Build against the declared contracts while dependencies land in parallel. S1 lands dark: refuse rebase and Done before effects when any required stack claim/fence, branch target, durable run/wait, policy, authorizer/delegated credential, catalog, bundled microVM or validated guest boundary is unavailable. Keep Resolve unavailable until T-UI-04's conflict view is wired. S2 lands dark: retain Rebase pending until authenticated daemon/capture, mutation lock, complete broker session cgroups, member identities, presence and sleep/captured-head providers are available. Missing or unknown presence is not agent-alone. Never substitute the host path for an awake branch. Enable each phase only after its named checks pass; exercise each missing-provider refusal in C-J7-03 (S1) and C-J10-04 (S2).
In:
- S1: `/branch.rebase` and `branch.rebase-now` (`agent: run`), `POST /api/branches/{b} {rebase}`. Item branches rebase onto `rebase_pending.onto`; scratch branches onto their fork source's current head. jj operations are the engine's own. A clean rebase reruns checks only; an agent-resolved conflict is new work (implement, check, review). Approvals clear after any rebase.
- S1: one resolution attempt inside the item's `todo` run (`conflictAttempts`, default 1, an install setting via T-FLW-02), then a `conflict` wait through T-STK-01 with the paths. **Done** settles only when `jj resolve --list` is clear, else `409 {code: still_conflicted}`. Scratch conflicts retain the pre-rebase head, conflict change, onto revision and paths, without an agent run. Scratch Done uses `branch.rebase` on `POST /api/branches/{b}` with `{conflict_change, onto_revision}`; validate the retained binding and unresolved paths in the guest before advancing. A stale target or remaining conflict changes neither head nor paths (C-J7-03).
- S2: `Decide(pending, presence)`: agent alone → next durable boundary; people present → "Rebase pending" until they leave or press Rebase now. Awake branches rebase through the daemon's `rebase(onto)` under the §9.4.2 freeze (mutation lock, cgroup freeze ≤ 1 s, capture, rebase, thaw; lock < 2 s). Asleep branches rebase on the host against the captured head without waking.

Out: Fork and Add to stack (T-MCH-08); other conflict producers (T-GH-06, T-COL-05); the Branch card and its S2 Resolve/Done rendering (T-APP-10); new visual Views (T-UI-04, T-UI-15); live document reload and Yjs/Yrs reconciliation (T-COL-08, S3); a new scheduler, retry engine, machine launcher, wire codec or root broker; agent overrides of system rebase; host execution of repository hooks, helpers, filters, flows or checks; free-form model history commands; a synthetic TODO or coding run for a scratch conflict.

## Security preconditions and root inputs
Repository flows, coding, checks, conflict resolution and working-copy jj run only as unprivileged users inside machines (M-29). Host asleep rebase consumes captured objects as data using install-controlled plumbing; repository configuration cannot select executable hooks, helpers, filters or imports. Members and agents have no sudo. smithers-3f reviews and accepts C-SEC-02 receipts. Branch-built code is never installed, imported or executed by root; a digest does not waive this rule.

- S1 root startup/setup/exec/file/cleanup consumes the complete R1–R3 input inventory in T-SEC-01: main-pinned helper/install bytes and digest, fixed destinations and commands; install-controlled bundle executable, image/base/interpreters, PATH/HOME/startup imports, machine/account IDs, deadlines, request transport, cgroup subtree and relay endpoint; branch-derived toolchain/env/cache data, argv/cwd/file payloads and capture outputs; member-controlled retained homes, request entries and symlink graph; kernel/filesystem/network responses and process state. These remain blocked until the three named production R1–R3 tests above prove validation before root use, including retained wake cleanup. Payload execution occurs only after group/GID/UID drop.
- S2 root broker boot consumes the main-pinned, bundle-shipped broker binary, fixed daemon binary and uid/gids, startup argv/environment, socketpair descriptors and fixed session-cgroup parent; install-controlled base/init, trusted file ownership/modes/ancestors, account records and kernel cgroup-v2 state. Retained image/path/environment entries can be branch/member-derived. `TestGuestHelperInstallPinsInterpreterAndEnv`, `TestRootSetupNeverFollowsMemberSymlinks` and `TestRebaseBrokerValidatesFreezeInputs` must prove trusted provenance and refusal of substitutions before root startup or cgroup access.
- S2 root freeze/thaw consumes only the main-defined bounded operation enum and fixed deadline, inherited private socketpair and expected daemon peer; the install-controlled descriptor for `/sys/fs/cgroup/smithers/sessions/`; and kernel `cgroup.events`/`frozen`/process-population responses influenced by branch/member processes. Retained directory entries, broker request bytes and session population are potentially branch/member-derived data. `TestRebaseBrokerValidatesFreezeInputs` proves bounded parsing, the sole peer, fixed subtree, no-follow handling and thaw on every failure before privileged use. No request-supplied cgroup path, uid, environment, argv, working-copy path or onto revision reaches root; busy-writer attribution stays in the unprivileged daemon. Capture, drain, rebase and conflict files remain daemon work. Branch-derived inputs without these validation receipts block enablement.
