# App shell, cards, commands — current state (main, 2026-10-02)

Paths are relative to `apps/app/src/mainview/` (written `mv/`) unless they start with `apps/`, `packages/` or `.specs/`. Counts come from `rg`; "inferred" marks anything not read directly.

## Summary
- The app is a React + TanStack DB (OPFS SQLite) client; state changes enter through one Flux dispatcher. A card is a React component in the transcript, not an iframe (iframes appear only in the browser card and custom run UI).
- One flow registry (~267 `name:` literals in `mv/flows/entries/*.ts`, plus the 27 shared wiki operations from `packages/smithers/ui/src/app-operations/wiki.ts`, plus repository flows) feeds slash, ⌘K palette, buttons and the single agent `commands` tool. Appendix A lists 58 commands; the catalog is about 5x too wide and has no MVP filter.
- Built and reusable: StackCard (home), ChangeCards (PR/diff with review threads), FileCards + CodeSurface (code intelligence via `code.hover/definition/diagnostics`), WorkspaceCard (terminal facet), IssueCards, RunTrace/Runs cards, FlowGraph/FlowPlan, toast stack (300 ms law, cap 3), Jev command selection (`POST /api/commands/select`), FlowFormCards (form law).
- Missing for the MVP: TODO card, Draft, Review&merge confirm, Learning proposal, Members, Settings/install setup card, Commands (help) card as a card, branch-per-TODO Branch card with presence, live co-edited File card, line comments in the diff, browser notifications (none exist: no `Notification` API use in `mv/`).
- Cut surfaces are wired into `App.tsx` and `CardRenderers.tsx`: SetupChecklist, SignupCards, RepositorySetupCard, SubagentGrid, BurndownCard, BillingCards, AdminCards, setup/billing/admin/signup/chores/ci/feature flows.
- No lint enforces product words (D-16) or MINIMAL TEXT; `apps/app/lint/conformance/` pins literals and vocabularies derived from source only. `useEffect` is banned by AGENTS.md but appears in three non-test files (StartupBoundary, FlowGraphSurface, FlowRunGraphSurface).
- Mock cards use the real `.smithers-card` chrome and `@smthrs/ui`; mock `AppFrame` copies the real shell anatomy, so the port is a rename plus new data, not a redesign.

## Architecture
- Entry: `mv/main.tsx:1-3` -> `AppIsland.tsx` -> `AppMount.tsx` / `AppRoot.tsx` / `ControllerBoot*.ts` -> `ControllerProvider.tsx`. Shell in `App.tsx` (676 lines), `SessionShell.tsx` (wordmark entrance), `Composer.tsx`, `SearchPalette.tsx`. Bun host in `apps/app/src/bun/` (`server.ts`, `serve.ts`, `CloudAgent.ts`, `ModelTurnHost.ts`, `ConfiguredModelHost.ts`).
- State: `state/AppStore.ts` builds TanStack DB collections (`createCollection`, `localOnlyCollectionOptions`) persisted to OPFS SQLite `smithers-mvp.sqlite` through `@tanstack/browser-db-sqlite-persistence` (`AppStore.ts:4,244,619`), falling back to localStorage (`AppStore.ts:613`). Writes go through `AppStore.dispatch` with an actor, journaled in `state/AppEventStream.ts` (event log, checkpoints, replay).
- Controller: `state/AppController.ts` composes sub-controllers in `state/controller/*` (turns, failures, runs, workflows, forms, frames, promptQueue, etc.). Seams (`state/seams/*`: StackSeam, WorkspaceSeam, SeamContext) hold live backend reads; cards read them with `useSyncExternalStore` (`cards/StackCard.tsx:35-39` `useStackSnapshot`) or `useLiveQuery` on collections (`cards/FileCards.tsx`, `RepositoryHomeCard.tsx`). Runtime seams: `runtime/ApplicationClient.ts`, `ApplicationTransport.ts`, `AgentPort.ts`.
- Card rendering: persisted `Card` rows (schema `packages/rpc/src/Cards.ts`, `kind: z.literal(...)`, e.g. `factory.home` at line 721) render through `ChatCards.tsx` (shell: header, status pill, maximize/minimize at lines 133-165) and the renderer map `cards/CardRenderers.tsx` (one `*CardFamily` spread per file; mapped type makes a missing kind a compile error; `CardRenderers.test.tsx` proves disjoint and complete). Card families are typed by `cards/CardFamily.ts:1-118`. Cards raise acts only as `RunCommand(FlowName, args)` (`CardFamily.ts:21`, `cards/CardActions.ts:52` `onMaximize -> card.maximize`).
- Maximize: `card.maximize`/`card.minimize`/`card.dismiss`/`card.history.*` flows in `flows/entries/card.ts`; same component, `maximized` prop (`ChatCards.tsx:67,85`), backdrop `card-maximize-backdrop`. Frames and URL: `runtime/FrameHistory.ts`, `state/controller/frames.ts`.
- Card subscribes to backend data: backend writes arrive as app events (`state/AppEventStream.ts`) or seam snapshots (stack, workspace, LSP via `state/CloudLspClient.ts`, terminal via `state/CloudTerminalClient.ts` + `tabs/TerminalView.tsx`), then project into collections. The app is a client of `packages/backend` (Go) via `packages/rpc`.
- Agent turn: `state/controller/turns.ts`, `httpTurns.ts` -> `/api/*` turn routes; web agent `native/WebAgent.ts`; tool contract `flows/agentTools.ts:1-288`.
