# CLI, skill, API, docs, cuts — current state (main, 2026-10-02)

## Summary (≤8 lines)
- `smthrs` is one incur 0.5.1 tree (`packages/smithers/src/Cli.ts`); ~75 top-level commands, 205 backend commands declared as zod data in `internal/backend/Definitions.ts`. Per-command skills are generated by incur (`smthrs skills add`); the one hand-written `skills/smithers/SKILL.md` is an authoring guide, not the Appendix A catalog.
- There are TWO command catalogs: the app registry (`apps/app/src/mainview/flows/entries/*.ts`, ~227 descriptors, slash names) and the CLI tree. They meet only at the HTTP API. Nothing checks Appendix A against either. §2 rule 1 / M-21 ("same catalog") is false today.
- Appendix A has no CLI door for most TODO/branch/flow verbs (`/todo.*`, `/merge`, `/branch.*`, `/flow.edit`, `/members`, `/settings`). Closest: `smthrs history todo|land|retry`, `smthrs workspace *`, `smthrs flow *`.
- `smthrs login` = alias of `auth login` (browser loopback consent, token in keyring/`~/.smithers` file, or `SMITHERS_TOKEN` env). No branch-terminal auto sign-in and no distinct "agent delegated credential" minted by login were found; the person/agent split exists only server-side for run credentials and agent accounts (`RequirePerson`).
- API is open and documented: `docs/api/openapi.yaml` (23k lines, 398 `/api` paths, Go-conformance-tested against served routes). It still carries Cut surfaces (billing, admin, oauth2, branch-locks, changes split, mythical backfill/bootstrap, repository-jobs).
- Docs: 50 generated Starlight sites (`apps/docs/*`) plus `apps/site`; nothing close to "one quickstart + flows reference". `docs/mvp/{PRODUCT,ENGINEERING,DESIGN}.md` still specify the old five-jobs product and are referenced by AGENTS.md (D-16).

## `smthrs login`, delegated credentials, branch terminals
- `smthrs login` (`Commands.ts` tail alias -> `auth login`, `internal/backend/Auth.ts`): `browserLogin` (`Auth.ts:50-`) opens a loopback server, browser consent returns a token in the URL fragment; options `--host --admin --observe --ttl --with-token`. Admin tokens `--ttl` 5m-12h (`Auth.ts:107-113`). Self-host owner path `auth local login|bootstrap` posts to `/api/auth/local/token` with scopes `write:user write:repository write:workspace write:approval write:agent` (`Auth.ts:268`): a person token that includes `write:approval`.
- Session resolution order (`internal/backend/Session.ts:343-370`): `SMITHERS_TOKEN` env wins, then keyring, then `smithers_auth_file`, then config. So a branch machine can be pre-signed-in today only by injecting `SMITHERS_TOKEN` (+ origin) into the terminal env; nothing in `packages/backend` sets it (rg `SMITHERS_TOKEN` hits only `git_mirror_sync.go`, a test). Inferred: the M-18/§6.13 "branch terminals sign in automatically" is unbuilt.
- Person vs agent enforcement exists server-side: `internal/middleware/run_credential.go:136-175` `RequirePerson`/`RefuseRunCredentials` refuse run credentials AND agent accounts (`IsAgentAccount`) for landing, approval decisions, commit statuses, run start/cancel/resume; `internal/services/mythical_land_todo.go:45` guards TODO landing; `docs/run-credentials.md`. Run tokens carry an `agent-session:<id>` restriction scope (`internal/middleware/scope.go:71-107`). Gaps vs §6.13: (a) a laptop agent that runs `smthrs login` obtains the member's own person token, which can land/approve; need a delegated agent credential (member + agent name, no approve/merge/main scope) minted by `login --agent <name>` or by the app confirmation flow; (b) attribution "Ben via Claude Code": `credential` has no agent-name field found (rg "via " in backend only hits models/sql; Partial per §6.13); (c) "confirmation opens in the app, unreachable by agent processes" needs a new person-only route; `RefuseRunCredentials` is the right guard.
- Over MCP, login/destination are host-owned (`Commands.ts` `Refused host_owned`).
