# C-J11-02 Flow Source, Plan and a draft-version Run on a scratch branch

Proves: mvp.md J11.2–J11.3, §6.14 Write flows and Monitor (custom view), §6.12 Run any flow, Appendix A `/flow.source`, `/flow.plan`, `/flow.run`, Appendix B.2 (`flow.source`, `flow.run`) · spec.md §1.3, §6.1.4, §8.5.1, §10.4.1a, §11.3.3, §11.4.3, §11.5b, §11.6.2 · Layer: e2e · Stage: S2 (edit through the branch terminal), S3 (edit in the File card) · Tickets: T-APP-05, T-FLW-04, T-FLW-05, T-FLW-07, T-UI-10, T-UI-12
Automation: `apps/app/e2e/real/flow-source-run.spec.ts` (new) · Runs in: reference host

## Setup
- Install at the commit under test, capacity ≥ 2. Will (owner) and Ben (member) signed in on two browsers.
- Scratch repository `smithers-mvp-canary/<date>` with `package.json` scripts `test` and `lint`, a `NOTES.md`, and `flows/hello/flow.ts`: a repository flow with payload `{name: string}` (required), two steps, and a declared custom view (the descriptor's `presentation`) that renders "Hello, <name>". `hello` is Active after `flow-load`.
- The built-in `todo` flow is Active at digest D1. No open TODO touches `flows/todo/`.
- The host's flow-host log and process list are captured for the whole run.

## Steps
1. Ben types `/hello` with no input. He fills `name` with `Ada` in the form card and submits.
2. Ben opens Inspect on the `hello` run.
3. Ben opens `/flow todo` and selects **Source**.
4. Ben adds a step `notify` after `check` in `flows/todo/flow.ts` on the branch that opened. S2: with an editor in his own terminal on that branch. S3: by typing in the File card. Wait until the File card shows the edit.
5. Ben forks that branch to a scratch branch S (`/branch.fork`).
6. On S, Ben selects **Plan** on the `todo` Flow card.
7. On S, Ben selects **Run** on the `todo` Flow card with the test input "Add the line 'draft' to NOTES.md". He opens the run's monitor and watches it to the end.
8. While step 7 runs, Will creates TODO X and lets it reach its first step.
9. Read the `todo` Flow card, the Home card, `todos`, `outbound_writes` and the GitHub write log.

## Pass when
- Step 1: `/hello` with no input renders a form card with the required field `name`, never a usage sentence (§6.1.4). The run executes in a machine, never in a host process (§1.3).
- Step 2: the monitor shows the flow's custom view reading "Hello, Ada" beside the graph. A flow without `presentation` (the `todo` run in step 7) shows no custom view.
- Step 3: the File card shows `flows/todo/flow.ts` on the branch of the TODO that proposes the change, which is the Flow card's Proposed version (§11.5b, §11.3.3). The file is the built-in composition (§10.4.1a).
- Step 6: Plan's graph shows `notify` between `check` and `review` before any run starts. The flow-host log shows the working-copy version loaded inside S's machine, and no host process loads it (§1.3).
- Step 7: the run card and the monitor read "draft version". Its graph includes `notify`, and each step's state reaches the monitor within 1 s of its `run:<id>` delta. No `todos` row references the run. It opens no PR, writes no `outbound_writes` row and calls no GitHub write, and it ends before proposing (§11.4.3).
- Step 8: X pins D1.
- Step 9: the Flow card's Active version is still D1 and Proposed is the step-3 TODO. The Home card lists no TODO for S.

## Fail when
- A missing input answers with a usage sentence, or the custom view is absent for a flow that declares one.
- Plan or Run loads repository flow code in a host process.
- The draft-version run appears on the stack, opens or updates a PR, or changes the Active version.
- X pins the edited version.
