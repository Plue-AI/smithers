# C-J7-02 Fork T2 to scratch, Add to stack as a new TODO after T2, drop T2

Proves: mvp.md J7.2, J7.3, §6.7 Fork, Appendix A (`/branch.fork`, `/branch.add-to-stack`, `/todo.drop`), Appendix B.2 (A✓), M-22 · spec.md §8.5, §8.5.3, §8.5.3a, §10.2, §10.7.2, §15.1.5 · Layer: e2e · Stage: S1 · Tickets: T-MCH-08, T-STK-05
Automation: `apps/app/e2e/real/fork-add-to-stack.spec.ts` (new) · Runs in: reference host

## Setup

- A fresh install on the reference host at the commit under test, wrapping `smithers-mvp-canary/<date>`, with the install's GitHub App installed.
- Stack: T1 in review; T2 working on `smithers/retry-webhooks` after a steer, with an open PR whose head is T2's last verified head H2, and an uncommitted edit in its working copy; T3 queued. Ben (member) is in the browser at one of the install's public origins.

## Steps

1. Ben runs `/branch.fork` with source T2 and name `retry-v2`.
2. Read `GET /api/branches/scratch/ben/retry-v2`, the branch tree and T2's run.
3. Ben opens a terminal on `scratch/ben/retry-v2`, edits `src/retry.ts`, and commits with `jj commit -m "try exponential backoff"`.
4. Read GitHub's branch list for the repository.
5. Ben asks the app agent in ⌘K to add the scratch branch to the stack. The agent posts a one-click Confirm card (`/branch.add-to-stack` is `agent: confirm`, §15.1.5). Read the stack, then Ben presses the card with the default placement.
6. Ben runs `/todo.drop T2` and confirms.
7. Read the stack, T2's PR on GitHub, the new TODO's branch and run, and the activity of both branches.
- Invoke Fork and Add to stack from the real TODO Container and record cardActions → flowAction dispatch.

## Pass when

- Step 2: the branch has `kind: scratch` and `forked_from {item: T2, commit: H2, base: C1}`, where H2 is the stage-1 fork source (§8.5.0) and C1 is T1's verified candidate that H2 was built from (§8.5.3), and the tree shows it under T2. T2's uncommitted edit is not in it. T2 stays Working throughout, and its machine has no stop, restart or pause.
- Step 4: no `scratch/*` branch exists on GitHub.
- Step 5: before the press, the stack is unchanged. After it, a new TODO T4 appears directly after T2, with no PR yet. Its revision 1 seed is the diff from C1 to the scratch head: T2's change plus the `src/retry.ts` edit. The same branch id is now `smithers/<slug>` with T4 as its item, on the same workspace, and Ben's terminal on it is still open.
- Step 6: T2 shows Dropped. Its PR is closed with the comment "Dropped in Smithers by @ben".
- Step 7: the stack order is T1, T4, T3. T4 passes through Starting to Working on its branch. T4's tree equals its tree before the drop, so T2's change and the `src/retry.ts` edit are both in it, and T4's item diff (from T1's candidate) lists T2's paths and `src/retry.ts` (§8.5.3a).
- The fork and the Add to stack each appear once in branch activity as "Smithers, for Ben" (M-32).
- No **Replace T2** action is offered anywhere (deferred, §0, §8.5.3).
- Fork dispatches branch.fork with `{from: "T2"}`; delegated branch.add-to-stack returns 202 with pending state and renders the requesting member’s private Confirm card. No TODO exists before the person’s press.

## Fail when

- T2's run is interrupted, paused or restarted by the fork.
- The app agent creates T4 without Ben's press on the Confirm card.
- The new TODO lands at the end of the stack instead of after T2, or Add to stack creates a second branch or workspace.
- The scratch branch is pushed to GitHub before it joins the stack.
- Dropping T2 removes any part of T2's change from T4 (J7.3).
- A history write is attributed to Ben or the agent instead of Smithers for Ben.
- A toast or card shows the TODO or Dropped state before its event exists (honest state, §19.3).
