# C-J4-02 Answer, merge next, move up and retry with a steer, all while chatting

Proves: mvp.md J4.2, J4.3, §4.2 Merging, rule 5, AGENTS.md "Instant chat" · spec.md §4.1, §6.2.2, §10.2.3, §10.6.1, §10.7.1, §10.8.2, §14.4 · Layer: e2e · Stage: S1 · Tickets: T-STK-02, T-STK-05, T-APP-02
Automation: `apps/app/e2e/real/todo-stack-actions.spec.ts` (new) · Runs in: reference host

## Setup
- Install from the commit under test on the reference host; record version and commit.
- Scratch repository `smithers-mvp-canary/<date>` with a fixture `todo` flow at `flows/todo/flow.ts`, merged and Active (T-FLW-03). It raises an `ask` wait when the prompt contains `ASK`, fails at its check step when the prompt contains `FAIL` and the attempt's first message doesn't contain `FIXED`, and otherwise opens a PR with a one-line change.
- Seeded through the public API (`apps/app/e2e/real/support/seed-stack.ts`, new): T1 `in_review` (green), T2 `needs_you{question}` (`ASK`), T3 `failed` (`FAIL`), T4 `in_review` (green). Stack order T1, T2, T3, T4.
- The lead, owner Will, in one browser in `main`'s conversation. Merge (T-STK-04) and answers (T-STK-01) must also have landed.

## Steps
1. Will asks the app agent "where do we retry webhooks?" and, while it answers, performs steps 2-5 from the Home card.
2. Answer T2's question.
3. Merge T1 after opening its evidence.
4. Move T4 up once so it sits above the stuck T3 (order T2, T4, T3 after T1 merges).
5. Retry T3 with the steer "FIXED: fix the real bug, keep the test".
6. Read the chat transcript, toasts and the Home card until every action settles.

## Pass when
- Each action returns an acknowledgement (`requested` or `accepted`) in under 1 s, measured from click to the acknowledgement frame; n = 4 actions, each listed.
- The app agent's answer streams and completes while the actions run; no input is disabled.
- Each action has a toast that stays running through execution and settles only on its terminal projection event (§14.4).
- Final state: T1 `merged`; T2 `working` or later with one `answer` event; order T2, T4, T3; T3's attempt 2 has passed `queued` and `starting` and is `working` or later, with the steer as its first message and attempt 1 kept.
- After step 3, T4 shows "Merges after T2", and no item shows **Merge** while T2, the first unmerged item, isn't in review.

## Fail when
- Chat waits on any background action, or a toast settles at launch instead of completion.
- Move reorders the cards but not the engine (admission or merge order unchanged).
- The answer or retry is applied twice after a double click.
