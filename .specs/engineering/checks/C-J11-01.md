## Setup
- Install at the commit under test, stage 1; Will (owner) and Ben (member) signed in on two browsers.
- Scratch repository `smithers-mvp-canary/<date>` with `test` and `lint` scripts.
- T5 seeded so that its run: asks one question that Ben answers 2 minutes later; fails `lint` on its first check attempt and passes on retry; makes model calls in plan, implement and review.
- A `flow-load` background run (T-FLW-03) from a `main` move that touched `flows/**`.
- A second run killed mid-step in a step with no reconcile, so the engine reports it `interrupted`.
- Reviewed literal step-title fixtures committed with the scenario.
- A packet-filter rule ready to block the `agent:fast` provider host, and the model proxy's call log.

- Commit literal expected labels, wait timestamps, role IDs, usage values and cost totals with the scenario. The test oracle never parses .specs files or calls the production label, pricing or projection code; rate changes require a reviewed fixture update.

## Steps
1. Let T5 reach Merged. On its run card, select Inspect.
2. Read every step title in the graph and the timeline. Expand the "Engine" row.
3. Select the `implement` node in the graph.
4. Open the timeline, the waits list, the steps view and the journal.
5. Scrub the replay to the middle of the run, then back to the end.
6. Run `/monitor`.
7. Inspect the DOM of the trace card for filters and controls.
8. Open T5's phases. Read each phase title, each cell label, and how each summary and explanation renders.
9. Block the fast-model host. Start a seeded run X, open its Inspect at once, and keep it open for 60 s. Unblock the host and keep it open for another 40 s. Start a run Y that nobody inspects, and let it finish.

## Pass when

- T-APP-07 summary-ordering integration: the phase/cell job is admitted atomically with its source event. Rolled-back events admit no job. A committed job survives restart. A late result for an old run, attempt or source revision cannot change the current phase/cell summary or projection; literal independently authored expected text remains intact.
- The graph shows every step with its final state, and step states change live while a run is in progress (checked on a second, live run within 1 s of its `run:<id>` delta).
- Step 2: each step's title equals its Appendix C rendering (for example "Edited the files" for `coding/edit-atom`, "Ran checks" for `coding/check-command`). Bookkeeping tags (`<seal-step>`, `<boundary:name>`, `agent/trace/checkpoint`, quota parking) appear only inside one collapsed "Engine" row for the run, never as steps.
- `implement` shows its input, output and agent transcript.
- The timeline shows both attempts of the check step, the first failed and the second passed.
- The waits list shows the question with kind, a "since" timestamp, "answered by Ben" and its settle time; since and settle time differ by 2 min ± 5 s.
- Each step with model calls shows tokens, time and cost; each step's cost equals the sum of its usage rows times `modelprice`, to the cent; a step with no model call shows no cost.
- The journal lists the run's events in order, read-only.
- Scrubbing changes only the view: no request other than reads is sent.
- `/monitor` lists T5's run, the `flow-load` run and the interrupted run, the last one as "Interrupted" with Retry.
- No `forks` filter chip and no fork or rewind control exists in the DOM.
- Step 8: each phase title equals its step's Appendix C rendering plus the outcome its recorded output reports, for example "Ran checks · 1 failed" for the first check attempt and "Ran checks" for the second (§11.6.3). Each cell shows its deterministic label. Replaying the run's journal gives byte-identical titles and labels with no model call. Every phase summary and cell explanation renders marked as a model summary.
- Step 9: while the host is blocked, every phase of X shows its title alone and every cell its label alone, with no error, spinner or placeholder, and X's steps finish within 2 s of an unblocked baseline run. Within 35 s of unblocking, X's phases gain summaries. The model proxy log shows no phase-summary or cell-explanation call for Y (§14.5.3).

## Fail when
- A step shows a raw tag id where Appendix C has a rendering, or bookkeeping shows as steps.
- Cost is missing or shows `$0.00` for steps that made model calls.
- The wait shows no "since", or shows the time the card opened.
- A retry hides the failed attempt.
- A fork, rewind or edit-and-rerun control appears, or scrubbing writes to the run.
- A phase title comes from a model, an absent summary shows an error or placeholder, or the summarizer slows the run.
