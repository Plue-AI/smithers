# C-J5-03 A learning proposal with evidence becomes a TODO that fixes the next TODO

Proves: mvp.md J5.5, §6.12 Learning, §10 Self-improvement, M-04, M-15 · spec.md §6.1.2 (in-card), §11.3, §11.5, §11.8 · Layer: journey · Stage: S3 · Tickets: T-FLW-06, T-REL-02
Automation: `apps/app/e2e/real/learning-journey.spec.ts` (new), recorded · Runs in: reference host, recorded manual on a fresh macOS user account on the reference mini

## Setup
- Fresh install at the commit under test on a fresh macOS user account on the reference mini, reached from a second Mac on the same network; owner and one maintainer signed in.
- Scratch repository `smithers-mvp-canary/<date>` with `package.json` scripts `test` and `lint`, where `lint` fails on unused imports. The built-in `todo` flow's check step runs `test` only (install-stored config with `lint` removed for this journey).
- Five TODOs written so that three of them leave an unused import: each is merged after the review step reports the lint failure and the agent fixes it.

## Steps
1. After the fifth merge, wait for its learning run on the home card's background runs.
2. Open the merged TODO's "N lessons" receipt. Open the proposal card.
3. Read the proposal's title, evidence and refs.
4. Select Make TODO. Wait for In review. The maintainer merges it.
5. Wait for the `todo` Flow card to show the new version Active.
6. Create a sixth TODO that again tends to leave an unused import.
7. Read the sixth TODO's evidence for its first check run.

## Pass when
- The learning-produced flow change runs under the previously pinned TODO closure; after real activation the sixth TODO pins the new immutable closure, imported review and dependency environment. Each TODO attempt has one run across implement, check, review and proposal loops; learning remains its separate background run. This S3 journey does not substitute for S1 C-J5-01 activation acceptance.
- The learning run is a background run that never becomes a TODO, and the fifth TODO stays Merged with no new state event.
- The receipt count equals the decision pages plus proposals the run wrote.
- The proposal's evidence states "3 of the last 5" with the three TODO refs, and its `signature` names the lint failure at review (`check:lint@review`, §11.8.2a).
- Make TODO creates exactly one TODO whose seed patch adds `lint` to the check step; nothing changes before a person merges it.
- The sixth TODO's first check run includes `lint` and passes it on the first attempt, with no lint finding at review.

## Fail when
- The flow-change TODO runs its own unmerged instructions, a correction creates another TODO run in the attempt, or this learning journey is used to claim pending S1 activation acceptance.
- The proposal has no counts or refs, or cites TODOs that never failed lint.
- The proposal turns into a TODO or a flow change without a member's Make TODO.
- The sixth TODO runs the old flow version, or passes only after a review round.
- Learning changes a merged TODO's state, or a second learning run for the same TODO writes a duplicate proposal.
