# C-J3-02 Own terminal as own user; others watch read-only; their keystrokes are dropped

Proves: mvp.md J3.3, J6.5, §6.8 Terminals, M-18 · spec.md §7.1, §7.5, §8.11.1–§8.11.3, §9.1.2 (`open_session`), §5.3.2, §5.6 · Layer: e2e · Stage: S2 · Tickets: T-TRM-01, T-APP-12
Automation: `apps/app/e2e/real/terminal-ownership.spec.ts` (new) · Runs in: reference host

## Setup

- A fresh install on the reference host at the commit under test, wrapping `smithers-mvp-canary/<date>`. Browsers run on a second Mac and open the install's public origin.
- Members: Ben (maintainer) and Alice (member), each in their own browser profile. TODO T1 in Needs you, branch awake.

## Steps

1. Ben opens a terminal on T1's branch from the Branch card. He types `id -un; echo $HOME; pwd; umask`.
2. Alice opens the Branch card. She sees Ben's terminal listed with Ben as owner, and opens it to watch.
3. Ben runs `for i in $(seq 1 5); do echo tick $i; sleep 1; done`. Alice watches.
4. Alice types `touch /workspace/alice-was-here` and Enter into the watched terminal through the UI.
5. From Alice's session, a raw `/api/live` client sends 1,000 kind-4 input frames (`echo injected\n`) on the same terminal subscription.
6. Read `smithers_terminal_input_dropped_total` from `/api/install/metrics` as the owner.
7. Alice opens her own terminal: `id -un`, `ls /home/ben`, `cat /run/smithers/<Ben's uid>/token`.
8. Alice reloads her tab while watching Ben's terminal.
9. A maintainer removes Alice from the roster.

## Pass when

- Step 1 prints `ben`, `/home/ben`, `/workspace` and `0002`.
- Step 2: Alice's view appears within 1 s and is read-only (no input caret, keyboard input not sent).
- Step 3: Alice's view shows all 5 ticks in order, within 1 s of Ben's.
- Step 4: no file `/workspace/alice-was-here` exists, and Ben's terminal shows no `touch` line.
- Step 5: Ben's terminal shows no `injected` line, and the shell's history has 0 such entries.
- Step 6: the counter grew by at least 1,000.
- Step 7 prints `alice`, and both reads fail with permission denied.
- Step 8: Alice's view replays the last screen from the ring (≤ 512 KiB) and continues live.
- Step 9: Alice's watcher and her own terminal close within 5 s. Ben's terminal keeps running.

## Fail when

- Any watcher byte reaches the PTY, through the UI or the raw socket.
- The terminal runs as `agent`, `developer` or one shared user, or the guest runs an sshd.
- The old per-session terminal WebSocket still accepts a connection (T-TRM-01 deletes it).
- An "Ask to type" or "Allow" control appears anywhere (deferred, spec §0).
- Removing a watcher kills the owner's terminal.
