# C-J1-01 Fresh Mac: built bundle or Homebrew install to the setup card, no Smithers account

Proves: mvp.md J1.1–J1.2, §6.1 Install on a Mac, §12.5 · spec.md §1.4, §5.1.0, §8.2.1, §16.1.1, §16.1.2, §16.2 · Layer: journey · Stage: S1, R · Tickets: S1: T-INS-08 · R: T-INS-05, T-REL-02
Automation: `scripts/journeys/j1-install.mjs` (new) records timestamps; the session is screen-recorded · Runs in: reference mini, fresh macOS user account with no prior Smithers state, recorded manual

## Setup
- The reference host after Erase All Content and Settings, macOS 15 or later, one new admin user, Homebrew from brew.sh, Safari and Chrome. No Smithers state.
- S1: T-INS-08's built bundle and bundled `smthrs`, version V, with the manifest recorded. No Homebrew tap.
- R re-run: released tap version V (T-INS-05), recorded by T-REL-02.
- A second Mac B on the same network.
- S1: the operator uses the built bundle's recorded path and these steps. R: the operator follows the quickstart (T-DOC-01) and nothing else.

## Steps
1. S1: unpack the built bundle and record its manifest and bundled CLI path. R: `brew install smithersai/tap/smithers`; note the duration.
2. S1: run the bundled `smthrs host start --bundle <dir>`. R: `smthrs host start`. Record the local URL, one-time setup URL and time to `/readyz`.
3. Open the setup URL in Safari on the Mac, then the plain local URL in Chrome.
4. Read the setup card: steps 0 (Address) to 6 in order, the detected host profile and limits.
5. From B, open `http://<mac-lan-ip>:4000` and `http://<mac>.local:4000`.
6. Repeat the stage's step-2 command with the same bundle.

## Pass when
- S1 runs the built bundle without source compilation or tap installation. R steps 1 and 2 need only those two commands. Both variants need exactly one `sudo` prompt, at `smthrs host start`, to install the launchd daemon (§16.1.2): no Smithers account, no file edited by hand.
- Step 2 prints `http://localhost:4000` and a setup URL carrying a token.
- Step 3: the setup card renders in both browsers; the card shows no VPN or tunnel step.
- Step 4: the host profile equals `sysctl hw.memsize`, `hw.perflevel0.physicalcpu` and the free space on the `$STATE` volume; the limits equal spec §8.2.1's formulas for that profile.
- Step 5: both connections are refused (default loopback bind).
- Step 6 leaves one launchd daemon, running as the installing user, and one backend process, and prints the same URLs.
- The card copy passes C-UI-02 (product words, minimal text).

## Fail when
- Either variant compiles from source or prompts for Xcode/toolchains. The R variant fails if its bottle or archive is missing.
- The setup card is reachable from B before the owner changes the bind.
- The limits match a fixed Mac model instead of the detected profile.
- A second `smthrs host start` starts a second backend, rotates the setup token, or asks for `sudo` again.
