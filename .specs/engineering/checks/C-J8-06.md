# C-J8-06 Generated pages refresh after a merge

Proves: mvp.md §6.11 Generated pages, §6.12 Default flows, §6.4 Home card (background runs), M-11, Appendix B.4 `background.retry`, `background.dismiss` · spec.md §3 (`background_dismissals`), §11.2, §13.5, §14.3 (Home) · Layer: e2e · Stage: S1 · Tickets: T-FLW-02, T-APP-01
Automation: `apps/app/e2e/real/wiki-generated-refresh.spec.ts` (new) · Runs in: reference host

## Setup
- Fresh install at the commit under test, setup complete. Maya (owner) and Ben (member) signed in on two browsers.
- Scratch repository `smithers-mvp-canary/<date>` with no `.smithers/` files and two top-level package directories, `api/` and `web/`. `api/server.ts` exports `startServer`.
- The stored default declaration lists an overview, an architecture page and one page each for `api` and `web` (§11.2, checked by C-J1-06). Each page exists at a recorded revision from the first refresh after setup.
- The test `flows/todo/flow.ts` of C-J4-01 is Active; its `PR` behavior applies a seeded patch and opens a PR at once.
- A fault hook (test builds only) that fails the next wiki refresh at its first step.

## Steps
1. Record each generated page's revision and the commit it was generated from.
2. Create TODO T1 with `PR` and a seed patch that adds `api/health.ts` exporting `healthCheck()`. Ben merges it. Record the merge commit M1.
3. Watch both Home cards until the wiki refresh run finishes.
4. Open the `api` page and its history.
5. Arm the fault hook. Merge T2, which adds `api/ready.ts` exporting `readyCheck()`. Record M2.
6. Ben presses **Retry** on the failed refresh. Wait for it to finish, then open the `api` page.
7. Arm the fault hook again, merge T3 (a change in `web/`), and let the refresh fail. Maya presses **Dismiss**. Both reload.

## Pass when
- Step 3: within 60 s of the merge on GitHub, a wiki refresh run appears in both members' Home card background runs. It is never a TODO and never takes a TODO's machine.
- Step 4: `api` has a new revision generated from M1 whose body names `healthCheck`. The revision's author renders as "Smithers".
- Step 5: the failed refresh stays on both Home cards with **Retry** and **Dismiss**.
- Step 6: Retry starts a new run of the same flow version with the failed run's input. After it finishes, `api` has a revision generated from M2 that names `readyCheck`.
- Step 7: the dismissed run leaves both Home cards and stays gone after the reload. `background_dismissals` holds one row for it, and the run's record is still readable through `/api/runs/{id}`.

## Fail when
- No refresh follows a merge, or the refreshed page doesn't name the merged code.
- A refresh appears as a TODO, or a page revision is attributed to a person.
- A failed refresh disappears without Retry or Dismiss, or Dismiss hides it for one member only.
