# C-J10-09 `/review` on a teammate's PR

Proves: mvp.md §6.3 "A teammate pushes their own branch or opens their own PR", §8 ("Review of outside PRs": deferred to §14), §14 trust rules, Appendix A `/review`, Appendix B.2 `prs.triage` (P, A✓, X) · spec.md §1.3, §8.3.1 (`background`), §11.1.2, §12.3 (teammate row), §15.1.5, §17.5 · Layer: e2e · Stage: S1, S2 · Tickets: T-FLW-13, T-MCH-06, T-FLW-01, T-REL-02
Automation: `apps/app/e2e/real/github-j10/review-any-pr.spec.ts` (new) · Runs in: reference host

## Setup
- Install at the commit under test. Ben and Alice (members) signed in. The built-in `review` flow is Active.
- Scratch repository `smithers-mvp-canary/<date>`. Alice opened PR #50 from her own branch `alice/cache` (not `smithers/*`); its `src/cache.ts` has an off-by-one in `evict()` on a known line, and its tests pass. A non-member, @outsider, opened PR #51 from a fork.
- S2 run: capacity lowered to 2, with one TODO working.
- The GitHub write log of the test account and the host's `machine_requests` table are recorded.

- Use committed literal author IDs, PR numbers/head SHAs and expected findings location/refusal envelopes. Enter /review through the production catalog/API dispatcher; no direct review-service launch or runtime spec/registry-derived oracle qualifies. For S1, capture runtime admission/launch records; machine_requests queue-order assertions apply only in S2.

## Steps
1. Ben runs `/review #50`.
2. Record the review run's machine, its checked-out head and its admission class.
3. Read the findings card when the run finishes.
4. Ben asks the app agent "review PR 50".
5. Ben runs `/review #51`.
6. S2 only: while step 1's machine runs, Alice opens a terminal on a third branch, and Ben runs `/review #50` again.

## Pass when
- Step 2: the run is the Active `review` flow, in an ephemeral machine checked out at PR #50's head SHA (recorded on the run). It never runs on a TODO's machine or in a host process. No TODO, branch or stack item is created.
- Step 3: the findings card lists at least one finding at `src/cache.ts` within 2 lines of the off-by-one, with a severity, and links the PR on GitHub. The GitHub write log shows no review, comment, label or status from the run.
- Step 4: the app agent posts a one-click Confirm card for Ben and starts the review only after he presses it (§15.1.5).
- Step 5: refused with class `permission`, and no machine request is made (outside PRs wait for the maintainer release).
- Step 6 (S2): the review request is `background` class and waits behind Alice's `person` request with a shown position. Its machine counts in the Home card's `in_use` while it runs and is deleted after the run ends.

## Fail when
- The review runs on the host, on a TODO's machine, or at a commit other than the PR head.
- The run writes anything to GitHub, or creates a TODO.
- An outsider's PR gets a machine.
- The app agent starts a review without the Confirm card.
