Proves: mvp.md J3.6, §6.6 Steer, §6.8 Shared agent activity, M-21 · spec.md §2 (actor notation), §3 (`activity`), §6.4, §7.2 (`branch:<id>:activity`), §10.7.3, §11.6.1, §14.6a · Layer: e2e · Stage: S1 · Tickets: T-STK-06

## Setup
- Install from the commit under test on the reference host; record version and commit.
- Scratch repository `smithers-mvp-canary/<date>` containing `src/retry.ts` (a helper `withRetry`) and `src/deliver.ts` (no retries).
- Members: owner Will (browser) and Ben (browser, plus Claude Code on his laptop after `smthrs login <install origin> --agent claude-code`, which needs T-ACC-04).
- T1 by Will: "Add retries to webhook delivery in `src/deliver.ts`." Wait until T1 is in its implement step.

## Steps
1. Record T1's run id, attempt number and the item change id.
2. Ben sends `/todo.steer T1 "use the existing retry helper"` from the browser. Record the request time.
3. Ben's Claude Code sends a second steer through the skill: "keep the max at 5".
4. Read T1's TODO card and branch activity in Will's browser, `item_events`, and the run transcript.
5. Let T1 reach `in_review`; read the diff, and the run id, attempt and change id.

## Pass when
- Step 4: both steers are on the TODO card and in the branch activity in order, the first attributed "Ben" with his avatar, the second "Claude Code for Ben" (§14.6a); each has one `item_events` row and one `activity` row with that actor.
- Step 4: each steer appears in the transcript before the agent's next model call after its request time (≤ one model turn, §10.7.3).
- Step 5: the run id, the attempt and the item change id are unchanged from step 1, and no steer started a run; the diff imports `withRetry` from `src/retry.ts` and caps attempts at 5.
- Step 2 returns an acknowledgement in under 1 s, and the chat stays usable.

## Fail when
- The steer waits for the next attempt or the next flow boundary after implement ends.
- The steer starts a new run or a new branch.
- The second steer shows as "Ben" with no agent named, or as the agent.
- A steer is delivered twice after a retried request.
