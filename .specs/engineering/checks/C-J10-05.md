# C-J10-05 Merge on GitHub turns the TODO Merged and closes its issue with a link

## Setup
- Reference host, install at the commit under test, App installed on a fresh `smithers-mvp-canary/<date>` with squash merging allowed.
- Members: the owner (GitHub browser session) and Ben (browser on a second Mac).
- Issue `#I` turned into T7 with "fixes the issue" set; issue `#J` turned into T8 without it. T7 is first in order, T8 second; both In review with green checks.

## Steps

- Decode literal github_check facts with name, state, required and url. Dispatch order.ok with literal {id, revision}; a newer revision returns stale_attention without clearing the row. Verify both attention kinds and reset bindings together with T-GH-07.
1. On GitHub, the owner squash-merges T7's PR. Record t0.
2. Watch the home card and T7's TODO card.
3. Read issue `#I` on GitHub.
4. Watch T8.
5. Once T8 is updated and its checks are green, merge T8's PR on GitHub. Read issue `#J`.

## Pass when

- The adopted owner contract passes: Decode literal github_check facts with name, state, required and url. Dispatch order.ok with literal {id, revision}; a newer revision returns stale_attention without clearing the row. Verify both attention kinds and reset bindings together with T-GH-07.
- T7 turns Merged within 60 s of t0, and its Merged event is no earlier than the `main` row showing the merge commit.
- Issue `#I` is closed by the App, with a comment that links the change, within 60 s of T7 turning Merged.
- T8's Merge control is enabled. T8's PR gets a new head whose parent is the new `main` tip, and its body no longer names T7.
- After step 5, T8 is Merged and issue `#J` is still open.
- No `checks.Land` approval exists for T7 or T8, and Smithers made no merge call for either: each PR's `merged_by` is the owner's account, not the App.

## Fail when
- Merged shows before `main` contains the commit.
- GitHub closes `#I` by a closing keyword at merge time, before Smithers' comment.
- Issue `#J` closes.
- Smithers calls the merge API again, or opens an out-of-order `mythical_stacks.attention` row for an in-order merge.
