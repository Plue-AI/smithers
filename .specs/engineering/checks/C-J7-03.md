# C-J7-03 Conflict on rebase: the agent resolves once, else Needs you with Resolve

Proves: mvp.md J7.4, §4.2 Rebase, §4.1 Needs you · spec.md §4.1, §10.5.1, §10.5.3, §10.5.4, §10.8.1, §14.5.2 · Layer: integration · Stage: S1 · Tickets: T-STK-08, T-UI-04
Automation: `packages/backend/internal/services/todo_conflict_db_test.go` (new) · Runs in: CI (real PostgreSQL, real git and jj, the fake GitHub REST server, a scripted coding agent inside the `todo` run)

## Setup
- Product schema at head; owner Will; stack with T1 merged and T2 `working` with a verified candidate that changes lines 10-14 of `src/retry.ts`.
- `conflictAttempts` = 1 (the default, in `flow_config`).
- The scripted agent records every resolution attempt and, per case, either writes a clean resolution or fails.

## Steps
1. Push a commit to `main` on the fake server that changes lines 10-14 of `src/retry.ts` differently. Run engine passes.
2. Case A (the agent resolves): read the attempts, state and events until T2 is verified.
3. Case B (the agent fails): read the attempts and state; run 10 more engine passes.
4. Case B: Will presses **Done** on the `conflict` wait while `src/retry.ts` still has conflict markers.
5. Case B: resolve the file cleanly in the item change and press **Done** again.

## Pass when
- Case A: exactly one resolution attempt, inside T2's run, whose first message names `src/retry.ts` and the `onto` commit; T2 never enters `needs_you`; a `rebased` event and activity entry "Rebased onto main" follow; any earlier `todo_approvals` row for T2 is deleted; a check run is admitted for the new head.
- Case B: exactly one resolution attempt, then `needs_you{kind: conflict, paths: ["src/retry.ts"]}` with action Resolve, whose model opens the TODO card's conflict view in S1 (§10.5.4); zero further attempts over 10 passes; `mythical_items.state` never takes `retrying` or `blocked` for this conflict.
- Step 4: refused with `409 still_conflicted`; the wait stays open.
- Step 5: accepted; T2 returns to `working` and check runs.

## Fail when
- Two or more agent attempts on one conflict (today's 3-attempt loop, `mythical_items.go:1840-1847`).
- The TODO shows `failed` or `blocked` instead of Needs you.
- Needs you is raised without the conflicted paths, or before the agent's attempt finished.
- **Done** settles the wait while conflicts remain.
