# C-J5-01 Flow edit from chat becomes Active after merge; running TODOs keep their version

Proves: mvp.md J5.1–J5.4, §6.12 Change the factory and Pinned versions, M-04, M-11 · spec.md §4.1, §4.3, §10.4.1, §10.4.1a, §11.3, §11.4, §11.5 · Layer: e2e · Stage: S1 · Tickets: T-FLW-03..05, T-FLW-11, T-APP-05, T-UI-10
Automation: `apps/app/e2e/real/flow-edit.spec.ts` (new) · Runs in: reference host

## Setup
- Install at the commit under test; owner Will and maintainer Ben signed in on two browsers; capacity 3 on the detected host.
- Scratch repository `smithers-mvp-canary/<date>` with `package.json` scripts `test` and `lint`, a `CHANGELOG.md`, and no `flows/` directory. The built-in `todo` composition is Active at digest D1.
- TODO A placed and working, with a step that asks a question and waits (seeded prompt: "Ask me which file to edit before editing").

## Steps
1. Record A's pinned digest from the TODO card.
2. In chat: "Every TODO must run `pnpm test` and update the changelog." Wait for the Flow card's proposed diff.
3. Select **Make TODO** on the Flow card, creating TODO B. Wait for B to reach In review.
4. Read B's PR files and B's pinned digest.
5. Ben merges B from the TODO card.
6. Poll the `todo` Flow card every 2 s until Active changes; record each state and its time.
7. Create TODO C. Wait for its first check step.
8. Answer A's question. Let A fail its check once (seeded), then Retry it.

## Pass when
- Step 2 shows a diff on the Flow card that creates `flows/todo/flow.ts` as the composition plus the change (§10.4.1a), before any TODO exists.
- B's PR adds `flows/todo/flow.ts`, and B's pinned digest is D1.
- After the merge the Flow card shows "Merged · active after sync", then Active with digest D2 ≠ D1. Active never appears before the `flow_versions` row for D2 is `loaded`.
- C pins D2 when it enters Starting, and its evidence shows a changelog step and `pnpm test`.
- A's continued run and its retry attempt both pin D1, and A's evidence shows no changelog step.
- Every state above appears on the Flow card within 1 s of its projection event.

## Fail when
- B runs its own edit (B's digest is D2): the edit applied to itself.
- Active shows at merge time, before the load finishes.
- A or its retry switches to D2 after activation.
- The edit is committed straight to `main` without a TODO and a person's merge.
