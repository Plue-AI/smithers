- Joint release gate: T-FLW-11's packaged built-in todo digest and review/dependency resolver seam plus real T-FLW-03/04 loading and activation. Injected D1/D2 fixtures prove pin restoration only; they do not satisfy this e2e check.
- Seed an additional non-proposing override canary, with host watchdog clock and step counters controlled by test fixtures. Run it after its real activation; include a non-yielding case on the guest.
- Install at the commit under test; owner Will and maintainer Ben signed in on two browsers; capacity 3 on the detected host.

- TODO A placed and working, with a step that asks a question and waits (seeded prompt: "Ask me which file to edit before editing").

## Steps
- FLW11 QA G17 (I20–I23): while A waits, edit an imported helper, review instructions and lockfile on A's branch, then rebase/Resume/Retry. Record loaded closure module bytes and dependency environment digest as well as the flow digest. Retry-current is a separate control that pins the Active version.
- FLW11 QA G06: activate the no-proposing canary through the same merge/load path. Exercise early success, yielding loop and non-yielding guest at 4 hours or 1,024 completed steps before first acceptance; repository configuration attempts to disable the watchdog must have no effect. Restore the ordinary flow through a person-merged TODO.
1. Record A's pinned digest from the TODO card.
2. In chat: "Every TODO must run `pnpm test` and update the changelog." Wait for the Flow card's proposed diff.
3. Select **Make TODO** on the Flow card, creating TODO B. Wait for B to reach In review.
4. Read B's PR files and B's pinned digest.
5. Ben merges B from the TODO card.
6. Poll the `todo` Flow card every 2 s until Active changes; record each state and its time.
7. Create TODO C. Wait for its first check step.
8. Answer A's question. A's seeded work adds a dev dependency (`pnpm add -D left-pad`), which changes `pnpm-lock.yaml` on A's branch. Let A fail its check once (seeded), then Retry it.

## Pass when
- A's Resume/ordinary Retry loads the immutable D1 closure, imported review and dependency environment, regardless of helper/config/AGENTS.md/lockfile edits or rebase; no mutable working-copy resolver stub is used. New C pins real Active D2, and Retry-current creates a new immutable attempt at D2. Each attempt has exactly one TODO run.
- Real no-proposing override fails no_proposal/factory/retryable true at either approved boundary or early success, without GitHub writes; idle waits accrue no active time, host restart retains counters, and non-yielding repository code cannot disable the host timer. Retain cycle times for the first 20 dogfood TODOs on T-FLW-11's issue; the approved bound remains 4 hours/1,024 steps.
- Activation acceptance stays pending until the real loader/activation and this journey pass jointly; immutable injected fixtures alone cannot mark it passed.
- Step 2 shows a diff on the Flow card that creates `flows/todo/flow.ts` as the composition plus the change (§10.4.1a), before any TODO exists.
- B's PR adds `flows/todo/flow.ts`, and B's pinned digest is D1.
- After the merge the Flow card shows "Merged · active after sync", then Active with digest D2 ≠ D1. Active never appears before the `workflow_definitions` row for D2 is `loaded`.
- C pins D2 when it enters Starting, and its evidence shows a changelog step and `pnpm test`.
- A's continued run and its retry attempt both pin D1, and A's evidence shows no changelog step. A's Resume restores D1 by digest via ExecutionSnapshot, and its retry reloads D1 by digest from its pinned source commit; neither stores or reads a closure blob (§11.3.0), and neither fails `lockfile_changed` (§11.4.1).
- Every state above appears on the Flow card within 1 s of its projection event.

## Fail when
- Review/import/dependency bytes load from agent-written files, Resume/ordinary Retry changes the pin, a phase starts another TODO run, or injected fixtures are reported as real Active-main acceptance.
- The activated override returns success or runs past the watchdog without an accepted proposal, or repository code disables the host counter/timer.
- B runs its own edit (B's digest is D2): the edit applied to itself.
- Active shows at merge time, before the load finishes.
- A or its retry switches to D2 after activation.
- A's retry fails to restore D1 because A's branch changed the lockfile.
- The edit is committed straight to `main` without a TODO and a person's merge.
