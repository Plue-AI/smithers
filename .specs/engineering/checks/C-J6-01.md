# C-J6-01 Terminal sign-in: S1 scoped token and S2 full delegation

Proves: mvp.md J6.1–J6.3, M-21, M-34 · spec.md §5.2.1, §5.3.2, §8.11.1, §14.6a · Layer: e2e · Stage: S1 · Tickets: T-TRM-02, T-APP-09, T-REL-02
Automation: `apps/app/e2e/real/terminal-signin.spec.ts` · Runs in: reference host

## Setup
- Real install and branch machine at the commit under test; catalog-generated skill; Ben is a maintainer. T1 has an open question, and T2 is already later in the stack.
- Ben signs Claude Code in with his own model access. Record which stage is running. The S1 scenario gates T-TRM-02’s S1 phase; the S2 scenario gates its S2 phase after T-MCH-11, T-TRM-01 and T-ACC-05.

## Steps
1. S1: open Ben’s terminal; inspect token path, owner and mode, run `smthrs whoami`, and inspect skill discovery.
2. Through Claude Code’s Smithers skill, read the wiki, answer T1, steer T1, and commit a TODO with Append.
3. Request placement directly after T1, drop, move, merge, confirmation creation, steering T2, secrets write and members change.
4. Close the terminal and reuse its token.
5. S2: open a fresh terminal as Ben’s uid; repeat identity, skill, wiki and answer checks. Through Claude Code request a TODO directly after T1; Ben approves its one-click confirmation.
6. Put T1 first and In review with required checks passed. Claude Code requests merge; Ben opens Review & merge and cancels it. Alice and `agent` try reading Ben’s token.
7. Close the S2 terminal and reuse its token. Inspect S2 presence and activity while the agent works.

## Pass when
- S1 uses `/run/smithers/sessions/<session id>/token`, mode 0600, uid 1500; S2 uses `/run/smithers/<uid>/token`, mode 0600, Ben’s uid. Identity reports Ben and terminal delegation; the skill needs no manual installation.
- S1 allowed calls succeed, append the new TODO after T2, and create no confirmation. Every out-of-scope call returns 403 `permission`, creates no confirmation and makes no mutation (C-SEC-05).
- S2 after-placement returns 202 with a confirmation id, creates no TODO before Ben presses, then creates exactly one TODO directly after T1. Merge returns 202 with a `review_merge` id; Ben’s browser shows the exact reviewed SHA, and cancel makes no merge call.
- S2 Alice and `agent` receive EACCES reading Ben’s token. Both stage tokens return 401 within 5 s of close.
- Agent-authored actions identify the Claude Code participant acting for Ben. S2 presence shows its own avatar and "Claude Code for Ben"; activity shows that same actor on its TODO action. The coding agent has a separate participant avatar.

## Fail when
- S1 after-placement or confirmation succeeds, or an agent merges without the person’s session.
- An agent action loses its participant identity, the skill asks for login, or a closed token remains valid.

`.artifacts/checks/C-J6-01/<UTC>/`: stage, redacted terminal transcript, request statuses and bodies, confirmation rows, TODO placement and activity JSON, S2 presence deltas and Review & merge trace, install version and commit. Record S1 and S2 results separately.
