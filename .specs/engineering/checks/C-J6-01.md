# C-J6-01 Claude Code in a branch terminal is signed in with the skill; actions show "Ben via Claude Code"

Proves: mvp.md J6.1–J6.3, §6.13 CLI and Attribution, M-21 · spec.md §5.3, §5.3.2, §5.4, §6.4, §8.11.1, §14.6a, §15.3 · Layer: e2e · Stage: S1 · Tickets: T-TRM-02, T-APP-09, T-UI-01
Automation: `apps/app/e2e/real/terminal-signin.spec.ts` (new) · Runs in: reference host

## Setup

- A fresh install on the reference host at the commit under test, wrapping `smithers-mvp-canary/<date>`. The Smithers skill is generated from the catalog (T-CAT-02). Steps 1–6 run in S1, where terminals use `msb exec -t` as the guest's single user (§8.11.1). Step 7 and the per-uid token path rerun once S2 lands.
- Ben (maintainer) in a browser at the install's public origin. TODO T1 in Needs you with question Q.
- Ben has his own Anthropic credential for Claude Code, entered by him in the terminal (his subscription or key, never the install's model access).

## Steps

1. Ben opens a terminal on T1's branch. He runs `printenv SMITHERS_TOKEN_FILE SMITHERS_URL`, `stat -c '%U %a' "$SMITHERS_TOKEN_FILE"` and `smthrs whoami`.
2. He lists the skill directory Claude Code reads in his home and confirms the Smithers skill is there.
3. He runs `claude -p "Using the Smithers skill: read the wiki page 'retries', answer TODO T1's question with 'use the retry helper', and place a TODO after T1 titled 'Add jitter'."`
4. Read T1's activity, the new TODO's `created_by_actor`, and the home card in Ben's browser.
5. In the same terminal: `smthrs merge T1`.
6. Ben closes the terminal. Run `smthrs whoami` with the old token file contents through `SMITHERS_TOKEN`.
7. S2 only: Alice opens her own terminal on the branch and runs `cat /run/smithers/<Ben's uid>/token`.

## Pass when

- Step 1: both variables are set; the file is owned by the session's user with mode `600` (S1: the guest's single user; S2: `/run/smithers/<uid>/token` owned by Ben's uid); `whoami` reports Ben with `via: terminal`.
- Step 2: the skill is present with no manual install step.
- Step 4: T1's answer and the new TODO both show "Ben via Claude Code" (`{person: Ben, via: "claude-code"}`, §14.6a), and the new TODO is placed directly after T1.
- Step 5: no merge happens. A person confirmation is created, and Ben's browser shows the Confirm card.
- Step 6: the credential is refused with 401 within 5 s of the close.
- Step 7 (S2): permission denied.

## Fail when

- `smthrs` asks for a login, or falls back to another identity.
- Actions are attributed as "Ben" with no agent, or as "Agent".
- The delegated credential merges or approves.
- The token stays valid after the terminal closes.
