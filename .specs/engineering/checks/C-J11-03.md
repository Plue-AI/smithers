# C-J11-03 The owner switches a factory agent's model on the Agent card

Proves: mvp.md J11.4, §6.5 Models, §6.14 Configure an agent, M-23 · spec.md §3 (`flow_config`), §5.2 (install settings), §6.1.2, §6.3 `/api/agents`, §11.5a, §15.1.4, §15.2 · Layer: e2e · Stage: S1 · Tickets: T-FLW-08
Automation: `apps/app/e2e/real/agents.spec.ts` (extend) · Runs in: reference host

## Setup
- Install at the commit under test. Model access: a coding provider with a default model A and a cheaper model B, a fast-model key with model F, and the AI Gateway key. Settings roles: `fast` = F, `coding` = A, `jev` set.
- Will (owner), Ben (maintainer) and Alice (member) signed in on separate browsers; Alice also holds a `delegated` credential from `smthrs login <install origin> --agent claude-code`.
- Scratch repository `smithers-mvp-canary/<date>` with no `.smithers/` files.
- TODO X admitted and working before any change.

## Steps
1. Will runs `/agents`. Read the Agent card, then the Settings card's model roles.
2. Will asks the app agent a question. Read the turn's model.
3. On the Agent card, Will opens the reviewer and switches it to model B. Record t_s.
4. Read `flow_config` for the reviewer, the TODO list, and the reviewer's model on the card.
5. Let X reach its review step. Read the review run's model.
6. Create TODO Y right after t_s and let it reach its review step. Read the review run's model.
7. Will removes the fast-model key in Settings and asks the app agent again. Read the turn's model.
8. Open the app agent's instructions link. Will asks the app agent to "always end answers with the word DONE".
9. Will commits the resulting TODO, merges it, and waits for its activation. Then asks the app agent a question.
10. Alice opens the Agent card. Alice's session and her delegated credential each call `PUT /api/agents/reviewer/model`.
11. Read `/help`, the palette and the app agent's tool list.

## Pass when
- Step 1: the card lists planner, implementer, reviewer and app agent, each with its current model (planner, implementer and reviewer A, app agent F), a link that opens its instructions in the File card, and its recent runs. Settings shows `fast`, `coding` and `jev`.
- Step 2: the turn records F. Step 7: the turn records A, the coding-model fallback (§11.5a).
- Steps 3-4: the change applies at once: the reviewer's `flow_config` row holds B with source `owner`, the card shows B, and no TODO, merge or restart was needed.
- Step 5: X's review records A, since X was admitted before t_s. Step 6: Y's review records B.
- Step 8: the link opens `.smithers/instructions/app.md` (the built-in text, since the repository has none). The agent doesn't change its behavior; it proposes a TODO that edits that file, posted as a one-click confirmation (`agent: confirm`).
- Step 9: before the merge activates, answers don't end with DONE; after it, the next answer does.
- Step 10: Alice sees models but no model picker, and both calls return 403 with class `permission`.
- Step 11: no `model.compose`, `model.ask` or other composer command appears anywhere; the restored `model.*` commands are absent from `/help`, and their writes from the agent's tool list.

## Fail when
- A model change creates a TODO, waits for a merge, or misses a run admitted after it.
- A run admitted before the change switches models mid-run.
- An instructions change takes effect without a merged TODO, or the app agent edits its own instructions directly.
- A member or an agent credential changes a model.
- The Agent card shows a model the run didn't use.
- Any model laboratory surface (composer, ask, fixture) is reachable.
