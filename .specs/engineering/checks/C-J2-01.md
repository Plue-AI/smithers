# C-J2-01 Make TODO from an issue: drafted, edited, placed, committed; issue labeled and commented

Proves: mvp.md J2.2, §6.3 (Make TODO row), §6.6 Create, M-16, M-22 · spec.md §6.1.4, §10.2.1, §10.2.2, §12.4.1, §14.5.1 · Layer: e2e · Stage: S1 · Tickets: T-STK-09, T-APP-02
Automation: `apps/app/e2e/real/todo-from-issue.spec.ts` (new) · Runs in: reference host

## Setup
- Install built from the commit under test on the reference host; record the `smthrs host status` version and the commit.
- Scratch repository `smithers-mvp-canary/<date>` with the install's GitHub App; a stack with T1 and T2 `queued`.
- Members: owner Will; Ben (Member). Issue #7 opened by Ben on GitHub with body "Webhooks fail on 502" and three comments; comment 2 alone contains "retry at most 5 times with jittered backoff".
- Browsers on a second Mac on the same network at the install's public origin: Ben, and Will in `main`'s conversation.

## Steps
1. Ben opens `/issue 7` and selects **Make TODO**.
2. Read the Draft card in Ben's browser and in Will's: title, prompt, acceptance, fixes toggle, place.
3. Ben edits the prompt (appends "Log each retry."), sets place **Before T2**, keeps fixes on, and commits.
4. Read the Home card, the TODO card and GitHub issue #7 (labels, comments).
5. Wait one full issues-poll interval plus 30 s (§12.2) and read the stack again.
6. Ben commits Make TODO on #7 again with the same draft (double click, same `Idempotency-Key`).

## Pass when
- Step 2: Ben sees the Draft card and Will doesn't (a private entry until committed, §14.5.1); no GitHub write has happened; the prompt or acceptance contains the comment-2 requirement.
- Step 4: one new TODO T3 placed between T1 and T2 (Home order T1, T3, T2); revision 1 has reason `from-issue`, the edited text and an `issue_digest`; `fixes_issue = true`; actor "Ben".
- Step 4: issue #7 has the label `todo` applied by the App and exactly one comment "Committed as T3 ↗" linking the TODO.
- Step 5: the App's own label event created no second TODO and no new revision.
- Step 6: still one TODO, one label application and one comment.

## Fail when
- The TODO is created before Ben commits (a draft written to GitHub or the stack), or another member sees the uncommitted draft.
- The prompt is the raw issue body without the discussion, or the edit is lost.
- A GitHub issue is created for the TODO (today's `FileTodo` behavior).
- Two comments, or a second TODO from the App's label or the double commit.
