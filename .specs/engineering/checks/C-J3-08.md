# C-J3-08 File deleted or renamed while open

Proves: mvp.md §6.8 External changes ("Deleted by Maya via SSH · Restore", "Renamed to `deliver.ts` · Follow"), M-27 · spec.md §9.2 (S2 intro), §9.2.6, §9.3.4, §14.3 (File gone state) · Layer: e2e · Stage: S2 · Tickets: T-APP-11
Automation: `apps/app/e2e/real/file-gone.spec.ts` (new) · Runs in: reference host

## Setup

- A fresh install at the commit under test. The scratch repository is `smithers-mvp-canary/<date>` with `src/retry.ts` and `src/webhook.ts`.
- Members: Ben signed in from a second Mac at the install's public origin, and Maya with SSH. Branch `smithers/retry-webhooks` is awake.
- Ben has `/file src/retry.ts` and `/file src/webhook.ts` open, plus the Branch card.
- Steps 1–5 gate stage 2. Step 6 is a rerun once T-COL-08 lands in stage 3, recorded in the same evidence directory.

## Steps

1. Maya runs `rm src/retry.ts` over SSH.
2. Ben selects **Restore** on the `retry.ts` card.
3. Maya runs `git mv src/webhook.ts src/deliver.ts`.
4. Ben selects **Follow** on the `webhook.ts` card.
5. Maya saves `src/deliver.ts` from an editor that writes a temp file and renames it over the target.
6. Stage 3 rerun, after T-COL-08: repeat steps 1–4 while Ben and Alice both have the live document open, with Alice typing.

## Pass when

- After step 1, within 1 s of the delete, the `retry.ts` card shows "Deleted by Maya via SSH" with **Restore**, and its text stays visible and read-only.
- After step 2, `src/retry.ts` on the machine byte-equals the text the card showed before the delete. That is the content in the deleting burst's `snapshot_before` (§9.2.6, §9.3.4), since the file had no other write in that burst. One activity entry is attributed to Ben, and the card returns to its normal state.
- After step 3, within 1 s, the `webhook.ts` card shows "Renamed to `deliver.ts`" by Maya via SSH, with **Follow**.
- After step 4, the card shows `src/deliver.ts` with its current text.
- Step 5 updates the `deliver.ts` card's text. It does not produce a renamed or deleted state.
- Each of Maya's actions produces one activity entry, never one per event.
- Stage 3 (step 6): the delete pauses editing in both pages. Restore rewrites the last document text, including Alice's last characters (§9.2.6), and Follow reopens the live document at the new path for both editors.

## Fail when

- A deleted file shows an empty editor, an error card or a "file not found" toast instead of the gone state.
- Restore brings back content older than what the card showed. In stage 3, that means a restore that drops Alice's last characters.
- An atomic save (step 5) shows as "Renamed" or "Deleted".
- Follow opens a new card while the old one stays stale, or loses the card's place in the conversation.
