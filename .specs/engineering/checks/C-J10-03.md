# C-J10-03 A push from a laptop to a TODO branch holds the agent's push; Bring in and Discard both work

Proves: mvp.md J10.3, §6.3 "Someone pushes to a TODO's branch from a laptop", M-33 · spec.md §4.1 (`in_review → needs_you`, `needs_you → working`, `needs_you → in_review`), §10.8.1, §10.8.2, §10.8.3, §12.3 (push row), §12.5.2 · Layer: e2e · Stage: S1 · Tickets: T-GH-06
Automation: `apps/app/e2e/real/github-j10/foreign-push.spec.ts` (new) · Runs in: reference host

## Setup
- Reference host, install at the commit under test, App installed on a fresh `smithers-mvp-canary/<date>`.
- Members: the owner (browser on a second Mac) and Alice (Member) with a git clone on a laptop, her own GitHub credentials and her own browser.
- T4, owned by the owner, In review on `smithers/retry-webhooks` with its PR open. Record its PR head sha `H0` and the item's diff.

## Steps
1. On the laptop: fetch `smithers/retry-webhooks`, commit a one-line change, and push it to the same branch. Record t0 and the commit sha `A1`.
2. Watch the Home card and T4's TODO card. Steer T4 ("add a log line on each retry") and sample `git ls-remote` every 2 s for 10 min.
3. As the owner, select **Bring in** on the Needs you. Wait for T4's next verified push and for T4 to return to In review.
4. Steer T4 again ("also log the attempt number"). While T4 is Working, Alice pushes a second commit `A2` the same way. Record t1.
5. Keep sampling `git ls-remote` until T4's run produces its next verified candidate, then 5 min more.
6. Alice selects **Discard** in her browser. Then the owner selects **Discard**. Wait for T4's next verified push.
7. Read T4's branch activity and the host repository store's `refs/smithers/kept/`.

## Pass when
- Within 60 s of t0, T4 shows Needs you reading "Alice pushed to `smithers/retry-webhooks` on GitHub" with a link to `A1`, offering **Bring in** and **Discard**, and the owner gets a toast.
- Step 2: the GitHub branch head stays `A1` for the whole 10 min; Smithers pushes nothing while the Needs you is open.
- Step 3: T4 goes to Working; its next verified head descends from `A1`, the item's diff contains Alice's line, an activity entry attributes it to Alice, and the PR number is unchanged.
- Within 60 s of t1, T4 shows a Needs you naming `A2`, although T4 was Working (§12.3, M-33).
- Step 5: the GitHub branch head stays `A2`; the verified candidate the run produced is held, not pushed.
- Step 6: Alice's Discard is refused (maintainers only, Appendix B.4). After the owner's, the next verified push replaces `A2` on GitHub, leased against `A2`; `A2` isn't an ancestor of the new head.
- Step 7: `refs/smithers/kept/<A2>` exists, and an activity entry links it.

## Fail when
- Smithers pushes over a person's commit before a person chooses (M-33), in review or while working.
- **Bring in** loses Alice's change, or attributes it to the agent.
- **Discard** deletes `A2` from every ref, happens without a person's choice, or is accepted from a member.
- The Needs you names Smithers or the App as the pusher.
