# C-J10-02 A GitHub review comment becomes a steer within 60 s and the agent's fix updates the PR

Proves: mvp.md J10.2, §6.3 "A review or review comment on a TODO's PR", §6.10 "Line comments" · spec.md §3 (`activity`), §4.1 (`in_review → working`), §10.4.1, §10.7.3, §12.3 (review rows), §12.5.3, §14.6a, §17.5 · Layer: e2e · Stage: S1 · Tickets: T-GH-04
Automation: `apps/app/e2e/real/github-j10/review-steer.spec.ts` (new) · Runs in: reference host

## Setup
- The T-GH-04 `github_inbound_reviews_integration_test.go` supplies the production poll/webhook, transaction crash and current-membership/held-delivery assertions before the browser journey.

- Reference host, install at the commit under test, App installed on a fresh `smithers-mvp-canary/<date>`. The App's webhook is inactive.
- Members: the owner, Ben (Maintainer, browser on a second Mac) and Alice (Member, with a GitHub token for the harness). Dana, a GitHub user with read access who isn't a member, also has a token.
- T3 In review; its PR changes `src/retry.ts`, including a hand-rolled delay loop at line N.

## Steps

- Decode GitHub authors with kind:"github", login and color_index 7. Decode member 0–5, undelegated agent 6 and outside 7 fixtures; reject indices outside 0–7. Retain no-steer assertions for outsiders and removed or suspended members.
- Adopted T-GH-04 boundary cases: Send reviews through production webhook hints/poll consumers with real PostgreSQL and the real durable signal receiver. Crash before transaction commit and after commit before dispatch; assert all-or-none rows and one recovered steer. Repeat held review delivery after author removal/suspension and include outsider authors: retain allowed activity attribution but no signal, TODO transition or authority from historical roster/login

1. As Alice, submit a review with "Request changes" and one line comment on `src/retry.ts` line N: "Use the existing backoff helper". Record t0 when GitHub returns 2xx (reference host clock).
2. Watch T3's TODO card and branch activity in Ben's browser. Record t1, the time of the `todo:3` delta that shows the steer.
3. Wait up to 30 min for T3 to return to In review.
4. Restart the host. Wait 2 min.
5. As Dana, add a conversation comment on T3's PR. Wait 2 min.
6. As the owner, submit an "Approve" review on T3's PR.

## Pass when

- The adopted owner contract passes: Decode GitHub authors with kind:"github", login and color_index 7. Decode member 0–5, undelegated agent 6 and outside 7 fixtures; reject indices outside 0–7. Retain no-steer assertions for outsiders and removed or suspended members.
- Use one transaction for activity, delivery key, TODO transition/events and durable steer signal intent. Supply a transaction-aware signal admission API; a separately committed dispatcher Admit call does not join the transaction. Dispatch only after commit and recover pending intents idempotently. Resolve the GitHub author to a current active member at steer admission and again before held delivery; removed, suspended and outsider authors have record-only activity and no effective steer

- t1 − t0 ≤ 60 s.
- The steer shows Alice's avatar, the GitHub mark and the anchor `src/retry.ts:N` in the branch activity; T3 reads Working; `todo_events` has one row for it with Alice's actor.
- By step 3, T3's PR head is a new commit whose diff in `src/retry.ts` calls the backoff helper, the PR number is unchanged, and T3 is In review.
- After step 4, there is still exactly one steer and one event for Alice's review.
- After step 5, the activity shows "@dana" with the GitHub mark, T3's state doesn't change, and the run receives no steer (§17.5).
- After step 6, the PR card lists the owner's approval, T3's state doesn't change, and no `todo_approvals` row is written.

## Fail when
- The steer is attributed to "Agent", "Smithers" or the App.
- One review produces two steers, before or after the restart.
- Working shows before the steer's event exists.
- A comment posted by the install's own App, or by a non-member, reaches the run as a steer.
- The agent replies inside the GitHub review thread (deferred) instead of pushing commits.
