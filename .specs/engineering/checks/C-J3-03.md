# C-J3-03 Outside change: one entry by user, diff, live cards, agent re-reads

Proves: mvp.md J3.4, §6.8 External changes and Live updates, M-27 · spec.md §7.2 (`:activity`, `:files`), §7.6 (row 1), §8.4.4, §9.3.2–9.3.4, §9.3.9, §18 · Layer: e2e · Stage: S2 · Tickets: T-COL-04, T-COL-07, T-APP-10
Automation: `apps/app/e2e/real/branch-outside-change.spec.ts` (new) · Runs in: reference host

## Setup

- A fresh install at the commit under test. The scratch repository is `smithers-mvp-canary/<date>` with 12 TypeScript files under `src/` that `pnpm format` (Prettier) rewrites, `retry.ts` and `deliver.ts` among them, and `node_modules/` gitignored.
- Members: Ben (owner) in a browser on a second Mac at the install's public origin, with no terminal open; Maya (member) over SSH.
- TODO T2 is `needs_you{question}`: the run trace shows `retry.ts` read in `implement`, and the agent's terminal runs no command.
- Ben has the Branch card and `/file retry.ts` open.

## Steps

1. Maya runs `pnpm format` over SSH. Hers is the only active session.
2. Ben selects the new activity entry, then presses **Restore this file** on `retry.ts`.
3. Maya edits `deliver.ts` over SSH. Ben presses **Restore this file** on `deliver.ts` in the step 1 entry.
4. Maya runs `pnpm install` (writes only under `node_modules/`).
5. Ben opens a terminal on the branch and runs a busy loop (`while :; do :; done`) while Maya edits `src/a.ts` over SSH and saves. Ben stops the loop and closes the terminal.
6. Ben answers T2's question. Wait for the agent's next turn that writes `retry.ts`.

## Pass when

- Step 1: exactly one new entry reads "Maya via SSH changed 12 files", with the SSH mark. Its burst closed 1.5 s ± 0.3 s after the last write (§9.3.4), and it reached Ben ≤ 1 s after the host committed the row (§7.2.1). Ben's File card shows the new `retry.ts` text and last writer "Maya via SSH" within 1 s of her write, with no reload pressed.
- Step 2: the diff is between the burst's `snapshot_before` and `snapshot_after` and lists exactly the 12 files. After Restore, `retry.ts` byte-equals its `snapshot_before` content, a new entry is attributed to Ben (§9.3.5), and Ben's File card shows the restored text within 1 s.
- Step 3: nothing is written to `deliver.ts`; Compare opens with the step 1 version beside the current file.
- Step 4: no activity entry and no file on `branch:<id>:files`.
- Step 5: the entry reads "changed outside Smithers", never "Maya via SSH" or "Ben's terminal" (two active sessions, §9.3.1).
- Step 6: the run trace shows a system note naming Maya and the changed files before the agent's next tool call. Its next write to `retry.ts` follows a read made after the note, or its first attempt fails with `stale_read` and a read follows.
- The host repository store holds every entry's snapshot commits (`refs/smithers/branches/<id>/snapshots/<burst>`), so each diff opens without the machine (§8.4.4).

## Fail when

- Twelve entries, one per file, or step 1 attributed to "Agent", "system" or the host user.
- Step 5 is attributed to one person.
- Restore overwrites a file that changed after its burst, or its write is attributed to Maya or Smithers.
- An entry shows a command name ("ran pnpm format"), an Undo button or a "replaced" flag. All three are [D] (§9.3.5–9.3.7), even though the design mock shows them.
- The File card shows new text only after a manual refresh, or a stale last writer.
- `node_modules/` paths appear as edits, or the agent writes `retry.ts` from content it read before Maya's change.
