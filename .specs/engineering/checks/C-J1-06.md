# C-J1-06 A repository with no Smithers files gets a working machine and checks

Proves: mvp.md J1.4, §6.1 Machine image without declarations, §6.12 Default flows, M-11 · spec.md §3 (`flow_config`), §8.6, §11.2, §13.5 · Layer: e2e · Stage: S1 · Tickets: T-MCH-10, T-FLW-02
Automation: `apps/app/e2e/real/fresh-repository.spec.ts` (new) · Runs in: reference host

## Setup
- Fresh install at the commit under test; setup completed through model access; owner signed in from a second Mac at the install's LAN origin.
- Scratch repository `smithers-mvp-canary/<date>-node`: `.node-version` (`22`), `package.json` with `packageManager: pnpm@9`, scripts `test` (vitest) and `lint` (eslint), `pnpm-lock.yaml`, one source file and one test. No `.smithers/`, no `flows/`.
- Second scratch repository `smithers-mvp-canary/<date>-go`: `go.mod` with a `go` directive, one package and one `_test.go`. No `.smithers/`, no `flows/`.

## Steps
1. Connect the Node repository. Wait for Source ready, then Machine ready on the Setup card.
2. Read the stored configuration: `GET /api/flows` and the `flow_config` rows in PostgreSQL.
3. Create a TODO: "Add a `sum(a, b)` export with a test".
4. Wait for In review. Open the TODO card's evidence and the PR on GitHub.
5. List commits on the TODO branch and on `main`.
6. Repeat steps 1–4 with the Go repository.

## Pass when
- Source ready appears before Machine ready, and both appear without a manual step.
- The stored checks for the Node repository are exactly `pnpm test` and `pnpm lint`, in that order; for Go, exactly `go test ./...`.
- The TODO's evidence lists each stored check with its outcome, duration and log, run on the machine.
- The PR opens on `smithers/<slug>` based on `main`.
- No commit on any branch adds or changes a path under `.smithers/` or `flows/`.
- The stored seats are `auto` for every role, and the stored wiki declaration lists an overview, an architecture page and one page per top-level package directory, at most 10 (§11.2).

## Fail when
- Setup or the TODO asks the user to commit `.smithers/coding-project.json` or a target index.
- Planning refuses the Go repository's single check (the minimum is one, §11.2).
- A check runs with the wrong package manager (`npm test` in a pnpm repository).
- The configuration shows in the repository instead of PostgreSQL, or a check result shows before its run event.
