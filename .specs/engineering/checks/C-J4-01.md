# C-J4-01 Home card counts, filters, merged since last look, sync time, machines vs capacity

Proves: mvp.md J4.1, §6.4 Home card · spec.md §14.3 (Home), §14.5.2, §4.1, §7.2, §4.4, §8.2.1, §10.6.1, §12.6, §19.3 · Layer: e2e · Stage: S1, S2 · Tickets: T-APP-01, T-REL-02
Automation: `apps/app/e2e/real/home.spec.ts` (new) · Runs in: reference host

## Setup
- Install at the commit under test. Record the detected host profile and the capacity C it derives (§8.2.1); `parallel` = C.
- Scratch repository `smithers-mvp-canary/<date>`. Its `main` holds a test `flows/todo/flow.ts`, Active, whose behavior the TODO prompt selects and which calls no model: `ASK` raises a question, `HOLD` waits on a signal, `PR` opens a PR at once, `FAIL` fails at check.
- Members: Maya (owner), Ben (maintainer), Alice (member), each in their own browser.
- Seeded TODOs so that Needs you, Starting, Working, Queued and In review each hold at least one item, and at least two items are In review. A `starting` item is held by a test hook between admission and its first step.
- Background runs: one finished wiki refresh and two failed `flow-load` runs, F1 and F2.

## Steps
1. Maya opens `main`'s conversation. Record the Home card and, at the snapshot's cursor, `SELECT state, count(*) FROM mythical_items WHERE merged_at IS NULL AND dropped_at IS NULL GROUP BY state` and the stack order.
2. Ben and Alice open the same card. Record theirs.
3. Maya selects the Needs you filter, then reloads.
4. As Alice, answer one Needs you item through the API. Record the commit time and each browser's render time of the new counts.
5. Maya closes the app. Merge 3 items (2 from Smithers by Ben, 1 on GitHub). Maya reopens.
6. Compare the `main` row's "synced N s ago" with `now − last_success_at` of the refs poller's health (§12.2).
7. Compare S1 in_use/capacity against the workspace/admission facts and host profile used by T-COL-02's snapshot. In S2, compare against the machines table and exercise the owner-only parallel stepper after T-STK-03 lands.
8. Record which rows offer which action for each member.
9. Compare the `home` snapshot payloads the three browsers received at the same cursor.
10. Ben presses **Retry** on F1. Alice presses **Dismiss** on F2. Reload all three browsers.

## Pass when
- Counts and row order equal the SQL at the same cursor, for all three members.
- Maya's filter shows exactly the Needs you rows, survives the reload, and leaves Ben's and Alice's cards unfiltered.
- After step 4 every browser shows the new counts; render minus commit is recorded (C-PERF-02 gates it).
- Maya sees "3 merged since you looked"; Ben, whose Home card stayed on screen for 2 s after each merge, does not see 3 (§14.3). Both counts are derived in the browser from shared rows and each member's own `last_seen_seq` (§7.2.2).
- N is within 2 s of the age computed from `last_success_at`, and the row is not gold while N ≤ 120.
- S1: the machines row shows in_use/capacity equal to the workspace/admission facts and detected host capacity used by T-COL-02's snapshot.
- S2, after T-STK-03 lands: the row matches the machines table and capacity formula; only Maya sees and can use the parallel stepper.
- Exactly one Merge exists, on the first unmerged In review row, for Maya and Ben; Alice sees no action there (§14.5.2); every other row has at most one action.
- F1 and F2 stay listed with **Retry** and **Dismiss** after a reload.
- Step 9: the three snapshots are byte-identical; no member's filter, last look or role-specific attention rides on the shared topic.
- Step 10: Retry starts a new run of F1's flow that appears as running for all three members within 1 s; Dismiss removes F2 for all three, and it stays gone after the reload.

## Fail when
- A count includes merged or dropped items, or differs between members.
- One member's filter changes another's card.
- Merge appears on a later item, or for Alice.
- The card shows a state before its `product_job_events` row exists (§19.3), for example Starting before admission or Working before the first step.
- A failed background run disappears without a Retry or Dismiss, or Dismiss hides it for one member only.
