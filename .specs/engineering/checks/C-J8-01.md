# C-J8-01 Learning writes a decision page linked to the change

Proves: mvp.md J8.1, §6.12 Learning, M-15 · spec.md §11.8.1, §11.8.3, §4.1.3, §3.1 · Layer: integration · Stage: S3 · Tickets: T-FLW-06, T-REL-02
Automation: `packages/backend/internal/services/learning_integration_test.go` (new) · Runs in: CI

## Setup
- Real PostgreSQL 18 with migrations at head; the wiki store (`wiki_pages`, `wiki_page_revisions`, blob store); fake GitHub server; test process runtime for the background machine; Jev replaced by a recorded fixture.
- T7 merged as PR #41 (merge commit `<sha>`) with two attempts: attempt 1 failed check `lint`; attempt 2 passed. One steer from Ben: "use the existing retry helper, it already backs off". One GitHub review comment on PR #41.
- 19 earlier merged TODOs with recorded outcomes.

## Steps
1. Emit the `in_review → merged` event for T7.
2. Wait for the learning run to finish.
3. Read the wiki pages and revisions it wrote, `proposals`, T7's `mythical_items` lessons, `item_events` for T7 and the durable-stream cursors for `todo:7`, `home` and `proposals`.
4. Replay the learning run's success payload a second time.

## Pass when
- Exactly one learning run exists for T7, class `background`, and it is not a TODO.
- At least one decision page revision exists whose body links the change (PR #41 URL and the merge commit) and the run ids of both attempts, and states a reason taken from Ben's steer or the review comment.
- The revision's author is `{agent: "coding", run}` for the learning run.
- T7's `mythical_items` lessons equals the pages written plus the proposals created, and the `todo:7` delta carries it.
- `item_events` for T7 has no state change after `merged`.
- Step 4 writes no new revision, proposal or lessons change.

## Fail when
- The page links neither the PR nor the commit, or cites no run ids.
- The page restates the PR title with no reason.
- `lessons` is set before the page and proposal rows exist, or the delta arrives without them.
- A replay duplicates a page section or a proposal.
