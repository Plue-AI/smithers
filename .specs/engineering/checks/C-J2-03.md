# C-J2-03 Agent question becomes Needs you; the owner gets a toast; the first answer wins

Proves: mvp.md J2.4, J3.6, §4.1 Needs you, M-14 · spec.md §4.1, §10.7.2a, §10.8.1, §10.8.2, §10.8.3, §14.4, §14.5.2 · Layer: e2e · Stage: S1 · Tickets: T-STK-01
Automation: `apps/app/e2e/real/todo-needs-you.spec.ts` (new) · Runs in: reference host

The S1 run covers the owner's toast and the Home card. From S2 the same spec also asserts the toast for a member present on the branch (§10.8.3).

## Setup
- Install from the commit under test on the reference host; record version and commit.
- Scratch repository `smithers-mvp-canary/<date>`; the built-in `todo` flow Active.
- Members: owner Will, Ben (Maintainer), Alice (Member). Three browsers on a second Mac, one per member, each in `main`'s conversation.
- T1 created by Will: "Add a retry policy to webhook delivery. Before editing, ask me whether to use backoff or a fixed delay." The implementing agent raises the question through its `ask` tool (§10.7.2a).

## Steps
1. Wait for T1 to reach `needs_you{kind: question}`; record the time the runtime opened the wait.
2. In each browser, record toasts, the Home card's Needs you count and T1's row.
3. Ben and Alice submit different answers at the same instant (Playwright `Promise.all`, both with the wait id).
4. Read T1's TODO card in all three browsers, T1's `item_events` and branch activity, and the run transcript.
5. In the losing browser, select **Send as steer** on the kept draft.

## Pass when
- Step 1: the question comes from the implement step's `ask` call, and the TODO left `working` for `needs_you` on the same run.
- Step 2: Will (the TODO's owner) gets a toast with action Answer within 1 s of the wait's projection event; Ben and Alice get no toast in S1 and see Needs you +1 and T1's question on the Home card.
- No browser shows Needs you before the wait-opened event's timestamp.
- Step 3: exactly one answer commits; the other request returns `409 {answered_by}`; the losing browser shows "<winner> answered" and keeps its text with **Send as steer**.
- Step 4: one `answer` event and one activity entry with the winner's avatar; the run receives exactly one answer and returns to `working`; all three cards show the same first answer.
- Step 5: the late text arrives as a steer with its author.
- S2 run: a member present on T1's branch also gets the toast.

## Fail when
- Both answers reach the run, or the later answer overwrites the first.
- The toast settles or disappears before the TODO leaves Needs you.
- A member's chat is blocked while the question is pending.
- The agent asks only in its transcript and the TODO stays `working`.

If no question is raised within 15 minutes, the run is inconclusive, not a pass; T-STK-07's integration test also proves the race deterministically.
