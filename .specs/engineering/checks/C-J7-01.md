## Setup
- Install from the commit under test on the reference host; record version and commit.
- Scratch repository `smithers-mvp-canary/<date>` with the fixture `todo` flow of C-J4-02 merged and Active; `parallel = 2`.
- Member Ben signed in. Stack: T1 `in_review`, T2 `working` (its implement step blocks until released), T3 `queued`.
- Record the install's next TODO number N before the test (`GET /api/todos` maximum + 1).

## Steps
1. Ben runs `/todo.new` with the prompt "Add a jitter helper", place **Before T3**, and commits.
2. Read the Home card order and the new TODO's number.
3. Ben runs `/todo.amend T2`, adding "Also log each retry.", and commits.
4. Read T2's TODO card, the Home card, `mythical_items.revisions` for T2 and the next TODO number.
5. Read the steers T2's run recorded.
6. Release T2's implement step; let T2 and then T<N> reach `in_review`; read T<N>'s candidate base and PR body.

## Pass when
- Step 2: the new TODO is T<N>; the Home order is T1, T2, T<N>, T3.
- Step 4: no TODO numbered N+1 exists; T2 shows "+1"; `mythical_items.revisions` for T2 has revision 2 with reason `amend`, author Ben and the new text; T2 keeps its branch and its run (it has no PR yet).
- Step 5: the fixture's blocked implement step recorded the amendment as a steer before it was released (§10.2.2, §10.7.3).
- Step 6: T<N>'s work starts from T2's last verified head (§10.3.2). T<N>'s PR is a GitHub draft, since T1 is first, and its body lists T2 among the earlier items it includes (§12.5.1).
- Each placement has one `product_job_events` row with actor Ben.

## Fail when
- Amend creates a TODO, a branch or a PR, or resets T2's state to `queued`.
- The new TODO lands at the end of the stack (append) or before T2.
- The cards show the new order but the engine admits T3 before T<N>.
