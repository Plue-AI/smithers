# C-J3-06 SSH with GitHub keys; VS Code Remote edit lands attributed; port forward

Proves: mvp.md J3.2, J3.4, J10.3, §6.15 SSH into a branch, M-24, M-28, M-29 · spec.md §1.4, §8.10.1–§8.10.5, §8.3, §5.6, §9.1.2, §9.3.2, §9.3.4, §16.3 · Layer: e2e · Stage: S2 · Tickets: T-TRM-03, T-TRM-04, T-COL-04, T-COL-06
Automation: `apps/app/e2e/real/ssh-branch.spec.ts` (new) plus a recorded VS Code session · Runs in: reference host; the VS Code step is recorded manual

## Setup

- A fresh install on the reference host at the commit under test, wrapping `smithers-mvp-canary/<date>`. The owner set the bind address so port 2222 is reachable from the second Mac, and the first public origin's host name is `<install host>` (§8.10.5).
- Maya, a member, has one ed25519 key on GitHub and has never run `smthrs ssh-key`. Ben is a member with no GitHub key.
- TODO T2 on `smithers/retry-webhooks`, asleep. Capacity 1, held by a working TODO, for step 6.
- The second Mac has OpenSSH and VS Code with Remote-SSH.

## Steps

1. Maya signs in. Read `GET /api/user/keys` as Maya.
2. From the second Mac: `ssh -p 2222 retry-webhooks@<install host> 'id -un; pwd'`.
3. `sftp -P 2222 retry-webhooks@<install host>`: put `notes.txt`, get it back.
4. `ssh -p 2222 -L 3000:localhost:3000 retry-webhooks@<install host> 'python3 -m http.server 3000'`, then `curl -s localhost:3000` on the second Mac.
5. VS Code Remote-SSH connects to the same host and branch. Maya edits `src/retry.ts` line 12 and saves. Read the branch activity and the Branch card presence.
6. With capacity full, Maya connects to another asleep branch. Record stderr, then free capacity.
7. `ssh -A …` and `printenv SSH_AUTH_SOCK`; `ssh … root@<install host>`; Ben connects with an unregistered key; a slug that matches two scratch branches.
8. Maya deletes her key on GitHub. Wait for the hourly sync (or trigger it), then reconnect.
9. A maintainer removes Maya while her VS Code session is open.

## Pass when

- Step 1 lists the GitHub key with `source: github`.
- Step 2 prints `maya` and `/workspace`, and the branch wakes through admission.
- Step 3 round-trips byte-equal.
- Step 4 returns the directory listing.
- Step 5: one activity entry "Maya via SSH changed 1 file" opens the diff for `src/retry.ts`, and presence shows "Maya via SSH" at `retry.ts` within 1 s of the save. Needs T-COL-04 and T-COL-06; before they land, record this step as blocked, not passed.
- Step 6: stderr shows "waiting for a machine #1", the connection stays open, and the session starts within 5 s of capacity freeing.
- Step 7: `SSH_AUTH_SOCK` is empty; root, Ben's key and the ambiguous slug are refused, and the slug case prints both candidates.
- Step 8: the reconnect is refused.
- Step 9: the session closes within 5 s.

## Fail when

- The login lands as `developer`, `root` or `agent`.
- The edit appears as "Agent" or "Smithers", or as one entry per keystroke save.
- `pgrep sshd` in the guest finds a process (machines run no sshd, §8.10.3).
- A listener is open on an address other than loopback and the configured bind address (§1.4).
- A key deleted on GitHub still authenticates after the sync.
