# C-J6-02 Laptop `smthrs login` gets a delegated credential that can't merge; merge opens a confirmation

Proves: mvp.md J6.3, J6.4, §6.13 "CLI" and "Attribution", M-21 · spec.md §5.3, §5.3.1, §5.4, §6.4, §14.3 (Settings laptop line), §15.3 · Layer: integration · Stage: S1 · Tickets: T-ACC-04, T-ACC-05
Automation: `packages/smithers/test/DelegatedLogin.integration.test.ts` (new), which drives the source CLI against a real backend · Runs in: CI

## Setup
- The backend at the commit under test in install mode. It uses real PostgreSQL and listens on a random loopback port.
- A fake GitHub that serves the OAuth web flow and the merge API, and records every call.
- Member B is a maintainer with a browser session in the test.
- T1 is `in_review` and first in order, with PR head `h1` and checks passing.
- The source CLI (`makeCli()`) runs in a child process with a temporary `HOME` and `SMITHERS_DISABLE_SYSTEM_KEYRING=1`.
- The CLI runs twice: once with `CLAUDECODE=1` in its environment, and once with no agent variables.

## Steps
1. Run `smthrs login <url> --agent claude-code`, the laptop line Settings shows (§14.3). Complete the browser consent with a headless request carrying B's GitHub identity.
2. Read the stored credential's server row by its id.
3. With the `CLAUDECODE=1` CLI, run `smthrs todo new --prompt "add retry"` (or another `todo.write` command already served).
4. Run `smthrs merge T1`.
5. Send `POST /api/todos/1/merge` directly with the CLI's token.
6. Approve the confirmation from step 4 with the CLI's token, then with B's session.
7. Run `smthrs login <url>` with no `--agent` and no agent variables, then `smthrs todo new --prompt "x"`.

## Pass when
- Step 2: the row has `kind = delegated`, `via = claude-code`, and no approval scope.
- Step 3: the TODO's creating actor is `{person: B, via: "claude-code"}`, and the audit row matches.
- Step 4: the CLI exits 0 and prints exactly a confirmation id and `state: pending`, with no text claiming a merge. The fake GitHub has 0 merge calls.
- Step 5: returns 403 `class: "permission"` with `fix.kind = "confirmation"`.
- Step 6: the CLI token gets 403. B's session approves, and the fake GitHub records exactly 1 merge with `sha = h1`.
- Step 7: the credential is `delegated` with `via = cli`, and the TODO actor is `{person: B, via: "cli"}`.

## Fail when
- `smthrs login` returns a person-equivalent token. Today's `Auth.ts:268` scopes include `write:approval`.
- The CLI reports "merged".
- A `Smithers-Via` header overrides the credential's `via`.
- The confirmation can be approved from the terminal.
