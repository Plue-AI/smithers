# Fault-matrix gaps

What the fault matrix does not cover, and what closing each entry would take.

The matrix is not a directory any more. Each case lives in the package whose
behaviour it asserts, under `packages/<package>/test/faults/`, and each of those
packages declares a `faults` target, so `//packages/...:faults` is the whole
matrix and the `e2e-faults` CI job runs exactly that. This file is the one part
of the old `e2e/` member that belongs to no single package: a coverage record
read across all of them, audited by `fault-skips.test.mjs` beside it.

Cost bands: **S** is at most two engineering days with the infrastructure this
repository already has; **M** is roughly three to five days or needs a new CI
service; **L** is more than a week, needs external credentials, or materially
lengthens CI.

Every row here is a gap in coverage, not a gap in the product unless it says so. A row never replaces a test: where the matrix is required to cover a behaviour the product does not have yet, the case stays in the matrix as a plain failing test and the row explains it. No case is red today — case 22's terminal-log half was the last one, and the redaction deliverable turned it green with no edit to the test — so the `e2e-faults` CI job is required.

| 02 | A real sandbox process is stopped and killed while the engine stays up, and `SandboxHealth` reports `unresponsive` and `ping_failed` from what actually happened to it. | The sandbox is a loopback ping responder, not a supported remote provider. Covering a hosted provider needs credentials and a privileged runtime in CI. | L |
| 03, 05 | The real CLI launches a prompt agent with `up -d`. Its approval park survives natural process exit and `approve` completes it in another process. Its timer park survives a real `SIGKILL`, the original deadline passes with no CLI alive, and `run --resume` completes it. Both preserve one model request, exact final output, cleared waits, and no cancellation. | **CLI approval/timer recovery gap closed:** `packages/smithers/test/faults/case03-cli-durable-recovery.test.ts` uses a recorded HTTP response with the production protocol decoder, agent, engine and SQLite files. It never inserts approvals, rewrites deadlines, or simulates completion through SQL. A separate child-process check proves unrecorded provider requests are blocked. Hosted-provider and orphan-child journeys are not implied. | Closed |
| 31 (graceful park) | A park that a `SIGKILL` interrupts: the host dies with the question, the deadline, or the orphan still outstanding, and a fresh host answers it, fires it, or reaps it. Every case drives the engine directly through `packages/smithers/test/faults/harness/waitChild.ts` and `packages/smithers/test/faults/harness/engineChild.ts`. The graceful path is now covered separately by `packages/smithers/test/faults/case03-05-31-graceful-detached-park.test.ts`: the real CLI runs `up -d`, its child exits normally, the admitted row remains non-terminal, and a later real CLI process executes a bounded `run --resume`. | **Closed in the product.** The 2026-09-04 real-binary rehearsal in `packages/smithers/test/faults/case03-05-31-graceful-detached-park.transcript.md` launched a prompt flow whose first cell called `ask`. After the detached child exited, `ps` read `run-3` as `waiting-approval`, not `cancelled`. A pre-decision `run --resume` returned `Accepted` with exit 3 in 26.8 seconds and left the row parked. `approve` returned `Accepted` with exit 0 in 41.7 seconds and drove the run to `completed`; `output` read `decision approved=true`. The automated case uses a seatless module flow at the deterministic `accepted` boundary because the CLI only executes prompt flows and CI has no model credential; the transcript supplies the stronger in-run-ask evidence. A future deterministic provider fixture at the real CLI boundary would move that stronger boundary into CI. | S |
| 31 | The engine host's observable orphan is reaped by its replacement. The real CLI records a supervisor for each shell or stdio MCP target; another live CLI's group survives startup, and MCP servers that ignore TERM are forcibly stopped during ordinary shutdown. After the CLI is killed, its supervisor automatically cleans up without a replacement. A separate fault stops that supervisor before killing the CLI, leaving a real group for replacement startup to reap. | **CLI composition and recovery gap closed:** `packages/smithers/test/faults/case31-cli-process-containment.test.ts` asserts actual target parentage and process groups against the durable supervisor/owner record, live-owner protection, and process death in both crash schedules. Replacement startup appends exactly one `process-reap-skipped` event with `process-gone` after automatic cleanup, or exactly one `process-reaped` event after signalling the stopped supervisor's surviving group. Containment remains below permission checks. This does not claim remote-provider containment. | Closed |
| 05 | A timer parked in durable state survives a `SIGKILL`, comes due while no host is running, and fires once. Two live replacement hosts also re-arm the same persisted deadline before it expires; an independent file counter proves the post-timer action runs once, including after a fresh-process replay. | **Two-host race gap closed:** `packages/smithers/test/faults/engine/case05-concurrent-timer-hosts.test.ts` requires both hosts to be ready before the actual deadline and verifies each host's re-arm record against the original clock, the first committed completion, and the final cleared wait. Per-host journal records are not mistaken for repeated execution. Real CLI-binary recovery is now covered separately above. | Closed |
| 06 | Two hosts drive one parked run and the step dispatches once, and two control planes with different identities race for one suspended run and exactly one is admitted while the other is refused with `ClaimLost`. | **Closed in the product since this row was written.** The fence used to tell two planes apart by `hostId` and `pid` only (`packages/smithers/control/src/SqlControlRuntime.ts` `sameProcess`) while `@smthrs/cli` supplied no owner, so every local plane was `{hostId: "local", pid: 0}`, considered every other one the same process, and the loser joined instead of losing the fence. `packages/smithers/src/NodeControl.ts` now stamps `{hostId: hostname(), pid: process.pid, nonce}`, and `packages/smithers/test/TwoProcessClaim.test.ts` drives a second real `smithers` process against a run the first owns and asserts it is refused. What this case still does not cover is the fence under a real race rather than a written row: rc.0 ships no flow the CLI can execute for a controlled span without a model provider, so a spawned pair would be decided by whichever process booted first. | S |
| 12 | A rewind restores a real jj working copy, archives the journal suffix, and records a completed audit. A rewind across an irreversible effect runs its registered compensation handler exactly once and completes; a failing handler keeps it refused. | **Compensation gap closed:** `packages/smithers/test/faults/time-travel/case12-rewind-reverts-vcs.test.ts` contributes `CompensationHandlers` to the real Node host. A handled rewind reverts once, restores the tree, and truncates; a failing handler returns `compensation_failed` with a `failed` audit and an untouched journal and workspace; no handler returns `irreversible`. | Closed |
| 16 | Five concurrent subscribers over 500 committed events, against the RSS budget in `packages/smithers/test/faults/budgets/memory.json`. | A long-lived soak: hours of streaming with a growth budget. It would add at least ten minutes to every run, so it belongs in a nightly tier this matrix does not yet have a runner for. | L |
| 22 | The journal redacts a credential out of every committed row, structurally by field name and textually inside a value, checked by reading the SQLite file rather than an API that could redact on the way out. **The operator's terminal is covered too, by a test that is now green.** | The rules recognise credential shapes, not arbitrary strings, so a secret that matches no `@smthrs/journal` `Redaction` rule and sits under no credential-named field is not detected, and neither half of that case nor any other test proves a negative about a shape the rules do not know. Covering that means a taint-tracking seam that follows a declared secret through the run rather than a rule set that recognises one, which is a design this candidate does not have. A second uncovered shape: a child process that writes its own stderr without going through the logger, such as a spawned agent binary, is that process's own output and no logger rewrites it; reaching it needs a case that spawns a real provider binary. Both limits are stated in `docs/pages/release/known-limitations.md#credential-redaction-in-logs`. | M |
| 25 | Unauthenticated and wrongly authenticated callers are refused, and an approval is refused when its envelope or digest does not match what the server issued. | A durable denial audit: actor, scope, target, and timestamp persisted for a refused approval. No audit sink exists to assert against. | M |
| 32 | A checkpoint survives the process that took it, and a reading taken at one sees the pinned tree while the live tree has moved on. A recorded real CLI agent now also captures an uncommitted tracked change, exits on approval, then reads both that checkpoint and the changed live file after another CLI resumes it. | **Agent-cell journey gap closed:** `packages/smithers/test/faults/case03-cli-durable-recovery.test.ts` asserts exact saved Git contents, distinct pinned/live cell outputs, one model request and checkpoint event, terminal replay, unchanged live bytes, and scratch/worktree cleanup. It uses production transport decoding and never inserts checkpoint or recovery rows. This is not a Git garbage-collection, concurrent-materialization, or container-confinement claim. | Closed |

## Scheduled tier continuation (lane G)

The runner-absence descriptions for case 16 and cases 28/29 above predate
`.github/workflows/reliability.yml`'s `sync-long-soak` job. That job now selects
the real sync TCP/SQLite reconnect, stalled-consumer, compaction and retention
workload for 60 minutes on Node 26.4.0 and 26.10.0. It requires completed JSON
receipts through `scripts/check-soak-campaign.mjs`, checks resource growth and
cleanup, and retains artifacts and logs for 30 days even when the workload fails.

This closes the missing sync runner wiring in the `sync-long-soak` job of
`.github/workflows/reliability.yml`; the scheduled 60-minute rows have
not been executed by lane G. They do not establish the CLI case 16 composition,
hours-long behavior, hosted-provider behavior, or reinstatement of every retired
soak case. Those remain separate acceptance evidence.
