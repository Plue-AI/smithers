# Reproduce the native and WASM ABI campaign

From the repository root, with its pinned Rust toolchain and pnpm dependencies installed:

```sh
SMITHERS_ABI_SEED=20260904 \
SMITHERS_ABI_CASES=5000 \
SMITHERS_ABI_STEPS=32 \
SMITHERS_ABI_ARTIFACT_DIR=/tmp/jj-abi-replay \
node scripts/run-jj-abi-campaign.mjs
```

Choose a new evidence directory for each run. Existing reports or logs are refused. The runner executes the parser-only test and native generated test directly, then replays the native test's exact malformed request bytes through the committed real WASM artifact. Cargo builds and Vitest workers are limited to one. Missing tools, missing WASM, nonzero tier exits, missing or incomplete reports, mismatched corpus/artifact hashes, and unbalanced allocations fail the campaign. The nightly reliability workflow runs these same 5,000 cases and 32 operation sequences, rotates the unsigned 32-bit seed by UTC day, and retains reports and logs even on failure. A dispatch can provide the seed explicitly. A local 2,000-case / 16-sequence run is a bounded local result, separate from completion of the scheduled declaration.

Each tier has a 20-minute timeout. On POSIX systems, the runner owns a separate process group for each tier and retires that group on completion, timeout, SIGINT or SIGTERM. Interruptions preserve `campaign.json` with `status: "interrupted"` and the signal; the command exits 130 or 143. Windows cleanup covers the direct child only. The scheduled job and process-group lifecycle regressions run on POSIX.

`parser.json` records seed, raw/grammar counts, status and the pending input's index, kind and complete hexadecimal bytes. `native.json` contains every malformed request as hexadecimal bytes and its complete decoded response, plus operation results and the last pending input. `wasm.json` contains the matching corpus and responses, the WASM SHA-256, call counts, allocation/free counts, outstanding buffers and host file handles, initial/current/peak linear memory, and completed allocation/growth/truncation probes. `campaign.json` records the requested configuration, final outcome, corpus hash, and hashes of all three reports. The input corpus is deterministic for a seed and count; generated repository IDs can vary because jj controls their randomness. Replaying the seed reproduces the inputs and assertions without assuming identical IDs. Reports do not claim automatic shrinking or coverage-guided exploration.

The stable-Rust parser-only target is independently runnable:

```sh
CARGO_BUILD_JOBS=1 cargo test -p flows-jj --locked --test test_abi_parser -- --nocapture
```

It never calls `call_json` or repository operations. Unfiltered raw-byte generation covers lengths 0, 1, 255/256/257, 65,535/65,536/65,537 and arbitrary lengths up to 4,096. Grammar cases supply independent field expectations for all seven request variants, including distinct field values, Unicode, escapes and NUL. Mutations remove required fields, replace field types, duplicate fields, truncate JSON, append NUL and use unknown tags. Separate fixed cases cover optional snapshot messages, trailing whitespace, malformed surrogate escapes and integer overflow. The test-only generator needs no new runtime or dev dependencies; the default locked cargo test runs on the pinned toolchain.

The native raw-byte path first invokes the pure `Request` parser. Only inputs proven malformed reach `call_json` in that corpus, so arbitrary bytes cannot dispatch filesystem operations. Grammar mutations exercise UTF-8, syntax, missing fields, unknown operations, payload types, depth, and signed/unsigned integer boundaries used where strings are required. Operation sequences independently reset their generator to the seed, making complete file content derivable from seed and operation index. They assert both snapshot identity envelopes, the exact unified diff including independently calculated BLAKE2b content hashes, the complete invalid-reference error, the successful restore envelope, the actual restored file bytes, and a successful identity diff after errors. Each sequence then revisits those snapshots three times in a seed-derived order, checking full file bytes and instance health after every restore. All these results are retained and revalidated by the runner; an empty or truncated operation receipt fails verification.

Every WASM request byte is within an owned allocation's initialized prefix. The host independently tracks live ranges and matching frees, unpacks the response pointer/length, parses the entire response using fatal UTF-8 decoding, and frees both request and response buffers. Fixed cases cover zero-length allocation, N−1/N/N+1 initialized subranges around a valid JSON request, every incomplete byte prefix of a Unicode request with unused allocation capacity, a 1 MiB-plus-one-byte allocation, and preservation of initialized request bytes across memory growth. Oversized layouts (`0x80000000` and `0xffffffff`) return zero before allocation; a 65,536-page growth request fails explicitly with `RangeError` and preserves memory size. No free follows a rejected allocation. A successful operation follows every parser failure and every allocation/growth rejection; invalid-reference failures are followed by a successful restore with exact file bytes. No trap or failure may be silently skipped. The fixture enforces an additional 16 MiB growth ceiling; this is a regression ceiling for this workload, not a public request-size limit.

The normal Rust test suite and jj Vitest inventory also execute smaller default campaigns (256 cases and four operation sequences). The standalone WASM default generator is independent; the combined runner explicitly feeds it the native corpus and compares complete error responses across runtimes. Every selection using the supported jj `vitest.config.ts` requires `wasm/flows_jj.wasm` before test collection. The sentinel invokes that actual config in an isolated missing-artifact fixture and requires exit 1, then proves the same invocation passes after copying in the committed artifact. Developer diagnostics using a separate configuration are reduced-scope evidence, not the supported conformance gate.

The scheduled `jj-native-wasm-abi` job also declares a separate parser AddressSanitizer tier on Ubuntu with `nightly-2025-08-08`, `rust-src`, `RUSTFLAGS=-Zsanitizer=address`, `-Zbuild-std --target x86_64-unknown-linux-gnu`, and the same 5,000-case seed. It validates the parser receipt and uploads `asan/parser.json` and `asan/asan.log`; a compiler, test or receipt failure fails the job. The default test command does not build this tier. Locally, `cargo miri test -p flows-jj --locked --test test_abi_parser` requires an installed Miri-capable toolchain. The pinned stable toolchain cannot run Miri or accept ASAN's nightly flags. See the [Rust sanitizer documentation](https://doc.rust-lang.org/unstable-book/compiler-flags/sanitizer.html) for instrumentation requirements.

This is a deterministic generated campaign, not coverage-guided `cargo-fuzz` or an exhaustive ABI proof. A passing uninstrumented local run does not claim completion of the scheduled ASAN tier. It does not pass random invalid pointers or mismatched free sizes, allocate multi-gigabyte buffers, certify internal allocator accounting, or establish a long-duration memory slope. Native `call_json` still excludes pointer packing; the real WASM tier is the evidence for that boundary. The committed artifact remains unchanged; the canonical-host WASM rebuild/reproducibility gate remains separate.
