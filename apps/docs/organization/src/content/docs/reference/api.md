Every module is importable from the root as a namespace
(`import { Roster } from "@smthrs/organization"`) and from its own subpath
(`@smthrs/organization/Roster`). Functions that can refuse return a `Result`
or an `Effect` failing with the module's tagged error; each error carries a
stable `code` or `reason` and a message that never repeats a field's value.
Loaders need `FileSystem` and `Path` from `effect`; the workspace also needs a
`ChildProcessSpawner` for host `git`.

| `BudgetPolicy`                                                                                                                                    | `tokensPerTask`, `tasksPerDay`, `concurrency`, optional `usdPerMonth`.                                                                                                               |
| `TaskContract`, `RoleResult`, `Evidence`                                                                                                          | What a principal is asked to do, and the one result schema every role task returns.                                                                                                  |
| `PrincipalId`, `Superior`, `Kind`, `Status`, `Contact`, `Tool`, `Access`                                                                          | Identifier and enumeration schemas. `owner` is reserved.                                                                                                                             |

## `@smthrs/organization/Grants`

| Export                                                                        | Behavior                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `widenings(child, parent, options?)`                                          | Every way `child` reaches beyond `parent`. With `hired` (the default) a child never holds personal accounts or owner contact. A child's retrieval `allow` stays inside the parent's and its `deny` covers the parent's. |
| `withinDomain(domain, scope)`                                                 | `domain` is `scope` or a subdomain of it.                                                                                                                                                                               |
| `subsetOf(child, parent, options?)`                                           | `widenings(...).length === 0`.                                                                                                                                                                                          |
| `isAssistant(profile)`                                                        | The active, unhired core principal with personal accounts and `owner-direct` contact.                                                                                                                                   |
| `canRead(principal, record, connections)`                                     | Refuses tombstones, personal records for anyone but the assistant, and ungranted containers.                                                                                                                            |
| `canWrite(principal, connection, container, connections)`                     | Requires write access on the container.                                                                                                                                                                                 |
| `canResolveCredential(principal, connection, connections)`                    | The connection is configured and granted; personal connections resolve only for the assistant.                                                                                                                          |
| `canReadKnowledge(principal, path)`                                           | A relative file path covered by a knowledge grant.                                                                                                                                                                      |
| `makeReceiptIssuer(issuedBy)`, `canContactOwner(principal, receipt, context)` | Owner contact: the assistant always; others only with an in-process receipt for that principal, destination, and window.                                                                                                |
| `Denied`, `DeniedReason`, `Widening`, `maxReceiptWindowMs`                    | The refusal, its reasons, one widening, and the longest receipt window (one day).                                                                                                                                       |

## `@smthrs/organization/Authority`

| Export                                                                                                                      | Behavior                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `loadSnapshot(root, loaded)`                                                                                                | Loads the roster (`rosterDir`), the skill pack (`skillsDir`, empty when unset), and the common instructions (`commonFile`, empty when unset) from a wiki root, confined by real path, and validates the roster against the pack.                                                                 |
| `makeSnapshot({ roster, common, skills, weeklyMeeting?, hireSeats? })`                                                      | Validates and pins; the revision covers the roster revision, the common text, and the pack revision. Fails with `AuthorityError` `invalid-roster` listing every violation.                                                                                                                       |
| `makeRegistry(initial)`, `layerRegistry(initial)`, `RosterRegistry`                                                         | The trusted registry: `pin(snapshot)` (keeps every pinned revision, makes it current), `current`, `get(revision)`, `resolve(revision, id)`. Only host code fills it.                                                                                                                             |
| `resolvePrincipal(pinned, current, id)`                                                                                     | The pinned profile when it and every hirer up its chain are active in both rosters and its pinned grants are still inside its current grants.                                                                                                                                                    |
| `RoleTaskPayload`, `TaskWorkspace`, `promptOf(payload)`                                                                     | A role task names `revision`, `principal`, `seat`, `task`, `context`, `digest`, and optionally a `workspace { key, repository }`. It never carries a profile, grants, or a system prompt.                                                                                                        |
| `compose(snapshot, profile, task, context)`                                                                                 | The principal's composition from the snapshot: common instructions, charter, and the profile's skills from the pack, then the task and context.                                                                                                                                                  |
| `authorize(payload, executionId)`                                                                                           | Every dispatch check. Refuses with `DispatchRefused` reasons `malformed-payload`, `unknown-revision`, `unknown-principal`, `inactive`, `grants-narrowed`, `seat-mismatch`, `composition-failed`, `composition-mismatch`, `workspace-not-granted`, `repository-not-granted`, `workspace-foreign`. |
| `layer(actions)`                                                                                                            | Wraps `FlowRuntime.register` and `Action.Implementations.add` for `organization/role-task` so every execution is authorized and runs under its `RoleHost` and `CapabilitySet.attenuate` of that host's envelope. A refusal is an `assembly_failed` `HarnessError` before any model call.         |
| `roleTaskTag`, `Snapshot`, `Registry`, `Authorized`, `AuthorityError`, `DispatchRefused`, `RefusalReason`, `maxCommonBytes` | Constants, models, and errors.                                                                                                                                                                                                                                                                   |

A role task is resolved again whenever its step executes, including on resume.
A host restarted with a different roster no longer holds the old revision, so a
run pinned to it is refused with `unknown-revision` rather than run under a
roster it was not composed against.

## `@smthrs/organization/Workspace`

| Export                                                                                                                                                                                                                                                                                           | Behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `microsandbox(options)`                                                                                                                                                                                                                                                                          | `Machines` over local Microsandbox microVMs: sticky workspace machines, ephemeral fresh ones, forced removal by remote id, and prepared bases as disk snapshots (`smthrs-env-<owner>-<name>`, the newest two per repository kept). A boot names a base and a `Network` (`none`, `all`, or a domain allowlist); without one, networking is off unless `network: true`. Image boots get a `diskMib` root disk (default `defaultDiskMib`, 32 GiB, sparse). The provider refuses a hosted backend. Workspace machines carry their key in the `workspaceLabel` (`smithers.workspace`) label. A machine whose guest dies is started again on its disk; `flush` (`sync`) writes a seeded workspace to that disk.                                                                                                                                                                                             |
| `layer({ machines, maxConcurrentVMs, environments?, limits?, identity? })`                                                                                                                                                                                                                       | The `Workspace` service; a semaphore bounds machine operations. `environments` maps a repository's host path to its `Environment`. Requires `ChildProcessSpawner`, `FileSystem`, and `Path`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `prepare({ key, repoPath, commit })`                                                                                                                                                                                                                                                             | Seeds `/workspace` from `git archive` of the resolved commit and records a guest baseline commit. Reuses a workspace seeded at the same commit; refuses one seeded at another (`occupied`). With an environment `prepare`, the workspace boots from the repository's prepared base instead (made first when missing: seeded, the command run with its network, the disk captured; `prepare-failed` carries the command's last output) and the source difference to the commit is synced onto it, falling back to the archive when it does not apply. The base is keyed by the command, its network, the key paths' content at the commit, and the machines' identity. The prepared tree is flushed before the capture; a base is booted once per host before use to confirm it holds the tree, and one that does not is removed and prepared again. Pruning keeps bases a task is about to boot from. |
| `resolveBase({ repoPath, commit? })`                                                                                                                                                                                                                                                             | The commit a task starts from: `commit`, where `HEAD` (the default) names the environment's `base`; a `<remote>/<branch>` of a configured remote is fetched first within `fetchTimeoutMs` (`fetch-failed` otherwise). Only that remote-tracking ref moves.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `findTools({ key, repoPath, commit })`                                                                                                                                                                                                                                                           | Boots a machine from the prepared base (preparing it when missing) and finds each command in `prepare.tools`: `{ base, tools: [{ name, path }] }`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
