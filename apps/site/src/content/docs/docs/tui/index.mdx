`smthrs tui` is Smithers in a terminal. It works in your local checkout: ask for a change, keep chatting while it works, and inspect every step. The tutorials show it in each **TUI** tab.

## 1.0 scope

The selected 1.0 workflow is the local terminal coding workflow: install, start, connect a configured model, run a checked change, interrupt and recover, and inspect failures. It is not yet release-qualified; [#3185](https://github.com/smithersai/smithers/issues/3185) tracks the candidate receipt.

Cloud and SSH execution, the browser [playground](https://tui.smithers.sh), extensions, custom views, monitors, and factory automation are deferred from this 1.0 scope. Their reference pages describe available features, not release qualification.

## Install

Until the release is published, run it from a source checkout. You need the Node version in `.node-version`, pnpm 11.25.0, Bun 1.4 or later, jj 0.39.0 or later, ripgrep, and the Rust toolchain `rust-toolchain.toml` pins.

```bash
git clone https://github.com/smithersai/smithers.git
cd smithers
pnpm install
cargo build --locked --release -p smithers-ffi --bin smithers-jj-export
export PATH="$PWD/node_modules/.bin:$PATH"
smthrs tui /path/to/project --model openai:gpt-6.1-sol
```

Set `OPENAI_API_KEY` before starting the example above. For another configured model, use its `provider:modelId` with `--model`; `/model` selects among reachable providers. See [configuration](/docs/tui/configuration/#providers). On Alpine, the compiled binary also needs `apk add libstdc++`.

Interactive compiled builds also need a writable, executable `TMPDIR`. If `/tmp` is mounted `noexec`, [set an executable temporary directory](/docs/tui/cli/#startup-on-a-noexec-temporary-filesystem) before launching. `--help` and `--print` do not load OpenTUI and cannot verify interactive startup.

## Make a first change

Give it a check it can run:

```text
Fix math.js so node check.mjs passes.
```

Press Ctrl+S for **Summary**: each edit with its diff, each command with its output.

## Interrupt and recover

Press Esc to interrupt a running turn. For a background worker, open its tab and use **x Stop**, then **r Resume** to continue with its prior steps. Exit with `/quit`, then run `smthrs tui /path/to/project -c` to recover the saved conversation; `/resume` picks another conversation. Check the saved changes before continuing interrupted work.

## See failures

Open **Summary** with Ctrl+S and select the failed work under **Needs you**. Inspect the failure card and command output. Fix the cause before resuming; in a failed worker tab, **m** chooses another model and **r** resumes. A failed check or provider call must remain visible as a failure.

## Candidate qualification

Retain one receipt for the exact candidate commit and immutable artifact identity from [#2483](https://github.com/smithersai/smithers/issues/2483): release label, artifact ID, SHA-256 digest, and installed TUI binary digest. Record OS, architecture, runtime, terminal, model ID, commands, exit results, screen captures, and saved run receipts without credentials.

Run every step below through the real interactive `smthrs tui` boundary on **macOS arm64** and **Linux x64**, using that candidate's artifacts. Repeat at **80x24** with `NO_COLOR` unset and with `NO_COLOR=1`; retain evidence that input, status, failures, and recovery controls remain visible and usable, with no color escapes in the latter run.

| Step | Required evidence on each platform and color mode |
| --- | --- |
| Install | Install the identified candidate artifact; record its digest and version. |
| Start | Launch `smthrs tui` in a disposable project; capture the interactive screen. |
| Connect | Select the configured model; send a prompt and retain a successful real model response. |
| Run work | Fix a deliberately failing local check; retain the diff, command output, and passing check. Keep chat usable while work runs. |
| Interrupt and recover | Stop running work, confirm it stops, exit, reopen with `-c`, and resume it to a checked completion with saved history intact. |
| See failures | Trigger a nonzero command and a provider failure; capture their visible causes, correct them, and retain successful recovery. |

Requests, source fixes, `--help`, `--print`, replay fixtures, and isolated unit tests do not qualify the candidate. Link every failure to a focused issue under [#3185](https://github.com/smithersai/smithers/issues/3185); rerun the affected steps on the replacement candidate before recording qualification. No candidate receipt is recorded here yet.
