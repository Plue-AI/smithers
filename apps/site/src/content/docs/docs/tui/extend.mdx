## Publish a view

A cell calls `ui.publish` with data; the TUI shows it as a view. Reusing an ID updates it in place.

```js
await ctx.call("ui.publish", {
  id: "checks",
  title: "Checks",
  summary: "Two addition checks passed.",
  rows: [{ id: "addition", label: "Addition", status: "done",
    details: [{ kind: "code", language: "javascript", code: "assert(add(2, 3) === 5)" }] }]
})
```

`/ui id` opens a view; `/ui` opens the newest. Blocks are `text`, `code`, `table`, or `diff`. Wrap a panel as `{ kind: "panel", placement: "card", panel }` to show it as a card in chat.

Limits: 24 views per conversation, 1 MB each, 500 rows, 40 blocks per row.

## Add a key or status item

In a flow's frontmatter:

```yaml
metadata:
  tui:
    keys:
      - key: alt+r
        label: Review
    status: true
    card: true
```

Or at run time with `ui.publish` and `kind: "key"` or `kind: "status"`. An action can send a prompt, start a flow or agent, or open a tab. Global keys need Ctrl or Alt; built-in keys always win.

## Watch with a monitor

Ask: "Watch the checks and tell me if the failure changes." A monitor watches a worker, a flow run, or a command's output, and posts an update when it changes in a way that matters.

```js
await ctx.call("monitor.create", {
  id: "checks",
  title: "Checks",
  watch: "Tell me when the check output changes.",
  source: { kind: "shell", command: "cat check-status.txt" },
  trigger: { kind: "interval", seconds: 10 }
})
```

Intervals run from 10 seconds to 24 hours; up to eight monitors at once. Monitors need a connected subscription.
