`smthrs approvals` reads pending requests and submits decisions. An approval is bound to the exact request payload; a run ID alone is insufficient.

## list

`smthrs approvals list` lists pending in-run requests. It does not list pre-run plans such as a trigger's waiting plan. Obtain those payloads from the plan result or the trigger's `activePlan.plan.approval` field.

The list also includes roots whose nested executions are waiting for a human.
Rows carry `runId`, `flowId`, and optional `question` and `approval` fields.
When the journal has no question, `question` uses the declared human-task
prompt. An optional `waits` array carries each holding execution's `runId` and
optional `flowId`, `name`, `attempt`, and `request`.

Answer a `HumanTask` with a signal to the listed root, using the wait's name
and an answer matching its request:

```bash
smthrs runs signal run-3 '{"name":"coding-clarification","payload":"the scheduler owns it"}'
```

## approve

Accepts a serialized payload or `@file`. The default scope is `run`, which extends the grant through the run; `once` covers this request only, and `remembered` can apply to matching future requests.

A plan-level approval records a decision without launching work. Execute the approved payload with `smthrs flow execute @approval.json`.

## deny

`smthrs approvals deny <approval>` refuses the exact request. The argument can be serialized JSON or `@file`, just as for `approve`.

## grant

`smthrs approvals grant <target>` approves the current revision of a build target that declares `approval: "required"`, such as `S.Docker.Push`:

```bash
smthrs approvals grant //images:push
smthrs target //images:push
```

The approval covers that revision only: the declaration, its inputs, its tools, its dependencies and the `--input` values, which `grant` takes the same way. Any change needs a new grant. `--plan` shows the revision as `approval`. Grants are stored in the workspace, so `grant` refuses while `SMITHERS_REMOTE` is set.

`list`, `approve` and `deny` accept `--root` and `--remote` to select the host, and read the bearer from `SMITHERS_TOKEN`. The saved `smithers auth login` session is shared with repository commands; `SMITHERS_TOKEN` is the non-interactive override. Use `--format json` for a structured decision receipt.

For a parked execution, [Waiting for approval](/docs/troubleshooting/waiting-approval/) explains how to locate its request and resume after a decision.
