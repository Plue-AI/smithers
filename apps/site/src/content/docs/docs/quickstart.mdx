Open [Smithers](https://smithers.sh/smithersai/smithers) in your browser. You do not need the CLI to use the app. Available actions depend on sign-in, repository permissions, and the services enabled by your host.

## 1. Connect your account

Select **Connect GitHub** or **Sign in with GitHub**, review the requested permissions, and return to Smithers. Complete the account fields if signup appears; its poll questions are optional. Select **Start Automating** when your workspace is ready.

The setup checklist follows three steps: **Connect GitHub**, **Add a repository**, and **Set up a job**. A step completes from the actual account, repository, or registration state.

## 2. Choose a repository

Select **Add a repository** and follow the import flow, or open a repository already available to your account. Check the selected owner and repository before requesting work.

Open **Chat** with Command-K on macOS or Control-K on Windows and Linux. Read the selected repository's instructions with:

```text
/files.read CONTRIBUTING.md
```

A file card opens in the conversation. Use **Maximize card** for more room. If the repository has no contribution guide, open `/files.read README.md` instead.

For search, type `?` in Chat to choose a search type. Type `/` to browse commands and repository flows.

## 3. Ask a bounded question

Try a read-only request:

```text
Explain this repository. Which files should I read before making a small
documentation change? Do not modify files or start a flow.
```

Read the response and inspect the referenced files. Complete any access step the app requests. [Sign in](/docs/learn/account/) covers access; [Work in a box](/docs/learn/boxes/) covers boxes.

## 4. Set up a job

Select **Set up a job**, or a recommended repository job. Review its configuration and proposed plan before approving registration. Follow the run card and background toast until registration finishes. The checklist does not complete merely because you pressed the button.

The repository's job buttons remain available after setup and show their current state. Use [Dispatcher](/docs/learn/agent-and-trigger/#put-it-on-a-schedule) to inspect declarations and live registrations, prepare a schedule, or run an enabled registration now.

## 5. Make and inspect a change

Choose a small issue and state the expected result and checks. For example:

```text
Update the contribution guide's stale setup instruction to match the current
package scripts. Run the documentation checks and show me the diff.
```

Chat remains usable while background work runs. A request acknowledgment means the work was requested; inspect the run's status and output to learn whether it started or completed. Use **Steer** on the run for a correction. During the current chat turn, Enter steers and Alt-Enter queues a follow-up.

Read the resulting Change's **Diff**, **Checks**, and **Review**. For issue work on the repository's mythical stack, use `/stack.show` to inspect its lane and pull request. On send-upstream repositories, including Smithers, the owner merges the GitHub PR. Verify the resulting main commit before treating it as landed.
