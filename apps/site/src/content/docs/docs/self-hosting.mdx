---
title: "Self-host Smithers"
description: "Run the Smithers app and backend on your own machine: one container, an external PostgreSQL 18, and one data volume."
---

Smithers runs as one unprivileged container, next to a PostgreSQL 18 database you provide, with one persistent volume. One machine, one owner, local disk.

**Partly available.** The image is not published yet ([#1667](https://github.com/smithersai/smithers/issues/1667)). Build it from a source checkout:

```sh
docker build -f distribution/Dockerfile -t smithers .
```

## Start it

```sh
umask 077
cat >smithers.env <<EOF
DATABASE_URL=postgres://smithers:replace-me@postgres:5432/smithers?sslmode=require
EOF
docker run --name smithers --restart unless-stopped -p 4000:4000 \
  --network smithers \
  --env-file ./smithers.env \
  -v smithers-data:/var/lib/smithers \
  smithers
```

`--network` must reach PostgreSQL. The app listens on port 4000 (set `PORT` to change it).

## Claim it

Until it has an owner, the app prints one JSON line with loopback and stored public-origin setup URLs:

```text
{"setup_urls":["http://localhost:4000/setup?token=…"]}
```

Read it with `docker logs smithers`. Open that URL and sign in with GitHub; that account becomes the owner. The token works once. Anyone who signs in later must be on the install's roster.

## Give it model keys

Put provider keys in a JSON file on the data volume and point `SMITHERS_PLATFORM_MODEL_KEYS_FILE` at it. Providers: `anthropic`, `openai`, `cerebras`, `openrouter`, and `vercel` (the AI Gateway key). Every call is metered against the owner's credit; grant it with `smithers-backend credits grant`.

## Back up and upgrade

Stop the container, then run the image's `backup.sh`, `restore.sh`, or `upgrade.sh` entrypoint against the same volume. Upgrade always starts from a verified backup.
