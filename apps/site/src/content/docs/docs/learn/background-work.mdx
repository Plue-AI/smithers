Give a job a clear result and a small set of files. It runs in the background while you keep chatting.

```text
Fix the failing search tests. Keep changes inside src/search.ts and its tests.
```

## Hand it off

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Ask in chat, or start a flow. A toast follows the work until it finishes; the run card holds the detail. Chat stays usable.

</TabItem>
<TabItem label="TUI">

**Available now.** Ask in Chat. Its card shows progress while you keep chatting. The strip shows one live count. A toast reports an off-screen settlement; Enter opens the run and clears it. Notices do not restore after restart. Up to six run at once (`SMITHERS_TUI_WORKERS`); more wait in order.

Use Ctrl+K **Run Claude Code…** or **Run Codex…** to run a signed-in CLI as a worker.

<AppScreenshot src="/images/learn/tui-background-worker.gif" alt="A worker runs in its own TUI tab while chat stays available." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now.** Start a flow and return as soon as it's admitted:

```sh
smthrs flow start review --data '{"args":"Review main"}' --detached
```

</TabItem>
<TabItem label="API">

**Available now.** `POST /api/repos/{owner}/{repo}/invoke` returns at once with the `run_id`.

</TabItem>
</Tabs>

## Follow, stop, retry

| State | Means |
| --- | --- |
| Requested | Saved; not started yet. |
| Queued | Waiting for a free slot. |
| Running | Working. |
| Waiting | Waiting for work it started. |
| Parked | Waiting for provider capacity. |
| Done | Finished; read the result and checks. |
| Failed | Read the error, then retry. |
| Cancelled | Stopped. |

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** The toast offers the controls that apply; the run card has **Steer** and **Stop**. See [Watch an agent work](/docs/learn/watch-an-agent/#steer-or-stop).

Ctrl+S shows every subagent as a tree beside the chat; press it again to close.

</TabItem>
<TabItem label="TUI">

**Available now.** Open active workers with Ctrl+]; finished workers open from Summary. Chat and Summary stay pinned, followed by counts and only the focused run. Its composer is focused; printable keys type. Enter steers a Smithers agent, Alt+X requests Stop (Enter confirms), and Alt+R resumes with its earlier steps. Alt+T takes over any running agent: a Smithers worker pauses at each step until Enter, and Ctrl+Y releases it; a Claude Code or Codex worker opens its CLI on the same session, and quitting that CLI hands it back. Failed workers also offer Alt+M to pick another model and Alt+W to wait for the provider's reset. Ctrl+Y returns to the parent worker or Chat; Ctrl+\ returns directly to Chat. Only actions available for the current state are shown. Ctrl+K lists the same actions, with their keys, from anywhere.

<AppScreenshot src="/images/learn/tui-worker-controls.gif" alt="Stopping and retrying a worker from its TUI tab." caption="The TUI with a scripted test model." width={880} height={480} />

A worker can start its own workers, three levels deep. Ctrl+S shows them together.

<AppScreenshot src="/images/learn/tui-worker-tree.gif" alt="A lead worker and its child workers in the TUI Summary tree." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smthrs runs list --status running
smthrs runs cancel <run>
smthrs runs resume <run>
```

</TabItem>
<TabItem label="API">

**Available now.** API procedures `List`, `Cancel`, and `Resume`; see [HTTP and RPC endpoints](/docs/reference/http-api/).

</TabItem>
</Tabs>
