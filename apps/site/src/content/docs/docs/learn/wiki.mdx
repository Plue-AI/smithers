Each repository has one wiki with a public part and a private part. Pages are Markdown in folders, linked with `[[Page]]`. Every edit is a revision.

## Open a part and read a page

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.**

1. Select **Wiki** in the sidebar.
2. Choose **Public** or **Private**.
3. Pick a page from the tree, or search it. Folders and tags group the pages.
4. Select a link in the page to follow it. Embedded images and pages show inline.

A generated page shows whether it's current with main, such as **current · main**. The rail beside the page lists what links to it (backlinks) and its outline.

<AppScreenshot src="/images/learn/app-wiki-private.png" alt="The Wiki pane in the private part: a hand-written Home page with a link to the roadmap and an embedded image, and its backlinks." caption="The private part, on a hand-written page, with example data." width={2880} height={1800} />

</TabItem>
<TabItem label="TUI">

Not available.

</TabItem>
<TabItem label="CLI">

**Available now** in the `smithers` CLI, built from a source checkout with `go build ./apps/smithers` ([#1989](https://github.com/smithersai/smithers/issues/1989) makes `smthrs` the one front door):

```sh
smithers auth login
smithers wiki index --repo acme/app --visibility private
smithers wiki view getting-started --repo acme/app
smithers wiki search --query install --repo acme/app
```

`index` lists the part's pages with their tags and backlinks, its folders, and its tags. Every wiki command takes `--visibility public|private`; public is the default.

</TabItem>
<TabItem label="API">

**Available now.** Pass `?visibility=public|private` on every wiki request; public is the default.

```sh
curl "$SMITHERS_API/api/repos/acme/app/wiki/navigation/index?visibility=private" \
  -H "Authorization: Bearer $SMITHERS_TOKEN"
curl "$SMITHERS_API/api/repos/acme/app/wiki/getting-started?visibility=private" \
  -H "Authorization: Bearer $SMITHERS_TOKEN"
```

The index returns `pages` (with links and backlinks), `folders`, and `tags`. A page has its `path`, `body`, and `revision`.

</TabItem>
</Tabs>

## Edit, rename, delete

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** On a page, select **Edit** to open the editor; select it again to read. **Rename** moves the page to another path, and **Delete** removes it; its history stays. **New page** adds one to the part you're in.

</TabItem>
<TabItem label="TUI">

Not available.

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers wiki create --title "Getting started" --path Guides/Start.md --repo acme/app
smithers wiki edit getting-started --expected-revision 3 --body "# Getting started" --repo acme/app
smithers wiki edit getting-started --expected-revision 4 --path Guides/Install.md --repo acme/app
smithers wiki delete getting-started --repo acme/app
```

`--expected-revision` refuses a save if someone saved first.

</TabItem>
<TabItem label="API">

**Available now.**

```sh
curl -X PATCH "$SMITHERS_API/api/repos/acme/app/wiki/getting-started?visibility=private" \
  -H "Authorization: Bearer $SMITHERS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"expected_revision":3,"body":"# Getting started\n\nRun pnpm install."}'
```

`POST /wiki` creates a page (`title`, `body`, optional `path`); `PATCH` with `path` renames it; `DELETE /wiki/{slug}` deletes it. A stale `expected_revision` is refused.

</TabItem>
</Tabs>

## History and attachments

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** **History** on a page lists every revision, including renames and the delete; download any revision. **Attach** adds a file under `assets/`; embed it with `![[assets/logo.png]]`.

</TabItem>
<TabItem label="TUI">

Not available.

</TabItem>
<TabItem label="CLI">

**Available now** for history:

```sh
smithers wiki history 7 --repo acme/app
```

The argument is the page id from `wiki index`. Attaching a file is available in the app and the API.

</TabItem>
<TabItem label="API">

**Available now.**

```sh
curl "$SMITHERS_API/api/repos/acme/app/wiki/history/7?visibility=private" \
  -H "Authorization: Bearer $SMITHERS_TOKEN"
curl -X PUT "$SMITHERS_API/api/repos/acme/app/wiki/attachments/logo?path=assets/logo.png&expected_revision=0&visibility=private" \
  -H "Authorization: Bearer $SMITHERS_TOKEN" \
  -H "Content-Type: image/png" --data-binary @logo.png
```

`GET /wiki/history/{pageID}/{revision}/content` returns a revision's exact content, even after a delete. Attachments are up to 16 MiB.

</TabItem>
</Tabs>

## Generate pages from the code

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Enter `/wiki.create owner/repo`. Smithers writes the pages declared in `.smithers/coding-project.json`, in the background. The repository needs its [history](/docs/learn/issue-to-main/) turned on.

</TabItem>
<TabItem label="TUI">

Not available.

</TabItem>
<TabItem label="CLI">

**Planned** ([#1989](https://github.com/smithersai/smithers/issues/1989)).

</TabItem>
<TabItem label="API">

**Available now.** `POST /api/repos/{owner}/{repo}/mythical/wiki` requests a refresh and answers `202`. It answers `409` if history is off or the repository declares no wiki.

</TabItem>
</Tabs>

**Partly available.** When main moves, Smithers regenerates the declared pages, reviews them against the code, and keeps pages a person edited. Hosted proof is tracked in [#1923](https://github.com/smithersai/smithers/issues/1923).
