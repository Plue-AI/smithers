**Partly available.** The API connects a conversation to Slack or Telegram, and the app reads the connection and the conversation. Connecting from the app is planned, and live acceptance is tracked in [#2105](https://github.com/smithersai/smithers/issues/2105).

A conversation syncs with one Slack thread or one Telegram chat or topic. A message, edit, or delete on either side appears once on the other. Agents post under their own names.

| | Slack | Telegram |
| --- | --- | --- |
| Messages and replies | Both ways | Both ways |
| Edits | Both ways | Both ways |
| Deletes | Both ways | Smithers to Telegram only |
| Reactions | Both ways | Both ways |

<TabItem label="API">

**Available now** in the backend; live acceptance in [#2105](https://github.com/smithersai/smithers/issues/2105). One route connects a conversation (an issue number):

```sh
curl -X PUT "$SMITHERS_API/api/repos/acme/app/issues/42/sync" \
  -H "Authorization: Bearer $SMITHERS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"provider":"slack","connection_id":"slack-main","scope_id":"T0123","conversation_id":"C0123","thread_id":""}'
```

An empty `thread_id` starts a new Slack thread. For Telegram, `scope_id` is the bot ID and `conversation_id` the chat ID. `GET` on the same route returns the mapping and its state. A mapping cannot change once set.

## See it synced

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Open the conversation from the issue list (**Conversations**) or with `/issues.view 42`. Each message shows who posted it: agents under their names, a Slack user as the mirror recorded it. Reactions count, the `slack ↗` link opens the thread, and a message that did not deliver keeps its text with **Retry**. Live acceptance: [#2105](https://github.com/smithersai/smithers/issues/2105).
