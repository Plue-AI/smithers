Ask for something concrete. Smithers answers in the conversation. Slow work runs in the background, so you can keep chatting.

## Send a message

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.**

1. Check the repository name beside the message box.
2. Select **Chat**, or press Command-K (Ctrl-K on Windows and Linux).
3. Say what you want and how you'll judge the result. Press Enter.

<AppScreenshot src="/images/learn/app-chat.gif" alt="Opening Chat, typing a question, and reading the reply in the Smithers app." caption="Chat in the app, with a scripted reply." width={800} height={500} />

Smithers answers in prose, shows a card, or starts a flow. If a step needs sign-in, it asks in the conversation.

</TabItem>
<TabItem label="TUI">

**Available now.**

```sh
smthrs tui
```

Type your request and press Enter. Shift+Enter adds a new line.

<AppScreenshot src="/images/learn/tui-composer.gif" alt="Writing a two-line request in the TUI and reading the answer." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now.** Answer one prompt and exit:

```sh
smthrs tui -p "Explain this repository. Which files should I read first?"
```

The answer prints to standard output. Add `--model provider:model` to pick the model.

</TabItem>
<TabItem label="API">

**Partly available.** Create a private chat, then post messages as comments. An agent reply to a chat message is planned.

```sh
curl -X POST "$SMITHERS_API/api/repos/acme/app/issues" \
  -H "Authorization: Bearer $SMITHERS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"Conversation","kind":"chat","idempotency_key":"chat-1"}'
```

The app's own chat route, `POST /api/agent/turn`, needs a signed-in browser session.

</TabItem>
</Tabs>

## Use cards and commands

Results arrive as cards beside the request: a file, a run, an approval. Select **Maximize card** for more room.

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Type `/` to browse commands and flows. A trailing dot, such as `/review.`, lists a command group.

</TabItem>
<TabItem label="TUI">

**Available now.** Type `/` to browse commands. Repository flows appear in the same menu.

</TabItem>
<TabItem label="CLI">

**Available now.** `smthrs --help` lists commands; add `--help` to any command.

</TabItem>
<TabItem label="API">

</TabItem>

## Steer or queue while it works

A turn can take a while. You don't have to wait.

- **Steer**: change the current request before its next step.
- **Queue**: add a follow-up that starts after this one.
- **Stop**: end the current turn and keep your draft.

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** While Smithers is answering, Enter steers and Alt+Enter queues. Queued messages stay with the conversation; you can edit or remove them. To correct a specific run, use **Steer** on its card.

</TabItem>
<TabItem label="TUI">

**Available now.** Enter steers, Alt+Enter queues, Alt+Up brings queued messages back, and Esc stops.

<AppScreenshot src="/images/learn/tui-queue.gif" alt="Queueing a follow-up in the TUI, bringing it back to the editor, and stopping the turn." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now** for durable runs, by run ID:

```sh
smthrs runs steer <run> --message "Keep the public API unchanged."
```

`smthrs runs cancel <run>` stops a run.

</TabItem>
<TabItem label="API">

**Available now** for durable runs, over the API: `Steer { runId, message, idempotencyKey }` and `Cancel { runId, idempotencyKey }`. See [HTTP and RPC endpoints](/docs/reference/http-api/).

</TabItem>
</Tabs>
