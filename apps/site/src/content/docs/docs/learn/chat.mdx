Ask for something concrete. Smithers answers in the conversation. Slow work runs in the background, so you can keep chatting.

## Send a message

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.**

1. Open the app and select **Chat**, or press Command-K (Ctrl-K on Windows and Linux).
2. Type your request and press Enter.

<AppScreenshot src="/images/learn/app-chat.gif" alt="Opening Chat, typing a question, and reading the reply in the Smithers app." caption="The app on a local host. The reply comes from a scripted test model." width={800} height={500} />

</TabItem>
<TabItem label="TUI">

**Available now.**

```sh
smthrs tui
```

Type your request and press Enter. Shift+Enter adds a new line.

<AppScreenshot src="/images/learn/tui-composer.gif" alt="Writing a two-line request in the TUI and reading the answer." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now.** Answer one prompt and exit:

```sh
smthrs tui -p "Explain this repository. Which files should I read first?"
```

The answer prints to standard output. Add `--model provider:model` to pick the model.

</TabItem>
<TabItem label="API">

**Planned.** Create a chat with `POST /api/repos/{owner}/{repo}/issues` and `"kind": "chat"`, then post messages as comments ([#2111](https://github.com/smithersai/smithers/issues/2111)).

The app's own chat route, `POST /api/agent/turn`, needs a signed-in browser session.

</TabItem>
</Tabs>

## Steer or queue while it works

A turn can take a while. You don't have to wait.

- **Steer**: change the current request before its next step.
- **Queue**: add a follow-up that starts after this one.
- **Stop**: end the current turn and keep your draft.

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** While Smithers is answering, Enter steers and Alt+Enter queues. Queued messages stay with the conversation; you can edit or remove them.

</TabItem>
<TabItem label="TUI">

**Available now.** Enter steers, Alt+Enter queues, Alt+Up brings queued messages back, and Esc stops.

<AppScreenshot src="/images/learn/tui-queue.gif" alt="Queueing a follow-up in the TUI, bringing it back to the editor, and stopping the turn." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now** for durable runs, by run ID:

```sh
smthrs runs steer <run> --message "Keep the public API unchanged."
```

`smthrs runs cancel <run>` stops a run.

</TabItem>
<TabItem label="API">

**Available now** for durable runs, over the API: `Steer { runId, message, idempotencyKey }` and `Cancel { runId, idempotencyKey }`. See [HTTP and RPC endpoints](/docs/reference/http-api/).

</TabItem>
</Tabs>
