Some steps wait for you: a file edit, a command, a launch. The run pauses until you decide. Read what it asks, then approve or deny.

## Find what's waiting

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** An approval card appears in the conversation. To list every pending request on the repository, enter `/approvals.list`. Each request names its run; open the run for context.

**Available now.** **Inbox** in the sidebar opens the same list. **Planned:** runs a budget or time guard paused, with **Continue** and **Stop** ([#2114](https://github.com/smithersai/smithers/issues/2114)).

<AppScreenshot src="/images/learn/preview-inbox.png" alt="Design preview of the Inbox: a paused run with Continue and Stop, an approval, and a question." caption="Design preview with example data. Not connected yet." width={868} height={509} />

</TabItem>
<TabItem label="TUI">

**Available now.** The request appears above the composer. Start the TUI with `--approve ask` to be asked, or `--approve deny` to refuse edits, shell commands, and network calls; the default allows them. `SMITHERS_TUI_APPROVE` sets the same.

```sh
smthrs tui --approve ask
```

**Available now.** A flow run a budget or time guard paused shows under **Needs you**. In its tab, press **c** to continue or **x** to stop it.

**Planned.** A list of pending approvals across runs ([#2119](https://github.com/smithersai/smithers/issues/2119)).

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smthrs approvals list
```

Each entry carries the exact payload to approve. With nothing waiting, it prints `[]`.

</TabItem>
<TabItem label="API">

**Available now**, over the gateway's projection RPC: `Projection.Snapshot` with selector `{ _tag: "approvals" }`. Each row has `runId`, `requestId`, `title`, `payload`, and `status`. See [HTTP and RPC endpoints](/docs/reference/http-api/).

</TabItem>
</Tabs>

## Decide

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.**

1. Read the requested action and the repository or run it concerns.
2. Check that it matches the work you asked for.
3. Select **Approve** or **Deny**, and wait for the card to show your decision.

</TabItem>
<TabItem label="TUI">

**Available now.** Press `y` to allow once or `n` to deny. Where offered, `a` allows that kind of call for the rest of the conversation. The keys work once the editor is empty and the 400 ms typing guard has elapsed. A flow asks once for each thing it may do.

<AppScreenshot src="/images/learn/tui-flow-approval.gif" alt="A flow asks for its write, process, and network permissions in turn; pressing y allows each, and the run completes." caption="The TUI with a fixture flow." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now.** Pass the payload from `approvals list`, or `@file`:

```sh
smthrs approvals approve @approval.json
smthrs approvals deny @approval.json
```

`--scope once|run|remembered` sets how far an approval reaches. The default is `run`.

</TabItem>
<TabItem label="API">

**Available now.** `Approval.Submit { target, scope, idempotencyKey, decision: "approve" | "deny" }` over the API. See [HTTP and RPC endpoints](/docs/reference/http-api/).

</TabItem>
</Tabs>

## Approve a build target

A target that declares `approval: "required"`, such as `S.Docker.Push`, runs only after its current revision is approved. Any change to the target or its inputs needs a new approval.

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Open **Inbox**: each waiting target shows its label and revision with **Approve** and **Deny**.

</TabItem>
<TabItem label="TUI">

**Available now.** Press Ctrl+S: each waiting target shows under **Needs you** as its label and short revision. Select it, then press **y** to approve or **n** to deny.

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smthrs approvals list --targets
smthrs approvals grant //images:push
smthrs target //images:push
```

`grant` also works against a remote host with `--remote`.

</TabItem>
<TabItem label="API">

**Available now.** `Plan { flowId: "system/target", input: { label, digest }, idempotencyKey: "target:<label>:<digest>" }`, then `Approval.Submit` with the returned plan and `decision: "approve"`. `digest` is the target's `approval` in `smthrs target <label> --plan --json`. `List { _tag: "plans", filters: { flowId: "system/target", decision: "pending" } }` returns the revisions waiting; pass an item's `card.approval` to `Approval.Submit`.

</TabItem>
</Tabs>

## Correct it instead

If the request is too broad or targets the wrong repository, deny it and tell Smithers what to change. For a running flow, [steer the run](/docs/installation/).
