A change is the code a run proposes, with the evidence for landing it.

## Read the diff

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Open the change from the run's result, or enter `/change.view <id>`. Start with **Diff**; select **Full diff** for every line. With several revisions, compare them with the revision selectors.

<AppScreenshot src="/images/app/change-example.png" alt="A change card with its revision, changed files, review views, and landing controls." caption="A change card, with example data." width={712} height={310} />

</TabItem>
<TabItem label="TUI">

**Available now** for edits the TUI made locally. On a finished worker's card in the chat (Tab focuses it), its **Summary** row, or its tab, press `d` for the run's whole diff; Esc goes back. In the chat's own **Summary**, pick a row with the arrows, Enter expands it, `d` shows its diff, `v` switches split and unified.

<AppScreenshot src="/images/learn/tui-review-diff.gif" alt="Reading a captured edit's diff in the TUI Summary." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers change diff CHANGE_ID
smithers land view 42 --repo acme/app
```

</TabItem>
<TabItem label="API">

**Available now.** `GET /api/repos/{owner}/{repo}/changes/{id}` and `/changes/{id}/diff`.

</TabItem>
</Tabs>

## Check the evidence

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** **Checks** shows check results, **Findings** shows analyzer findings, and **Review** shows verdicts and discussion. Ask Smithers to fix a specific finding, then read the new diff and checks.

<AppScreenshot src="/images/app/checks-example.png" alt="The Checks view of a change card with a build result." caption="Checks, with example data." width={712} height={306} />

</TabItem>
<TabItem label="TUI">

**Available now.** Expand a command row in **Summary** to read its output.

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers land checks 42 --repo acme/app
smithers land conflicts 42 --repo acme/app
```

</TabItem>
<TabItem label="API">

**Available now.** `GET /api/repos/{owner}/{repo}/changes/{id}/findings`; reviews and comments live on the landing: `GET /api/repos/{owner}/{repo}/landings/{number}/reviews`.

</TabItem>
</Tabs>

## Review a pull request

<Tabs syncKey="surface">
<TabItem label="GUI">

**Beta.** Open the pull request with `/prs.view <number>`, then select **Approve** or **Request changes**. Line comments and suggested changes are not available yet.

</TabItem>
<TabItem label="TUI">

**Planned.**

</TabItem>
<TabItem label="CLI">

**Beta.** Approve, or comment on the whole pull request. Line comments and suggested changes are not available yet.

```sh
smithers land review 42 --repo acme/app --approve --commit COMMIT_ID
smithers land comment 42 --repo acme/app --body "Needs a test" --commit COMMIT_ID
```

</TabItem>
<TabItem label="API">

**Beta.** `POST /api/repos/{owner}/{repo}/landings/{number}/reviews` and `/comments`; a comment with `path` and `line` starts a line thread, closed with `/threads/{id}/done` and `/threads/{id}/ack`. Suggested changes are not available yet.

</TabItem>
</Tabs>

## Land it, or undo it

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** When checks and required reviews pass, select **Land**. Its label shows the range, such as **Land 1 → 2**; check it before confirming. If landing is blocked, the card says what's missing.

A person's request for changes blocks landing until they approve, or they or a repository admin dismiss the review. A later comment does not clear it, and the change's author cannot dismiss it. The card shows **changes requested by** that person and an **Ask** button to request their review again. An agent's request for changes does not block landing.

On a repository that sends work upstream, including Smithers itself, landing opens a GitHub pull request for the owner to merge.

</TabItem>
<TabItem label="TUI">

**Available now.** Changes stay in your checkout; commit them yourself. To undo a run, press `u` where `d` works (Alt+U and Alt+V in its agent tab): every file it changed is listed, files a shell command wrote included. Space unchecks one; Enter undoes the rest. A file changed since the run, one outside the repository, and a binary or large change stay as they are.

<AppScreenshot src="/images/learn/tui-undo-edit.gif" alt="Undoing a captured edit from the TUI Summary." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers land review 42 --repo acme/app --approve --commit COMMIT_ID
smithers land land 42 --repo acme/app --commit COMMIT_ID
```

</TabItem>
<TabItem label="API">

**Available now.** `PUT /api/repos/{owner}/{repo}/landings/{number}/land`.

**Beta.** `GET /api/repos/{owner}/{repo}/operations` lists the repository's jj operations. `POST /api/repos/{owner}/{repo}/workspaces/{id}/operations/{op_id}/undo` undoes one in a workspace; `GET` its `/undo/preview` first. The app and CLI do not show operations yet.

</TabItem>
</Tabs>
