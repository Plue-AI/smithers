An agent's history is its runs. Each run has a timeline.

## Flags to look for

| Flag | Means |
| --- | --- |
| Thrashing | The agent repeats work without progress. |
| Blocked | The run paused and needs a resume. |
| Approval needed | The run waits for your decision. |
| Runaway | A budget or time limit paused it. Continue or stop it. |

## Find an agent's runs

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Select **Agents** in the sidebar, then **Runs** beside an agent. Or enter `/runs.list` with **Flow** set to the agent's id, such as `reviewer`. Select a run to open it.

<AppScreenshot src="/images/learn/app-agents.png" alt="The Agents card lists each agent with its model and a Runs button." caption="The Agents card." width={852} height={364} />

The card lists the built-in agents and the loaded repository's agent flows: a `flows/<name>/flow.mdx` whose frontmatter names a `model`.

</TabItem>
<TabItem label="TUI">

**Available now.** `/smithers` lists flow runs, newest first. Select one to open its tab. Active background workers have tabs too; finished runs open from Summary; see [Work in the background](/docs/learn/background-work/).

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smthrs runs list --flow reviewer
smthrs runs list --status waiting-approval
```

</TabItem>
<TabItem label="API">

**Available now.** API procedure `List { _tag: "runs", filters: { flowId: "reviewer" } }`. Over HTTP, `GET /api/repos/{owner}/{repo}/workflows/{id}/runs` lists one flow's runs.

</TabItem>
</Tabs>

## Read the timeline

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** The run card shows the trace as a tree and a timeline, with the flags above. Select a row for its inputs, output, and token use. Filter the trace, or select **Maximize card** for room.

<AppScreenshot src="/images/app/run-example.png" alt="A run card with status, trace filters, a call tree, and controls to stop or steer the run." caption="A run card, with example data." width={712} height={592} />

**Available now.** Select **Steps** for one row per step: time, type, description, duration, and tokens. Select a step for its detail. The first rows are the run's recorded triggers: the pushed ref a change request started from, the schedule that fired it, and each approval decision with who made it. **Planned:** the chat message that started a run ([#2115](https://github.com/smithersai/smithers/issues/2115)).

<AppScreenshot src="/images/learn/app-run-steps.png" alt="The Steps view of a finished run: two trigger rows, the schedule that fired it and an approval by will, then three steps with durations." caption="The Steps view, with example data." width={2264} height={1162} />

</TabItem>
<TabItem label="TUI">

**Available now.** Press Ctrl+T for a one-row timeline over the current view, with recorded actions; arrows move, `[` and `]` jump between milestones, Home and End jump to the ends, Esc restores the previous view, scroll and composer target. An earlier point shows only what was known then.

<AppScreenshot src="/images/learn/tui-timeline.gif" alt="Inspecting recorded actions in the TUI timeline." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smthrs runs show <run>
smthrs runs logs <run> --follow
```

`show` gives the status and a diagnosis. `logs` streams events as they commit.

</TabItem>
<TabItem label="API">

**Available now.** API procedure `Watch { runId, follow: true }` streams events. `Projection.Snapshot` with selector `run-events` or `run-tree` returns the recorded trace.

</TabItem>
</Tabs>

## Steer or stop

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Type a correction in the run's steering box and select **Steer**. Use **Stop** to cancel it. For a paused run, enter `/runs.resume`. Starting it again creates a second run.

```text
Keep the existing public API. Fix the parser and add a regression test.
```

</TabItem>
<TabItem label="TUI">

**Available now.** In a running flow's tab, `x` stops it. A failed, cancelled, interrupted, or parked run offers `r` to resume. Ctrl+K lists the same actions from anywhere. Completed runs show neither control.

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smthrs runs steer <run> --message "Keep the existing public API."
smthrs runs cancel <run>
smthrs runs resume <run>
```

</TabItem>
<TabItem label="API">

**Available now.** API procedures `Steer { runId, message, idempotencyKey }`, `Cancel`, and `Resume`. Over HTTP, `POST /api/repos/{owner}/{repo}/runs/{id}/cancel` and `/resume`.

</TabItem>
</Tabs>

If the run waits on a decision, [answer the approval](/docs/learn/approvals/). If it failed, read its error before retrying. If it produced a change, [review it](/docs/learn/review-a-change/).
