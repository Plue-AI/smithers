An agent's history is its runs. Each run has a timeline.

## Flags to look for

| Flag | Means |
| --- | --- |
| Thrashing | The agent repeats work without progress. |
| Blocked | The run parked and needs a resume. |
| Approval needed | The run waits for your decision. |
| Runaway | A budget or time guard parked it. Planned. |

## Find an agent's runs

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Enter `/runs.list` and set **Flow** to the agent's id, such as `reviewer`. Select a run to open it.

**Planned.** An **Agents** list with a **Runs** button per agent ([#2113](https://github.com/smithersai/smithers/issues/2113)).

<AppScreenshot src="/images/learn/preview-agents.png" alt="Design preview of the Agents list, each agent with a Runs button." caption="Design preview with example data. Not released." width={868} height={380} />

</TabItem>
<TabItem label="TUI">

**Available now.** `/smithers` lists flow runs, newest first. Select one to open its tab. Background workers each have a tab too; see [Work in the background](/docs/learn/background-work/).

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smthrs runs list --flow reviewer
smthrs runs list --status waiting-approval
```

</TabItem>
<TabItem label="API">

**Available now.** API procedure `List { _tag: "runs", filters: { flowId: "reviewer" } }`. Over HTTP, `GET /api/repos/{owner}/{repo}/workflows/{id}/runs` lists one flow's runs.

</TabItem>
</Tabs>

## Read the timeline

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** The run card shows the trace as a tree and a timeline, with the flags above. Select a row for its inputs, output, and token use. Filter the trace, or select **Maximize card** for room.

<AppScreenshot src="/images/app/run-example.png" alt="A run card with status, trace filters, a call tree, and controls to stop or steer the run." caption="A run card, with example data." width={712} height={592} />

**Planned.** A **Steps** view: the trigger first, then time, type, description, duration, and tokens for each step ([#2115](https://github.com/smithersai/smithers/issues/2115)).

<AppScreenshot src="/images/learn/preview-run-steps.png" alt="Design preview of the Steps view: a run flagged Runaway, with a Resume button and five steps with durations and tokens." caption="Design preview with example data. Not released." width={868} height={562} />

</TabItem>
<TabItem label="TUI">

**Available now.** The timeline sits above the composer, with phases (Researching, Implementing, Testing, Stuck, Blocked) and milestones. Press Ctrl+T to inspect it; arrows move, `[` and `]` jump between milestones, Home and End jump to the ends, Esc returns to live. An earlier point shows only what was known then.

<AppScreenshot src="/images/learn/tui-timeline.gif" alt="Scrubbing the TUI timeline across phases and milestones." caption="The TUI with a scripted test model." width={880} height={480} />

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smthrs runs show <run>
smthrs runs logs <run> --follow
```

`show` gives the status and a diagnosis. `logs` streams events as they commit.

</TabItem>
<TabItem label="API">

**Available now.** API procedure `Watch { runId, follow: true }` streams events. `Projection.Snapshot` with selector `run-events` or `run-tree` returns the recorded trace.

</TabItem>
</Tabs>

## Steer or stop

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Type a correction in the run's steering box and select **Steer**. Use **Stop** to cancel it. For a paused run, enter `/runs.resume`. Starting it again creates a second run.

```text
Keep the existing public API. Fix the parser and add a regression test.
```

</TabItem>
<TabItem label="TUI">

**Available now.** In a flow run's tab, `x` stops it and `r` resumes it. `/stop <id>` and `/retry <id>` do the same by ID.

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smthrs runs steer <run> --message "Keep the existing public API."
smthrs runs cancel <run>
smthrs runs resume <run>
```

</TabItem>
<TabItem label="API">

**Available now.** API procedures `Steer { runId, message, idempotencyKey }`, `Cancel`, and `Resume`. Over HTTP, `POST /api/repos/{owner}/{repo}/runs/{id}/cancel` and `/resume`.

</TabItem>
</Tabs>

If the run waits on a decision, [answer the approval](/docs/learn/approvals/). If it failed, read its error before retrying. If it produced a change, [review it](/docs/learn/review-a-change/).
