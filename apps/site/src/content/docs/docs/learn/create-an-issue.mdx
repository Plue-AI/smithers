An issue is something to get done. It moves `open → fixed → verified → closed`. The person who verifies it cannot be the one who fixed it.

## Open the issue

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Enter `/issues.create` and give it a title. `/issues.list` shows open issues; `/issues.view 42` opens one; `/issues.comment` replies.

</TabItem>
<TabItem label="TUI">

**Planned.** Issue commands in the TUI ([#2119](https://github.com/smithersai/smithers/issues/2119)).

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers issue create --repo acme/app --title "Footer link is hard to find" --body "Make the label clearer."
smithers issue list --repo acme/app
smithers issue view 42 --repo acme/app
```

</TabItem>
<TabItem label="API">

**Available now.**

```sh
curl -X POST "$SMITHERS_API/api/repos/acme/app/issues" \
  -H "Authorization: Bearer $SMITHERS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"Footer link is hard to find","body":"Make the label clearer."}'
```

Set `SMITHERS_API` to your Smithers API origin and `SMITHERS_TOKEN` to a personal access token with the `write:repository` scope. The response is the issue, with its `number`.

</TabItem>
</Tabs>

## Hand it to the factory

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Enter `/issue.implement 42`. The factory plans, changes, checks, and opens a pull request. **History** (`/history.show`) shows its progress.

</TabItem>
<TabItem label="TUI">

**Planned** ([#2119](https://github.com/smithersai/smithers/issues/2119)).

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers issue edit 42 --repo acme/app --label smithers
```

</TabItem>
<TabItem label="API">

**Available now.** Label the issue `smithers`:

```sh
curl -X PATCH "$SMITHERS_API/api/repos/acme/app/issues/42" \
  -H "Authorization: Bearer $SMITHERS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"labels":["smithers"]}'
```

</TabItem>
</Tabs>

## Mark it fixed, then verified

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** On the issue card, select **Fixed**, then, as someone else, **Verify**. Or enter `/issues.fix 42` and `/issues.verify 42`. The list shows each issue's state; **Conversations** and **Issues** narrow it. Set an owner, due date, priority or parent with `/issues.set`.

<AppScreenshot src="/images/learn/app-issues.png" alt="The issue list: Open and Closed counts, All, Conversations and Issues filters, a conversation row, and two issues, one marked fixed." caption="The issue list, with example data." width={2264} height={538} />

</TabItem>
<TabItem label="TUI">

**Planned** ([#2119](https://github.com/smithersai/smithers/issues/2119)).

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers api /api/repos/acme/app/issues/42 --method PATCH --field state=fixed
smithers api /api/repos/acme/app/issues/42 --method PATCH --field state=verified
```

</TabItem>
<TabItem label="API">

**Available now.** Set `state` to `fixed`, then, as a different person, `verified`:

```sh
curl -X PATCH "$SMITHERS_API/api/repos/acme/app/issues/42" \
  -H "Authorization: Bearer $SMITHERS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"state":"verified"}'
```

Verifying your own fix fails with `self_verification`. Verifying an issue that is not `fixed` fails with `invalid_transition`.

`owner` (a username), `due` (`YYYY-MM-DD`), `priority` (`0`–`3`) and `parent` (an issue number in the same repository) are set the same way; `null` clears one. A parent that would loop fails with `cycle`. An unknown field fails with `400`.

</TabItem>
</Tabs>
