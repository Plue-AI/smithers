An agent is a file in your repository. A trigger starts it.

## Write the agent

**Available now.** Every surface reads the same file. Create `flows/reviewer/flow.mdx`:

```markdown title="flows/reviewer/flow.mdx"
---
description: Reviews the working-copy change and returns a verdict with reasons.
model: openai:gpt-6-sol
capabilities: ["fs:read:**", "proc:spawn:*"]
budget:
  tokens: 200000
  milliseconds: 600000
---

# Review the change

Read the diff and run the tests. Return approve or request changes,
with the evidence for each finding.
```

Allow only what the job needs. [flow.mdx frontmatter](/docs/reference/flow-mdx/) lists every key. On Smithers Cloud, commit it to the default branch.

## Run it once

Run it like any flow: `/reviewer` in the app, `/flow reviewer` in the TUI, or `smthrs flow start reviewer`. See [Run a flow](/docs/learn/run-a-flow/).

## Put it on a schedule

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.**

1. On the home, open **Run it every night**, or select **Dispatcher** in the sidebar and then **Register a rule**.
2. Pick the flow and select **Schedule**. It runs nightly (02:00 UTC) under the flow's name; a toast follows the registration until it is live.
3. For another schedule, a name, input or limits, type the line instead: `/triggers.register --flow lint --schedule "0 9 * * 1-5"`. That path prepares the plan for you to read and approve before it registers.

Each live schedule has **Run now** and **Pause**. A scheduled run needs a token and time budget; the form uses the flow's `budget`.

<TabItem label="CLI">

**Available now** for a local project:

```sh
smthrs triggers register weekday-review --flow reviewer --cron "0 9 * * 1-5" --timezone America/New_York
smthrs triggers list
smthrs triggers fire weekday-review
```

Keep `smthrs serve` running for schedules to fire. A fired run still asks for approval. See [Define triggers](/docs/guides/triggers/).

</TabItem>

## Keep the rule with the code

**Partly available.** To keep rules with the code, add them to `.smithers/FACTORY.ts`. When main moves, rules for `flow.mdx` agents go live; rules for `flow.ts` flows stay declared only. See [Triggers and flows](/docs/how-it-works/triggers-and-flows/#rules).

```ts title=".smithers/FACTORY.ts"
import { Smithers as S } from "@smthrs/targets"

export const factory = S.Factory({
  summary: "How this repository develops itself.",
  on: {
    "schedule:0 9 * * 1-5": { flow: "reviewer", description: "Weekday morning review" }
  }
})
```
