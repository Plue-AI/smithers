**Planned.** Thread sync is built and awaiting release ([#2105](https://github.com/smithersai/smithers/issues/2105)). This page describes how it will work.

A thread maps to one Slack thread or one Telegram chat or topic. A message, edit, or delete on either side appears once on the other. Agents post under their own names.

| | Slack | Telegram |
| --- | --- | --- |
| Messages and replies | Both ways | Both ways |
| Edits | Both ways | Both ways |
| Deletes | Both ways | Smithers to Telegram only |
| Reactions | Both ways | Not mirrored ([#2110](https://github.com/smithersai/smithers/issues/2110)) |

<TabItem label="API">

**Planned** ([#2105](https://github.com/smithersai/smithers/issues/2105)). One route maps a thread:

```sh
curl -X PUT "$SMITHERS_API/api/repos/acme/app/issues/42/sync" \
  -H "Authorization: Bearer $SMITHERS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"provider":"slack","connection_id":"slack-main","scope_id":"T0123","conversation_id":"C0123","thread_id":""}'
```

An empty `thread_id` starts a new Slack thread. For Telegram, `scope_id` is the bot ID and `conversation_id` the chat ID. `GET` on the same route returns the mapping and its state. A mapping cannot change once set.
