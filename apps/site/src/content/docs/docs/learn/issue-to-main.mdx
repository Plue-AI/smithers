When Smithers works on issues, each one moves through a path: planned, built, checked, opened as a pull request, landed. **History** shows every issue on that path at once, above the changes already on main.

## Turn it on

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Select **History**, then **Bootstrap**. Smithers builds the history from main in the background; a toast follows it until it's ready. Needs admin permission on the repository.

</TabItem>
<TabItem label="TUI">

**Planned** ([#2119](https://github.com/smithersai/smithers/issues/2119)).

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers api /api/repos/acme/app/mythical/bootstrap --method POST
```

</TabItem>
<TabItem label="API">

**Available now.** `POST /api/repos/{owner}/{repo}/mythical/bootstrap`, admin only.

</TabItem>
</Tabs>

## File a TODO

A TODO is an issue the factory implements. Filing one needs a GitHub login the repository's policy names as a maintainer.

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** On **History**, select **New TODO**, or enter `/history.todo Add the footer link`. A toast follows it through its checks until its pull request opens.

</TabItem>
<TabItem label="TUI">

**Planned** ([#2119](https://github.com/smithersai/smithers/issues/2119)).

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers api /api/repos/acme/app/mythical/todos --method POST --field title="Add the footer link"
smithers history watch 42 --repo acme/app
```

</TabItem>
<TabItem label="API">

**Available now.** `POST /api/repos/{owner}/{repo}/mythical/todos` with `title` and an optional `body`. The response is the queued issue. `403` when your GitHub login is not a maintainer.

</TabItem>
</Tabs>

## See where each issue is

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Select **History**, or enter `/history.show`. Each issue shows its step, checks, failures, and pull request; each change shows whether it has landed. Open its run or pull request for the detail.

- `/history.backfill` adds the repository's open issues.
- `/history.parallel 3` works on up to three issues at once (1 to 8).
- `/history.retry` retries a blocked, rejected or declined issue. A declined issue stays declined until its title or body changes.

</TabItem>
<TabItem label="TUI">

**Planned** ([#2119](https://github.com/smithersai/smithers/issues/2119)).

</TabItem>
<TabItem label="CLI">

**Available now.**

```sh
smithers api /api/repos/acme/app/mythical
smithers api /api/repos/acme/app/mythical/backfill --method POST
```

</TabItem>
<TabItem label="API">

**Available now.**

| Call | Does |
| --- | --- |
| `GET /api/repos/{owner}/{repo}/mythical` | The history and every issue on it. |
| `GET .../mythical/events` | A live stream of changes. |
| `POST .../mythical/backfill` | Add open issues. Only a person asks for it. |
| `PUT .../mythical/config` | Set `maxParallel` (admin). |
| `POST .../mythical/items/{id}/retry` | Retry one issue. Only a person retries a rejected or declined issue. |

</TabItem>
</Tabs>

## When is it landed

On a repository that sends work upstream, including Smithers itself, the owner merges the pull request on GitHub. The issue is landed once that commit is on main.
