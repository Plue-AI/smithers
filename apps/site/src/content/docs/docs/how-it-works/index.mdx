Smithers is built from a few ideas.

| Idea | In one line |
| --- | --- |
| [Conversation](/docs/how-it-works/conversations/) | A chat with Smithers, or the discussion on an issue. |
| [Issue](/docs/how-it-works/issues/) | Something to get done, from open to verified. |
| [Wiki](/docs/how-it-works/wiki/) | What the project knows, versioned and kept current. |
| [Agent](/docs/how-it-works/agents/) | Instructions, a model, what it may do, and a budget. |
| [Trigger](/docs/how-it-works/triggers-and-flows/) | Something that happens: a message, a schedule, an issue or code event. |
| [Flow](/docs/how-it-works/triggers-and-flows/) | The steps Smithers runs when a trigger fires. |
| Run | One durable execution of a flow; it resumes after a restart. |

1. **Something happens.** A message arrives, a schedule comes due, or an issue is labeled.
2. **Its rule picks a flow.**
3. **The flow runs.** Each agent uses its own model, permissions, and budget.
4. **Work comes back.** Replies land in the conversation. Code changes arrive as pull requests. The wiki refreshes when code lands.

## Four ways in

Everything is meant to be reachable four ways. The tutorials show each one in a tab.

| Surface | For | Open it |
| --- | --- | --- |
| GUI | People | The Smithers app |
| TUI | People | `smthrs tui` |
| CLI | Scripts and agents | `smthrs <command>` |
| API | Scripts and services | HTTP |

## Nothing is lost

Smithers records each step as it finishes. After a restart, a run picks up where it stopped without repeating finished work. [Durable execution](/docs/concepts/durable-execution/) explains the engine.
