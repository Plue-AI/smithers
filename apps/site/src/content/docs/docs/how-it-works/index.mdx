Smithers is built from six ideas. Learn these and the rest of the product reads as detail.

| Idea | In one line |
| --- | --- |
| [Thread](/docs/how-it-works/threads/) | A conversation that lasts: a chat or an issue. |
| [Task](/docs/how-it-works/tasks/) | An issue that someone intends to finish, with state and owners. |
| [Wiki](/docs/how-it-works/wiki/) | What your team knows, versioned and kept current. |
| [Agent](/docs/how-it-works/agents/) | A profile you write once: what a worker does, which model it uses, and what it may touch. |
| [Trigger](/docs/how-it-works/triggers-and-flows/) | Something that happens: a message, a schedule, a webhook, an issue event. |
| [Flow](/docs/how-it-works/triggers-and-flows/) | The steps Smithers runs when a trigger fires. |

Read it top to bottom:

1. **Something happens.** Someone writes in a thread, a schedule comes due, or a service sends a webhook.
2. **A flow starts.** The flow is a recipe of steps: research, plan, change, check, report.
3. **The flow picks agents.** For each step it chooses the right agent profile, such as a builder for a code change or a reviewer for a check.
4. **Agents work on your records.** They reply in threads, move tasks forward, and update the wiki.

## Where your records live

Threads, tasks, and wiki pages live in Smithers. They can also mirror into the tools your team already uses, such as Slack, Linear, or Notion. Sync goes both ways: a reply in Slack lands in the Smithers thread, and a reply in Smithers lands in Slack. Each concept page says which syncs exist today.

## Nothing is lost

Smithers records each step of a flow as it finishes. If a machine restarts, the run picks up where it stopped, and finished steps are not repeated. You can open any run and see what happened, in order. [Durable execution](/docs/concepts/durable-execution/) explains the engine underneath.
