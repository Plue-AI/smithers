Smithers is built from six ideas. One loop, the **coding factory**, runs them.

| Idea | In one line |
| --- | --- |
| [Thread](/docs/how-it-works/threads/) | A conversation that lasts: an issue, or a private chat. |
| [Task](/docs/how-it-works/tasks/) | An issue someone intends to finish, with state. |
| [Wiki](/docs/how-it-works/wiki/) | What the project knows, versioned and kept current. |
| [Agent](/docs/how-it-works/agents/) | A profile: a flow file with a charter, a model, grants, and a budget. |
| [Trigger](/docs/how-it-works/triggers-and-flows/) | Something that happens: a message, a schedule, an issue or code event. |
| [Flow](/docs/how-it-works/triggers-and-flows/) | The steps Smithers runs when a trigger fires. |

1. **Something happens.** A message arrives in a thread, a schedule comes due, or an issue is labeled.
2. **The factory admits it.** Each event is recorded once, queued, and dispatched to the flow its rule names.
3. **A flow runs.** An agent profile is a flow, so the run uses that profile's model, grants, and budget.
4. **Work comes back.** Replies land in the thread. Code changes arrive as pull requests. The wiki refreshes when code lands.

There is no separate "organization" to set up. Your repository's flows, rules, and wiki are the whole configuration.

## Four ways in

Everything is meant to be reachable four ways. The tutorials show each one in a tab.

| Surface | For | Open it |
| --- | --- | --- |
| GUI | People | The Smithers app |
| TUI | People | `smthrs tui` |
| CLI | Scripts and agents | `smthrs <command>` |
| API | Scripts and services | HTTP and the control RPC |

## Nothing is lost

Smithers records each step as it finishes. After a restart, a run picks up where it stopped without repeating finished work. [Durable execution](/docs/concepts/durable-execution/) explains the engine.
