The **wiki** is what people and agents know about a repository. Both read it and write it. Agents read it before they plan.

## One wiki, two parts

**Available now.** Each repository has one wiki with a **public** part and a **private** part. The public part is readable by anyone who can read the repository. The private part is for people with explicit access to it. A page stays in the part it was written in.

## Shaped like a vault

**Available now.** Pages are Markdown files in folders, like an Obsidian vault. `[[Page]]` links another page, `[[Page#Heading|label]]` a heading, and `![[assets/logo.png]]` embeds a file. Every page shows what links to it. Front matter, tags, and aliases are kept as written.

## Versioned

**Available now.** Every edit, rename, and delete is a revision; earlier revisions stay readable, even after a delete. Edits never silently overwrite each other.

## Kept current

When wiki upkeep is enabled and a change lands, Smithers regenerates the pages it affects, reviews each against the code, and publishes it. Pages a person edited stay as written.

**Partly available.** Wiki upkeep is off by default. Set `planning.wiki` to `true` in the host-owned coding request configuration to refresh wiki input before planning. For post-fold refresh when main moves, set `"wiki": true` and provide a non-empty `pages` array in `.smithers/coding-project.json` on main; the repository also needs the stack on. Hosted proof is tracked in [#1923](https://github.com/smithersai/smithers/issues/1923).
