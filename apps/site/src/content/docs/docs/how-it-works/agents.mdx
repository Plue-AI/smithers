An **agent** in Smithers is a **profile**: a short file that describes one worker. A flow reads the profile when it needs that kind of work done, and runs a model with exactly what the profile allows. You write the profile once; many flows and tasks can use it.

## What a profile holds

| Part | What it decides |
| --- | --- |
| Charter | The job: objective, responsibilities, expected output, evidence, and when to escalate. |
| Seat | Which model does the thinking, such as `openai:gpt-6-sol`. |
| Grants | What the agent may use: tools, repositories, connected services, and wiki pages. Anything not listed is refused. |
| Skills | Reusable instructions the agent follows, such as how to report evidence. |
| Memory | Where the agent keeps what it learns between tasks. |
| Budget | How many tokens and tasks it may spend. |
| Reports to | Who it answers to: you or another agent. |

## Create a profile

**Available now.** A profile is a Markdown file, read by [`@smthrs/organization`](/docs/reference/api/organization/). Settings go in the frontmatter; the charter is the body. This is a shortened copy of the `builder` profile from the package's example:

```markdown title="Org/Roles/builder.md"
---
id: builder
name: Builder
kind: core
status: active
version: 1.0.0
reportsTo: lead
seat: openai:gpt-6-sol
effort: high
grants:
  tools: [workspace, memory, retrieval]
  connections: []
  knowledge: ["Org/Roles/builder.md"]
  repositories: [example/demo]
  personalAccounts: false
  contact: via-assistant
budget: { tokensPerTask: 400000, tasksPerDay: 20, concurrency: 1 }
skills: [evidence-receipts]
cases: [builder-small-change]
identities: {}
meeting: { weekly: true }
---

## Objective

Deliver the scoped change in the task workspace.

## Boundaries

- Never lands changes and never contacts the owner directly.
```

Profiles live together in one directory, the **roster**. People write core profiles in `Org/Roles/`. Skills live in `Org/Skills/<name>/SKILL.md`.

## Configure it

- **Seat.** Pick the model per profile. A quick reviewer can use a light model; a builder can use a strong one. [Model seats](/docs/guides/model-seats/) lists the providers.
- **Grants.** Give the least the job needs. A profile without the `workspace` tool cannot run commands or edit files at all.
- **Skills.** Name the skills the agent should follow. A skill adds instructions, never permissions: authority comes only from grants.
- **Memory.** Each profile gets its own memory bank, named `agent-<id>` unless you set one. An agent cannot read another agent's bank. See [Memory](/docs/concepts/memory/).

## Make it useful

- **Write the output you want to read.** List the fields the agent must return, and the evidence that proves them.
- **Say when to stop.** An escalation rule, such as "unclear acceptance: return to the lead", beats a guess.
- **Give it the right pages.** Grant the wiki pages the job depends on, and keep them current.
- **Test it.** A profile names evaluation cases (`cases`): small, known tasks that show whether it still does its job after a change.

## Run agents with the organization host

**Available now.** It runs from a Smithers checkout on macOS (Apple silicon) or Linux with KVM. The organization host runs a roster of profiles on your machine. Each agent works in its own virtual machine, and requests can come from the command line or Slack direct messages.

```sh
node flows/organization/cli.ts init ~/org
node flows/organization/cli.ts doctor
node flows/organization/cli.ts serve
node flows/organization/cli.ts submit "Add a line to README.md" --wait
```

`init` copies a four-profile example organization to start from. The [organization quickstart](https://github.com/smithersai/smithers/blob/main/packages/smithers/agent/organization/docs/quickstart.md) covers setup, and the [host guide](https://github.com/smithersai/smithers/blob/main/flows/organization/host.md) covers every command.
