An **agent** is a file in your repository: `flows/<id>/flow.mdx`, or `flows/<id>/SKILL.md`. An agent profile is a flow, so everything that runs flows runs agents. The front matter sets the model, what the agent may do, and its budget. The body is its instructions.

## Write one

**Available now.**

```markdown title="flows/reviewer/flow.mdx"
---
description: Reviews a change and returns a verdict with reasons.
model: [sol, opus]
effort: high
capabilities: ["fs:read:**", "proc:spawn:*"]
budget:
  tokens: 200000
  milliseconds: 600000
---

# Review the change

Read the diff. Run the tests. Return approve or request changes,
with the evidence for each finding.
```

| Key | What it decides |
| --- | --- |
| `description` | One line shown wherever the agent is listed. |
| `model` | The model: an alias such as `sol`, `astra`, `luna`, `opus`, `fable`, or `qwen`, or `provider:modelId`. A list is a primary and fallbacks. |
| `effort` | Reasoning effort, such as `low` or `high`. |
| `capabilities` | What it may do. Anything else is refused. |
| `budget` | The most tokens and time one run may spend. |
| `flows` | Other agents or flows it may call. |
| `disable-model-invocation` | `true` lets people start it but not other agents. |
| Body | The instructions: the job, the output, and when to stop and ask. |

Skills are `SKILL.md` files beside your flows. A skill adds instructions, never permissions. [flow.mdx frontmatter](/docs/reference/flow-mdx/) lists every key.

## Start one

<Tabs syncKey="surface">
<TabItem label="GUI">

**Available now.** Type `/` and the agent's name, or ask for it in chat. See [Run a flow](/docs/learn/run-a-flow/).

</TabItem>
<TabItem label="TUI">

**Available now.** `/agent` opens a picker. `/agent reviewer` fills in the composer; `/agent reviewer Review math.js` starts it in the background right away.


</TabItem>
<TabItem label="API">

**Available now.** `POST /api/repos/{owner}/{repo}/invoke` with `{"flow":"reviewer","input":{"args":"..."}}`.

</TabItem>
</Tabs>

The model is chosen in order: the one you asked for, then the file's `model`, then the default.

## If it won't start

| Code | Cause |
| --- | --- |
| `unknown_agent` | No agent has that name. |
| `not_an_agent` | It's a `flow.ts` flow; run it as a flow. |
| `not_invocable` | Another agent tried to start a people-only agent. |
| `unreadable` | Its instructions couldn't be read. Fix the file and retry. |
| `unknown_seat` | `model` names no known provider or alias. |
| `unknown_effort` | `effort` isn't a supported level. |

## Agents call agents

**Available now.** An agent lists what it may call under `flows`. Each call is its own run, with its own model, permissions, and timeline. A called agent can only do less than its caller, never more.

## See what an agent did

**Available now.** Filter the run list by the agent's id, then open a run's timeline. See [Watch an agent work](/docs/learn/watch-an-agent/).

**Planned.** An Agents list in the app, with a **Runs** button per agent ([#2113](https://github.com/smithersai/smithers/issues/2113)).

## Budgets

**Available now.** `budget` caps a run's tokens and time.

**Planned.** When a run hits its budget or time limit, it pauses and asks you to continue or stop ([#2114](https://github.com/smithersai/smithers/issues/2114)).

## Memory

**Partly available.** Add a memory bank to `capabilities`, such as `memory:read:global-team` and `memory:write:global-team`. The agent then recalls what's relevant from that bank as it works, and can save what it learns. Agents share a bank only when each is allowed it. See [Memory](/docs/concepts/memory/).
