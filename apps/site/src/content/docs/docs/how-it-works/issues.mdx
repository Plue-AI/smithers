An **issue** is something to get done. Discussion happens in its comments.

## States

```text
open → fixed → verified → closed
```

| Field | Meaning |
| --- | --- |
| State | `open`, `fixed`, `verified`, or `closed`. |
| Fixed by | Who marked it fixed. |
| Verified by | Who confirmed the fix. Never the fixer. |
| Assignees, labels, milestone | Who owns it and how it is grouped. |

**Available now.** The issue card has **Fixed**, **Verify**, **Close**, and **Reopen**; `/issues.fix 42` and `/issues.verify 42` do the same, and so does the API.

**Planned.** Owner, due date, priority, and parent issue ([#2112](https://github.com/smithersai/smithers/issues/2112)).

## Let Smithers fix it

**Available now.** Label an issue `smithers`, or run `/issue.implement 42` in the app. Smithers plans the change, runs the checks, and opens a pull request. **History** (`/history.show`) shows where each issue is.

## Sync with Linear

**Partly available.** A repository can sync issues and comments with a Linear team, both ways. The host must enable integrations; the app has no setup screen yet ([#2116](https://github.com/smithersai/smithers/issues/2116)).
