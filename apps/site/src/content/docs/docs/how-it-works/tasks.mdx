A **task** is an issue someone intends to finish. It is still a [thread](/docs/how-it-works/threads/), so discussion happens in its comments. On top of that it carries the facts that say who owns it and how far along it is.

## What a task adds to a thread

**Available now.** Smithers issues carry this task state:

| Field | Meaning |
| --- | --- |
| State | `open`, `fixed`, `verified`, or `closed`. |
| Assignees | The people responsible. |
| Labels and milestone | How the task is grouped. |
| Fixed by, verified by | Who made the fix and who confirmed it. |

A task moves from open, to fixed, to verified. Verification must come from someone other than the fixer, so "done" means a second party checked it. The app opens and closes issues today; the fixed and verified steps are set through the Smithers Cloud API.

## Put agents on a task

**Available now.** Flows can pick up an issue and work on it. In the app:

```text
/issue.repro 42
/issue.implement 42
```

`/issue.repro` researches and reproduces the problem. `/issue.implement` plans and implements it with the repository's coding flow and checks. Each launch runs in the background; follow its run card to the result.

The local [organization host](/docs/how-it-works/agents/#run-agents-with-the-organization-host) can also take GitHub issues on its own: a triage agent decides which to take, claims each with a label, and delivers a fix, as a pull request when the repository is set up for one.

## Sync with task trackers

A task can mirror into the tracker your team uses, such as Linear. Sync is two-way: a new issue, a comment, or closing and reopening on either side appears on the other.

**Partly available.** Smithers Cloud can link a repository to a Linear team and mirror issues and comments both ways. It is off unless the host enables integrations, and the app has no setup screen yet.

**Planned.** tracker sync set up from the app.
