A **task** is an issue someone intends to finish. It is still a [thread](/docs/how-it-works/threads/), so discussion happens in its comments.

## States

```text
open → fixed → verified → closed
```

| Field | Meaning |
| --- | --- |
| State | `open`, `fixed`, `verified`, or `closed`. |
| Fixed by | Who marked it fixed. |
| Verified by | Who confirmed the fix. Never the fixer. |
| Assignees, labels, milestone | Who owns it and how it is grouped. |

**Partly available.** The API sets every state. The app opens, closes, and reopens issues; its **Fixed** and **Verify** buttons are planned ([#2112](https://github.com/smithersai/smithers/issues/2112)).

**Planned.** Owner, due date, priority, and parent task ([#2112](https://github.com/smithersai/smithers/issues/2112)).

## Hand a task to the factory

**Available now.** The coding factory implements issues. Run `/issue.implement 42` in the app; on a repository whose factory stack is on, an issue labeled `smithers` is picked up too. The factory plans the change, runs the checks, and opens a pull request. `/stack.show` shows where each issue is.

## Sync with Linear

**Partly available.** A repository can mirror issues and comments to a Linear team, both ways. The host must enable integrations; the app has no setup screen yet ([#2116](https://github.com/smithersai/smithers/issues/2116)).
