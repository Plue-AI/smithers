A **trigger** is something that happens. A **flow** is the steps Smithers runs when it does. A **rule** connects them.

## Kinds of trigger

| Trigger | Example | Status |
| --- | --- | --- |
| Schedule | Every weekday at 9:00, run the review. | Available now |
| Issue event | An issue is labeled `smithers`, or gets a comment. | Partly available |
| Code event | A change opens, lands, or main moves. | Partly available |
| Message | A message arrives in a chat. | Planned |
| Manual | You run a registered rule now. | Available now |

## Flows

A flow lives at `flows/<name>/`: a `flow.mdx` whose body is the prompt, or a `flow.ts`. Each execution is a run. Every step is recorded as it finishes, so a stopped run resumes without redoing work. [Agents](/docs/how-it-works/agents/) are flows too.

**Available now.** Run flows from the app's `/` menu, the TUI's `/flow`, `smthrs flow start`, or the API. See [Flows, actions, and plans](/docs/concepts/flows-actions-plans/).

## Rules

A repository declares its rules in `.smithers/FACTORY.ts`, under `on`. The key is the trigger; the value names the flow.

```ts title=".smithers/FACTORY.ts"
import { Smithers as S } from "@smthrs/targets"

export const factory = S.Factory({
  summary: "How this repository develops itself.",
  on: {
    "issue.labeled:todo": { flow: "coding/request", description: "Implement every TODO" },
    "change.opened": { flow: "review", description: "Review every change" },
    "schedule:0 9 * * 1-5": { flow: "review", description: "Weekday morning review of main" }
  }
})
```

The app's **Dispatcher** lists each rule as declared.

**Partly available.** When main moves, rules for `flow.mdx` flows go live: schedules, and issue, comment, pull request, and push events. Rules for `flow.ts` flows stay declared only. Smithers also runs its built-in rules: implementing every TODO (an issue one of the policy's `maintainers` labels `todo`, or writes after `todoSince`, which Smithers then labels itself), reviewing each pull request that work opens, merging it when the review approves, CI passes on that head, and a maintainer labeled the issue `automerge`, and refreshing history and the wiki when code lands. Smithers removes a `todo` label anyone else adds. Assigning an issue to `smithers`, or a maintainer's comment that mentions `@smithers`, proposes it; coding starts only when a maintainer labels it `todo`.

**Available now.** Schedules register directly: in the app with **Dispatcher**, **Register a rule**, or for a local project with `smthrs triggers register`. See [Configure an agent and a trigger](/docs/learn/agent-and-trigger/).

**Planned.** Message rules, so a chat message starts the assistant.

## Once only

A repeated event never runs twice.
