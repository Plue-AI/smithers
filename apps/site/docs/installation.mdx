Smithers maintains your codebase. It turns issues into reviewed, tested changes and, when enabled, keeps the project wiki current. Flows beside your code define how.

## Install

**Planned.** The Homebrew package is not released. Prepare:

- An Apple Silicon Mac running macOS and Homebrew.
- A GitHub repository with squash merging enabled.
- A coding-model provider key or ChatGPT sign-in, and an AI Gateway key for Decisions.

Once the package ships, run on your Mac:

```bash
brew install smithersai/tap/smithers
```

## Start the install

**Planned.** These commands are not in the current CLI. The release may ask for administrator authorization once and will print a setup URL for the Mac and each configured public address.

| Access | Run on the Mac | Open the browser on | Example setup URL |
| --- | --- | --- | --- |
| Mac | `smthrs host start` | The Mac | `http://localhost:4000/setup?token=...` |
| LAN | `smthrs host start --bind 0.0.0.0 --origin http://studio-mini.local:4000` | The Mac or a LAN laptop | `http://studio-mini.local:4000/setup?token=...` |

Replace `studio-mini.local` with your Mac's LAN hostname. The planned options are `--bind <addr>` and `--origin <url>`.

## Complete setup

**Planned.** Open the printed setup link. The setup card will guide you in this order:

1. **Address:** choose **This Mac** or a network address your teammates will use. Address comes first because the GitHub App's sign-in callback is registered to it.
2. **GitHub App:** create the App through GitHub's app-manifest flow.
3. **Owner sign-in:** sign in with GitHub through the new App to claim the install. Claiming invalidates the setup token.
4. **Repository:** choose the repository and install the App on it. Setup checks that GitHub allows squash merging; if it does not, enable squash merging on GitHub and retry.
5. **Model access:** connect the three roles: **fast** for the app agent and summaries (Cerebras by default), **coding** through a provider key or ChatGPT sign-in, and **Decisions** through an AI Gateway key. Without a fast-model key, the app agent uses the coding model.

The rest of the docs will be in the app at `/docs`.
