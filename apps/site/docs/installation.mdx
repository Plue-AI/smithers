## Requirements

- Node.js <code>{versions.nodeRange}</code>. The durable engine runs on Node only.
- pnpm 11.25.0 and Git.
- No database server. Run state is local SQLite in the project's `.flows/` directory.

See the [RC support matrix](/docs/reference/support-matrix/) for engine ranges, platforms, and hosting limits.

## Install the CLI

These docs describe <code>{versions.cli}</code>. It is not published to npm: npm's `@smthrs/cli` is the 0.x line. Install it from the source checkout:

```bash
git clone https://github.com/smithersai/smithers.git
cd smithers
pnpm install
export PATH="$PWD/node_modules/.bin:$PATH"
smthrs --version
```

`smthrs --version` prints <code>{versions.cli}</code>. The PATH line puts this checkout's `smthrs` (and its alias `smithers`) on the current shell. It needs no build step. Change to your own project directory before running `smthrs init`. Target commands such as `smthrs build` and `smthrs test` run with this CLI in any directory; they load `WORKSPACE.ts` and `PACKAGE.ts` against the checkout's own Effect and Smithers packages.

:::caution[declaration_dependency_mismatch]
Target declarations and the CLI must resolve the same physical Effect and Smithers packages. A second, separately installed CLI fails with `declaration_dependency_mismatch` even when its versions match. Use one CLI.
:::

## Use the libraries

The `@smthrs/*` libraries are not on npm either. Link a project directory to the checkout's `examples` workspace, which carries the packages the tutorials and guides import, and the one pinned Effect (<code>{versions.effect}</code>):

```bash
mkdir my-flows && cd my-flows
echo '{ "type": "module" }' > package.json
ln -s /path/to/smithers/examples/node_modules node_modules
```

Run programs with `node <file>.ts`. A package that workspace lacks, such as `@smthrs/artifacts`, resolves only inside the checkout.

## Verify the install

```bash
smthrs doctor
```

`doctor` prints one line per check without running a flow, and exits 1 when any check fails:

- registry: the flows discovered under `flows/`.
- state and databases: `.flows/` and the migrations applied to `control.db` and `engine.db` ("not created yet" before first use).
- runtime: the Node.js version against the supported range.
- jj: whether the configured Jujutsu executable is available.
- providers: which provider credentials are set, and which are exported but empty.

## Stay current

```bash
git pull
pnpm install
```

`smthrs update` reads npm's dist-tags for `@smthrs/cli` and never installs anything.
